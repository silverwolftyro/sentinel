# 哨兵 Sentinel

> **Agent 的自动审计员。**
>
> **v3.4.0 起：哨兵会自己收干净，后台不再留幽灵。**
> Windows 右下角常驻一个哨兵图标，右键菜单里点【**彻底退出**】
> 就能关掉看板服务、结束它自己拉起的子进程、退出程序 ——
> **不留任何后台残留**；
> 看板右上角另有红色【关闭哨兵】按钮，关掉黑框也走同一条路。
> 挂载的会话卡片多了一个 `[×]`（选错了点一下就卸载）；
> 进程死了状态会如实改成「已退出（静默）」，不再一遍遍刷旧日志。
> 雷达也学会**不抓自己的压测残留**，还能认出你自己的 Agent。
>
> **v3.3.2 起：终端里跑着 Agent、看板却抓不到？哨兵会告诉你。**
> 雷达除了扫**文件**，现在也扫**进程** ——
> 发现「本机有正在跑的 Agent，却对不上正在监控的日志」时，
> 看板左侧会亮起橘黄提示：
> **「⚠️ 检测到本机有 1 个活跃的 MCode 进程，未发现可读日志。」**
> 点它就能直接去填日志路径；
> 设置页【挂载管理】里还有一条**可复制的快捷重定向命令**，
> 照着跑，下一次开任务就不会再掉链子。
>
> **v3.3.1 起：「它一直在看」这件事，你看得见了。**
> 中间「实时告警」面板的底部多了一块「**实时审核流水**」——
> L1 每判定一次正常，就留一行极简灰字
> （`[12:01:05] 正常读取: auth.py`）；
> 没目标时顶部的「未设置」会变成**橘黄高亮**并挂上引导气泡，
> 填完目标它变成「**手动锚定**」；
> 查不到进程时界面会把话说清楚：
> **L1/L2 告警与推送照常，只是没法挂起进程。**
>
> **v3.3.0 起：哨兵【不自启】、不后台静默驻留 —— 用完即走，想开才开。**
> 「开机自启」与「守护模式」已被**彻底删除**（脚本、快捷方式、隐藏启动器、
> `--daemon` 参数、自检线程全部移除）。
> 哨兵**只在你手动启动时**才运行；用完了它**自己退出**，
> 不会在后台悄悄待着、也不会开机自己冒出来。
> 旧版装过的机器上如果有残留，哨兵启动时会**当场提醒**并给出清理命令。

哨兵是一个 **只读监听型** 的自动化监控系统。它实时读取外部 AI CLI Agent 的流式日志（JSONL），
通过「确定性规则 + 本地大模型」双层审查，在发现异常时发出告警，必要时发出中断信号。

> **v2.2.0 起它能"复盘"和"自检"了**：
> 【时间线】把这一路发生过的事（开始目标 / 首次意图漂移 / 红线拦截 / 复活重试…）
> 排成**一条带时间戳的线**，节点能直接回看「当时的改动」；
> 【体检】在启动时和看板上告诉你「**你的环境到底行不行**」——
> 本地模型通不通、云端密钥有没有效、**手机推送配没配**
> （没配就明说：**半夜跑挂，您将收不到手机推送！**）。
> 改了 `config.yaml` 还**不用重启** —— 规则热重载自动生效。
> 它**不替 Agent 改代码**，而且这三样都**只读、都不扩大任何权限**。
> 详见 [案发时间线](#案发时间线复盘) 与 [开箱安全体检](#开箱安全体检)。
>
> **v2.2.1 修了一件事**：双击 `sentinel.exe` **不再闪退** ——
> 无参数会直接进演示模式并打开浏览器；
> 万一出了致命错误，窗口也**不会自己关**（会挂住让你看清报错）。
>
> **v2.3.0 修了两件事**：
>
> 1. **哨兵不再要求你改习惯** —— 以前想审一个正在跑的 Agent，
>    唯一的办法是**用哨兵把它重新启动一遍**；
>    现在它是**雷达**：看板左侧点【**＋ 发现/挂载进程**】，
>    它会扫出你**已经在跑**的 Codex / MCode / Claude 会话日志，
>    点「接入」就实时审查 —— **你的 Agent 该怎么跑还怎么跑**。
>    认得出来时会话名会写成 `[Codex] D:\work\project_alpha`；
> 2. **界面不再把所有东西堆在一个页面** —— 顶栏多了【**⚙ 设置**】，
>    点进去是**独立全屏**的设置页（`/settings`，可以单独收藏、刷新不丢）：
>    模型路由 / 通知通道 / L1 规则 / 挂载管理，
>    改完点【保存并应用】—— 写回 `config.yaml` 并**立刻热重载**，
>    配置文件里的中文注释**全部保留**。
>
> **v2.4.0 补完了挂载会话的两块残缺**：
>
> 1. **挂载进来的会话，现在能管也能盯** ——
>    以前它只能**看**（只读），现在哨兵会**反查**出
>    「谁在写这份日志」：
>    查得到就在会话卡片上写明 `PID 54372`，
>    并给你一个【**武装守护者**】开关 ——
>    **只有你亲手打开它**，守护者才会真的去挂起那个进程；
>    查不到就明写「**[未绑定进程]**」并**禁用**开关，
>    哨兵**绝不**拿一个「大概是某个进程」去挂起别人；
> 2. **旁路会话也能盯意图漂移了** ——
>    挂载进来的日志往往**没有最初那句 Prompt**，
>    所以现在选中它就能在顶部「**任务目标**」里**手动注入**目标；
>    设定之后，**立刻**启用滑窗机制、开启 DRIFT 监控。
>
> **v2.2.2 修了一件事**：**演示模式不再骗人** ——> 演示里的一切（告警、日志、Token）都是**模拟数据**，
> 看板顶栏会挂一整条**红色横幅**、背景铺**红色斜条纹**、
> 左侧会话名变成「**[演示] 默认会话**」；
> 终端大字报后面也会紧跟一段 6 行的醒目说明，
> 直接告诉你**怎么用真的**去监控自己的 Agent。
> 真实接管模式（`--agent`）**不会**挂这些东西 —— 那是真监控。

> **v3.0.0 做了三件「让它更省心」的事**：
>
> 1. **目标不用你填了** —— 挂载进来的日志**开头**通常就写着
>    你最初给 AI 的那句话，哨兵会**自动**提取成「任务目标」，
>    卡片上标 **[自动提取]**；
>    提取不到它会**明说提取不到**，绝不编一个出来；
>    （顺带补上了 `codex` 适配器**完全缺失**的 `user_message` 分支 ——
>    没有它，codex 会话根本没法自动锚定。）
> 2. **武装开关会自己「亮」起来** —— 反查置信度 ≥ 0.95 时，
>    【武装守护者】开关**高亮**并给一句气泡提示
>    「高置信度匹配（0.95），建议开启守护者」。
>    ⚠️ **只建议，绝不自动武装** —— 挂起别人的进程永远要你亲手点；
> 3. **手机上能看了** —— 看板与设置页都做了**窄屏适配**（断点 760px），
>    三栏改**上下流式**（不是 Tab 切换 —— 少点一次是一次），
>    按钮最小 40px（手指点得准），长路径自动换行。
>    实测 390×844：改前页面宽 584px（一半内容在屏幕外），改后 390px 零溢出。
>
> 另外 v3.0.0 把**技术债清干净了**：`ruff check .` **零告警**，
> **51 处 `try...except...pass` 全部补上了可定位的日志**，
> 路由切换改成**先收摊再 fetch**（不再被后台 SSE 推送卡住），
> 终端加了一行极简问候：`Sentinel v3.0.0 is ready.`
>

## ⚠️ v5.0.1：双击之后**只会有一个**哨兵

> **这一版修一个被误判的现象**：双击 exe 之后任务管理器里出现**两个同名进程**
> （PID 27280、14532）—— 看着像双开。查下来**不是双开**。

### 那两个进程是什么

**一个实例，不是两个。** PyInstaller 单文件（`--onefile`）模式下：

```
资源管理器 ──► 引导器（bootloader）──► 核心进程（真正的 Python）
                 ├─ 解压到 %TEMP%\_MEIxxxxxx
                 └─ ⚠️ 不跑任何 Python 代码
```

引导器**不执行 Python**，所以它碰不到单例锁 —— **锁天然就落在核心进程上**。

| 你看到的 | 它是什么 |
| --- | --- |
| 核心进程（**父进程也是**同名进程） | **真正干活的**哨兵 |
| 引导器（父进程不是同名进程） | 解压壳 —— 核心进程退出后它也跟着退 |

### 顺带修掉的两个真问题

- **第二个实例不再挂 10 秒模态框** —— v3.8.0 留下的那个弹窗默认超时 10 秒，
  连点几次就会看到四五个同名进程卡在弹窗里。
  **现在打印一行提示就立刻退出。**
- **提示文案不再指向已经删掉的东西** —— 旧文案让你
  「到系统托盘找到哨兵图标，右键 →【彻底退出】」，
  而 v5.0.0 已把前端整体剥离，**哨兵压根没有托盘图标**。

### 怎么自己验一遍

```powershell
python _构建与发布/scripts/verify_single_instance.py --clicks 5
```

实测：连点 5 次 → 同名进程**总数 2**（引导器 1 + 核心 1），
**核心进程恰好 1 个**，输掉的 4 个立刻以退出码 0 退出。

详见
[`_管理文档/文档与报告/versions/v5.0.1-forced-single-instance-lock.md`](_管理文档/文档与报告/versions/v5.0.1-forced-single-instance-lock.md)。

## ⚠️ v5.0.0：哨兵变成了**无头守护进程**

> **这一版动的是架构，不是界面。** 读完这一节，你就知道现在该怎么用它。

### 变了什么

| 之前（≤ v4.3.1） | 现在（v5.0.0） |
| --- | --- |
| 双击弹出一个**浏览器看板** | 双击**什么也不弹** —— 它在后台安静地干活 |
| FastAPI + Jinja2 + SSE + **574 KB** 前端资源 | **全没了**。对外接口只用标准库 `http.server` |
| 一个**全局** `task_goal` | **每一路会话一个目标**，按 CWD / session_id / thread_id 精准分区 |
| 没有目标的会话也照跑 L2 | 没目标 → **L2 自动休眠**（不调模型），只留 L1 纯规则拦截 |
| 6 个第三方依赖（fastapi / uvicorn / jinja2 / httpx / pystray / pillow） | **0 个** —— 只剩 requests / pyyaml / watchdog / psutil |
| 产物叫 `sentinel.exe` | 产物叫 **`sentinel-daemon.exe`**（名字说实话：它是守护进程） |

**为什么**：哨兵的价值在**内核**（L1 规则、L2 漂移、守护者、派发），
不在那一层界面。界面带来的只有依赖、体积、内存和一个「双击没反应」的误会。
把内核留下、把界面剥掉，哨兵就能作为一个 **OS 级进程**安静地待着 ——
替外部宿主（第三方 Agent 插件、CI、别的守护程序）提供「安检」与「挂起」。

### 怎么用（无头模式）

```powershell
# 1) 起守护进程（默认 127.0.0.1:8787）
sentinel-daemon.exe --daemon

# 2) 让外部宿主在 Agent 动手**之前**问一句「这活儿能做吗」
curl -X POST http://127.0.0.1:8787/api/pre-check `
     -d '{"text": "把支付模块的重试逻辑改成指数退避"}'
# → {"action": "allow"}   或   {"action": "block", "rule_id": "..."}

# 3) 让哨兵后台静默监听某一路会话
curl -X POST http://127.0.0.1:8787/api/attach `
     -d '{"cwd": "D:/projects/myapp", "pid": 12345, "agent": "codex"}'
# → {"fingerprint": "...", "goal": "从日志首句提取的目标", "l2_sleeping": false}

# 4) 看所有会话的状态（各自的目标、各自的休眠状态）
curl http://127.0.0.1:8787/api/state
```

### 四个端点

| 端点 | 方法 | 用途 |
| --- | --- | --- |
| `/api/health` | GET | 活着吗？版本、模式、会话数、几路在休眠 |
| `/api/pre-check` | POST | **纯 L1 规则**秒级判定：`{"action": "allow"｜"block"}` |
| `/api/attach` | POST | 挂载一路（`cwd` + `pid` + 可选 `log_path`） |
| `/api/state` | GET | 所有会话的快照（各自的目标与休眠状态） |

**报警不弹窗**：命中红线只在**终端**打一行，
并（配了 `--callback-url` 就）往那儿 POST 一条极简 JSON。

⚠️ **安全边界**：只绑 `127.0.0.1`，**没有鉴权** —— 它假定「同机的其他进程都可信」。
要跨机器用，请自己在前面加一层反代与鉴权。

### 老的用法还在

```powershell
sentinel-daemon.exe --agent mcode "把 README 改清楚"   # 接管真实 Agent，边跑边审
sentinel-daemon.exe --scan path/to/agent.jsonl        # 命令行审查一份已有日志
```

## 核心特性

| 特性 | 说明 |
| --- | --- |
| **只读监听** | 不修改、不注入、不改写被监控 Agent 的任何代码、配置或产物 |
| **实时流式** | `tail -f` 语义：日志写一行审一行，文件轮转 / 截断都不崩 |
| **真实管道接管** | 一条命令拉起**真的** mcode / claude / codex，边打印边审查；红线当场挂起它 |
| **双层审查** | L1 规则引擎（确定性、快）+ L2 模型层（语义级、准） |
| **异步漂移审计** | 判定在后台线程跑，主循环**绝不被模型调用堵住**；模型太慢按背压丢弃 |
| **异步解释** | 告警**先到**、解释**后补**：红线当场挂起，人话解释在后台慢慢问模型、回来后**追加**到原卡片 |
| **意图漂移检测** | 锚定用户给的原始目标，连续 2 个窗口判定跑偏就报警（**只警告，不挂起**） |
| **时间盒拦截** | 「一个子任务吃掉整轮」——同一件事（或同一类操作）磨过时间盒（默认 15 分钟）就判 `[CRITICAL] 严重跑偏` 并推手机；守护者武装着的时候会**自动挂起**死磕的进程（可逆） |
| **引擎心跳看门狗** | 本地模型引擎掉线时**立刻**红色告警（终端 + 看板 + 手机），恢复时也报一声 —— 不会「不声不响地让 L2 整个停用」；⚠️ **只监控，不替你拉起引擎** |
| **无自启、用完即走** | 「开机自启」「守护模式」已**彻底删除** —— 脚本、快捷方式、隐藏启动器、`--daemon`、自检线程全部移除；哨兵只在你手动启动时运行，用完自己退出 |
| **远程告警（叫醒服务）** | 红线拦截 / 连续漂移 → **手机**收到结构化卡片（钉钉 / 飞书 / Server酱 / Bark / 自定义），60 秒防骚扰 |
| **告警重试不堵主流程** | Webhook 投递走**后台线程 + 有界队列**，指数退避重试；主事件流**零阻塞**（实测入队 0.5 ms vs 网络超时 2000 ms） |
| **Token 消耗审计** | 实时累计每个会话烧掉的 Token（usage 真值优先，无则按字符估算）；看板顶部「已消耗 Token」计数器 |
| **挽回 Token 提示** | 守护者真的拦下 / 连续漂移时，卡片上写「预估为您挽回 X 万 Token 的无效消耗」 |
| **夜间值守晨报** | 挂一整夜后自动出一份《哨兵值守晨报》：时长 / Token / 拦截次数 / 挽回的浪费 / 用了哪些模型；落盘到「晨报归档/」 |
| **多级模型路由** | 平时用本地模型省钱；**红线级拦截**或**连续漂移**时自动升级到云端强模型；云端挂了自动退回本地，绝不让红线事件没有解释 |
| **一键复制纠偏提示** | 告警卡片上【复制纠偏提示】/【复制拦截原因】，把「人话解释 + 错误状态」粘给 Agent，它就知道怎么从死循环里出来 |
| **直接发送给 Agent** | 看板一键把纠偏提示**写进 Agent 的标准输入**；CLI 不读 stdin 时降级为**留言箱**（`sentinel_inbox.json`），下次启动自动注入任务提示 —— 屏幕上永远有下一步的中文指引 |
| **危险操作快照与一键回滚** | 红线拦截时**先拍极速快照**再挂起进程；看板上【一键回滚至拦截点】把 Agent 改乱的文件退回去 —— **先出计划，你点头才动手** |
| **一键复活** | 【回滚并重试】把「回滚 + 注入纠偏提示 + 结束挂起进程 + 重拉 Agent」合并成**一次点击**（0.019 秒）—— 多个会话同时挂起时**各回各的，互不影响** |
| **Web Diff 预览** | 告警卡上【查看改动】弹窗里看 Agent 到底改了哪些文件、加了什么、删了什么 —— **绿底新增 / 红底删除**，看清再决定放行还是回滚 |
| **Webhook 真实自检** | 配了真实 Webhook 就**启动时真发一条**（含版本号与本机 IP），验证外网连通性 —— 不是模拟，手机会响 |
| **案发时间线** | 【时间线】把这一路发生过的事排成**一条带时间戳的线** —— 开始目标 / 首次意图漂移 / 红线拦截 / 复活重试…；每个节点都告诉你「**距上一步隔了多久**」，还能直接回看**当时的改动** |
| **开箱安全体检** | 【体检】检查本地模型通不通、云端密钥有没有效、**手机推送配没配**、工作目录有没有排除规则 —— 没配 Webhook 会明说「**半夜跑挂，您将收不到手机推送！**」 |

### ⚠️【防误杀指南】手动双击 exe 被 Defender 拦了？

**先看现象，再看做法** —— 这不是「弹个窗」，是**打不开**：

> Defender 的**机器学习**启发式有时会判哨兵的单文件 exe 是木马并**隔离**它
> （v3.2.0 发布当夜就中过一次，威胁名 `Trojan:Win32/Bearfoos.A!ml`）。
>
> 被隔离之后：**双击 exe 没反应**（或者 Defender 直接弹窗说「已阻止」），
> 文件还在，但**已经被隔离走了**。

**先确认有没有中招**（管理员 PowerShell）：

```powershell
Get-MpThreatDetection | Select-Object -First 3 InitialDetectionTime, ThreatID
Get-MpComputerStatus | Select-Object RealTimeProtectionEnabled
```

**解法：把 exe 所在目录加进 Defender 排除项**（**必须管理员权限**）：

```powershell
# 用仓库里现成的脚本（会自动定位打包目录，非管理员会给具体提示）
powershell -NoProfile -ExecutionPolicy Bypass -File '_构建与发布\scripts\add_defender_exclusion.ps1'

# 或者自己敲（把路径换成 exe 所在的目录）
Add-MpPreference -ExclusionPath "<exe 所在目录>"
```

查状态 / 撤销：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File '_构建与发布\scripts\add_defender_exclusion.ps1' -Status
powershell -NoProfile -ExecutionPolicy Bypass -File '_构建与发布\scripts\add_defender_exclusion.ps1' -Remove
```

**为什么哨兵不自己改 Defender 设置** ——
那是**系统级安全设置**，必须由你本人确认；
哨兵能做的只有**把这件事说清楚**，以及在每次打包后**提醒你一次**。

⚠️ 顺带一提：Defender 排除项是**按目录**的 ——
你换了目录就得重设一次。

### 引擎掉了怎么办（v3.3.0）

NInfer 会掉线，而且掉得**不声不响**：
规则层照跑，但 **L2 判定与人话解释整个停用**。

v3.3.0 起哨兵会**每 30 秒**只读探活一次（不触发推理、不烧显存），
掉了立刻在终端 + 看板 + 手机上喊：

```
[CRITICAL] NInfer 引擎已掉线！L2 判定和解释已停用！
```

启动时如果引擎就连不上，体检报告尾部会有一段**跳出表格**的醒目说明，
写清楚「现在会怎样 / 怎么办 / 怎么自查」。

⚠️ 哨兵**只监控，不替你拉起引擎** —— 保持只读边界。
它会告诉你「掉了」，**动手的是你**（本地 NInfer：双击引擎目录里的启动面板）。

配置在 `config/config.yaml`：

```yaml
llm:
  watchdog:
    enabled: true
    interval: 30          # 探活间隔（秒）
    timeout: 8            # 单次超时（秒）
    restart:              # ⚠️ v3.3.0：**保留但被忽略** —— 哨兵绝不自动拉起引擎
      enabled: false
      command: []         # 参数列表，不是整行字符串（绝不走 shell）
      max_attempts: 2
      cooldown_seconds: 300
```

⚠️ 看门狗**只盯本机引擎** —— 云端 API 掉线是服务商的事。

⚠️ 引擎**刚重启**时会先回 `HTTP 503`（模型还在加载），看门狗会**继续**报掉线，
直到它回 `200` 才转「已恢复」—— 这是对的，那段时间它确实还没在服务。
看到连续 503 时多等一个心跳周期就好。

### 时间盒：拦截「一个子任务吃掉整轮」（v3.3.0）

《Agent 跑偏警示录》里的真实根因：下载依赖、修测试、给即将删掉的引擎装权重 ——
**一件事干到天荒地老，主任务一动没动**。

这类行为**既不删文件、又不偏离目标**，之前的哨兵**一次都没抓到**。
v3.3.0 加了时间盒：同一件事（或同一类操作）磨过时间盒（默认 15 分钟），
直接触发 **`[CRITICAL] 严重跑偏`** 并推送到手机。

```yaml
rules:
  timebox:
    enabled: true
    window_minutes: 15    # 时间盒长度
    min_repeats: 3        # 至少重复几次才算「死磕」
    categories:           # 只盯这几类（「一直在改代码」是正常的，不盯）
      - "dependency"      # 装依赖 / 下载
      - "test"            # 跑测试
    guardian_suspend: null   # 留空 = 跟着守护者的武装状态走（见下）
```

⚠️ 「同一条命令反复出现」这条判定**不受** `categories` 限制 ——
同一条命令磨满一个时间盒，本身就值得看一眼。

**守护者武装着的时候，时间盒会顺手把死磕的进程挂起来**：
你把 `alert.intervention_mode` 设成 `guardian`，
就等于说了「该拦的给我拦」——「超时死磕」也是一种该拦的情况。
挂起是**可逆**的（看板上一键恢复）。
想「只告警不挂起」，把 `guardian_suspend` 显式设成 `false`。

### 真实 Agent 管道接管

一条命令拉起**真的** AI CLI Agent，边打印边审查：

```bash
# 默认接管 mcode
python _构建与发布/scripts/run_with_sentinel.py "在当前目录创建 hello.py 并运行它"

# 换成 Codex CLI
python _构建与发布/scripts/run_with_sentinel.py --agent codex "在当前目录创建 hello.py 并运行它"

# 换成 Claude Code
python _构建与发布/scripts/run_with_sentinel.py --agent claude "在当前目录创建 hello.py 并运行它"
```

它会：

1. 用 `subprocess.Popen` 启动目标 CLI（按各家的流式参数）；
2. **分支 A** —— 把 Agent 的输出实时打印到控制台（看得见它在干嘛）；
3. **分支 B** —— 解析成统一事件喂给哨兵引擎逐条审查；
4. **自动锚定** —— 从你给的那句话里提取任务目标
   （`[SENTINEL] 已自动锚定任务目标: xxx`）；
5. **红线挂起** —— 命中红线时挂起**真正的 Agent 进程**
   （Windows 上是 npm `.cmd` 垫片下的 `node.exe`，
   或者是 codex 这类原生二进制本体 —— 挂垫片或临时 shell 都等于没挂）；
   看板（默认 `http://127.0.0.1:8000`）上点【放行并忽略】即恢复。

常用开关：

```bash
--agent codex        # 被接管的 CLI：mcode / claude / codex
--cwd <目录>         # Agent 的工作目录
--model <模型>       # 覆盖模型
--permission full    # 统一权限档位：smart / full / off（默认 smart）
--extra-arg <参数>   # 透传给 Agent 的额外参数（可重复）
--session-file <文件> # 多路会话配置（JSON），同时接管多个 Agent
--keep-alive         # Agent 跑完后看板不关，留到 Ctrl+C
--port 8000          # 看板端口
--no-gui             # 不启动看板，只在终端审查
--no-guardian        # 不挂起进程，只观察
```

> **退出码**：发现告警时返回 `1`，否则返回 `0` —— 方便接进 CI。

> **Claude 适配器尚未实机验证**（本机没装 `claude` CLI）；
> mcode 与 codex 均已实机跑通。

### 异步解释（告警先到，解释后补）

L1 命中后哨兵**不等模型**：

```
[CRITICAL] DANGEROUS: 红线级命中：用 find 批量删除文件     ← 同一毫秒，守护者随即挂起
ALERT_JSON        {"alert_id": "1793065506444-000001", "explanation_pending": true}
…（主循环继续处理后续事件，6 秒后模型才回来）…
↳ 人话解释（补充）：AI 想删除所有临时文件。原因：…
ALERT_UPDATE_JSON {"alert_id": "1793065506444-000001", "update": true, "explanation": "…"}
```

- 解释跑在**独立后台线程**（`sentinel-explain`）的**有界队列**上，
  主循环一秒都不等；
- 解释靠 `alert_id` 与原告警**配对**，回到看板时是**追加更新**：
  原卡片下方**无缝淡入**人话解释，**不会新开一张卡片**；
- 队列满了就丢弃并记 `[WARN] 解释队列已满` ——
  丢一句解释不致命，堵死主循环才致命。

### 意图漂移检测

哨兵除了「这一步危不危险」，还多问一句：
「**Agent 还在做用户交代的那件事吗？**」

- 每收集 **5 个** `thinking` + `tool_call` 事件做一次判定；
- **连续 2 次**（= 10 步）判定为漂移才告警：
  `[WARNING] 意图漂移：Agent 可能偏离了原始任务`；
- 漂移是**标准级**告警 —— 只弹窗提醒，**不挂起进程**
  （跑偏是「可能做错事」，不是「马上要毁掉东西」）；
- 模型不可用时判定为「**没漂移**」并清零计数 ——
  **缺失绝不等同于有问题**。

目标可以在三个地方设定，三者等价：

| 位置 | 方式 |
| --- | --- |
| 配置文件 | `config/config.yaml` 的 `task_goal` |
| 命令行 | `--task-goal "..."`（**显式**，谁都不许覆盖） |
| 看板顶栏 | 输入框 + 【设定】（**运行中也能改**，同样是显式） |

**都不设也行** —— 引擎会从流里第一条用户请求自动提取：

```
[SENTINEL] 已自动锚定任务目标: 在当前目录创建 hello.py，内容是打印 hello world
```

优先级：**显式指定** > **自动提取** > 配置文件（兜底）。
没设目标就**完全不做判定** —— 没有目标就没有「偏离」可言。

判定在**后台线程**跑：主循环把窗口丢进有界队列就继续读日志，
模型再慢也堵不住；队列满了按背压丢弃并记 `[WARN] 漂移检测超载`。

[`_管理文档/文档与报告/versions/v0.8.0-async-drift.md`](_管理文档/文档与报告/versions/v0.8.0-async-drift.md)、

### 守护者模式（可选）

守护者是哨兵唯一的「主动干预」能力，**需要显式开启**
（本机 `config/config.yaml` 已设为 `guardian`）。
开启后，只有**红线级**事件（`rm -rf /`、整盘格式化、批量删除、
敏感数据外发到外部地址）才会触发对被监控进程的**可逆**干预。

```bash
# 1) 在 config/config.yaml 里把 alert.intervention_mode 改成 "guardian"

# 2) 跑起来（会自动探测被监控进程）
python -m src.core.engine path/to/agent-stream.jsonl

# 3) 看到拦截提示时，敲 override 放行
override
```

放行会恢复进程，并让哨兵在**当前任务**中不再拦截该规则；
每次干预与放行都留痕到 `logs/`。

> **权限小于用户**：哨兵只挂起 / 只中断，**绝不 kill 进程**；
> 干预随时可逆，用户随时可以否决。
> 详见
> [`_管理文档/文档与报告/versions/v0.5.0-guardian.md`](_管理文档/文档与报告/versions/v0.5.0-guardian.md)。

### 远程告警通道（叫醒服务）

桌面弹窗只在**有人盯着屏幕**时有用。
半夜真正能叫醒你的是**手机推送** —— 哨兵支持把告警推成**结构化卡片**：

| 平台 | 报文格式 | 卡片 |
| --- | --- | --- |
| 钉钉 | `dingtalk` | Markdown 卡片（支持**加签**） |
| 飞书 | `feishu` | interactive 卡片（红线 `red` / 其余 `orange`，支持**加签**） |
| Server酱 | `serverchan` | `title` + `desp` |
| Bark | `bark` | critical 用 `timeSensitive`（**绕过静音**，这才是叫醒） |
| 自定义 | `generic` | 完整 JSON（`text` + `card` + 告警全量） |

```yaml
# config/config.yaml
alert:
  channels:
    - type: "webhook"
      enabled: true
      url: "https://oapi.dingtalk.com/robot/send?access_token=xxx"
      format: "dingtalk"
      card: true
      secret: ""                    # 钉钉 / 飞书加签密钥
      triggers:
        - "guardian_intercept"      # 守护者**真的挂起**了目标进程
        - "intent_drift"            # 连续意图漂移
      dedup_seconds: 60             # 防骚扰：同一条事件 60 秒内只推一次
```

**手机推送不是桌面弹窗的复制品** —— 默认只推两类真正要紧的事件：

- `guardian_intercept` —— 守护者**真的拦下来**了才打这个标记；
  拦不住（进程已退出）**不推** —— 半夜被「拦不住」吵醒更烦人；
- `intent_drift` —— **连续**漂移（跑偏了，越晚发现越贵）。

`context_anomaly`（死循环 / 敏感数据外泄）默认**不推** ——
半夜一条 STUCK 就能把人吵醒，那等于没开。

**防骚扰按事件指纹**（`sha1(agent | rule_id | command)`），
60 秒内同一件事只推一次；**推送失败会撤销占位**，没送到就该允许重试。

#### 投递失败会重试，但**绝不**堵住主流程

网络不通是常态，不是例外。所以投递失败会**指数退避重试**：

```
第 1 次失败 → 等 1 秒 → 第 2 次失败 → 等 2 秒 → 第 3 次失败 → 放弃
```

- **只有临时性故障才重试** —— 网络错误 / 超时 / 5xx / 429；
- **4xx 立刻放弃** —— URL 写错、签名错时，重试多少次都一样；
- 重试耗尽后给一句**看得懂的中文**：
  「webhook 投递最终失败（共尝试 N 次）：…。请检查网络连通性、URL 是否正确、
  是否需要加签密钥。**本次告警未能推送到手机。**」

关键在于**投递走后台线程**：`send()` 只做「校验 + 入队」就返回，
真实 HTTP 在后台做 —— 引擎主循环**一秒都不会被网络卡住**
（架构红线 R5）。这是「要重试」和「不能阻塞」能同时成立的唯一做法。

```yaml
# config/config.yaml
alert:
  channels:
    - type: "webhook"
      enabled: true
      url: "https://oapi.dingtalk.com/robot/send?access_token=xxx"
      format: "dingtalk"
      max_retries: 2         # 额外重试几次（默认 2，即总共尝试 3 次）
      retry_backoff: 1.0     # 首次退避秒数（之后 1s → 2s → 4s 指数增长）
```

卡片正文必含**五要素**：

```
🚨 哨兵告警 · RED_LINE

- Agent：codex
- 触发规则：catastrophic_root_delete
- 触发类型：guardian_intercept
- 任务目标：在当前目录创建 hello.py 并运行它
- 当前操作：rm -rf /tmp/test
```

五种格式的**完整实发报文**见
[`_管理文档/文档与报告/assets/webhook-sample-v1.0.0.json`](_管理文档/文档与报告/assets/webhook-sample-v1.0.0.json)。

### Token 消耗审计

「跑偏的 Agent 会白白烧掉 Token」是共识，但**烧了多少**一直是个黑箱。

- **有 usage 就用真值** —— codex 的 `turn.completed` 带
  `{"usage": {"input_tokens": …, "output_tokens": …}}`，直接采信；
- **没有 usage 就按字符估算** —— CJK 1 字 ≈ 1 Token，其它 4 字符 ≈ 1 Token；
- **估算值在界面上带 `~` 和虚线边框** —— 估算**不冒充**真值。

⚠️ **usage 是快照不是增量** —— codex 报的是「到目前为止的上下文总量」，
当成增量累加会重复计数好几倍，所以真值来了是**替换**估算值。

看板顶栏实时显示「**已消耗 Token**」；当守护者**真的拦下来**、
或者**连续漂移**告警时，卡片上会多一行：

> 本次异常已拦截，预估为您挽回 3.2 万 Token 的无效消耗

计算逻辑：

```
挽回 = 本次会话已消耗 + 每步均摊 Token × 10 步
     = 已烧掉的          + 本来还要烧的
```

拦不住时**不**给这个提示 —— 那会是一句空话。
更多细节见
[`_管理文档/文档与报告/versions/v1.1.0-stress-and-tokens.md`](_管理文档/文档与报告/versions/v1.1.0-stress-and-tokens.md)。

### 夜间值守晨报

挂了一整夜，早上打开电脑不该面对**一夜的几百条日志**。
哨兵会替你拼好一份《哨兵值守晨报》：

```
# 哨兵值守晨报 · 2026-10-27

## 会话 stress-a · codex

- **执行时长**：1 小时 12 分
- **总 Token 消耗**：24.7 万
- **红线级拦截**：2 次
- **意图漂移**：3 次
- **[STUCK] 卡死**：2 次
- **预估挽回的无效消耗**：4.1 万 Token
- **本次用到的模型**：openai_compatible:bonsai2-27b ×9
```

- **三个触发点**：会话收尾自动生成 / 看板【生成晨报】按钮 / 退出信号；
- 落在 `_管理文档/文档与报告/晨报归档/晨报-YYYY-MM-DD.md`
  （多路会话**合并**进同一份日报，每路占一节）；
- 终端同时打印一份**几行看完**的摘要；
- ⚠️ **统计部分纯计算** —— 模型不可用也照样能出晨报。

### 多级模型路由（平时省钱，出事用强模型）

单一模型总会卡在两头：只用小模型解释得慢又糙，只用云端既费钱又要送日志出本机。
所以哨兵**分级**：

| 触发条件 | 用哪个模型 |
| --- | --- |
| 普通告警 / 正常审查 | `primary`（本机 `bonsai2-27b`，数据不出本机） |
| **红线级拦截** | `fallback`（云端 `deepseek-chat`） |
| **连续漂移** | `fallback` |

```yaml
llm:
  provider: "openai_compatible"        # 本机 NInfer 也是这一条（OpenAI 兼容协议）
  base_url: "http://127.0.0.1:8888/v1"  # 本机 = 数据一步没出本机
  model: "bonsai2-27b"
  api_key: "sk-no-key-required"          # NInfer 不校验密钥，但这个头不填有些网关会 401
  timeout: 600                           # 27B 推理模型：思考本身就要几十秒
  max_tokens: 8192                       # 「思考」也算 token，给小了正文吐不出来
  routing:
    # ⚠️ 本机默认**关** —— NInfer 本身就是本地强模型，
    #    再挂云端 fallback 只会把内容送出本机。
    enabled: false
    escalate_on_red_line: true
    drift_escalate_threshold: 1
    fallback:
      provider: "openai_compatible"
      base_url: "https://api.deepseek.com"
      model: "deepseek-chat"
      api_key_env: "DEEPSEEK_API_KEY"
      max_tokens: 1024
```

> ⚠️ **本机引擎的单并发脾气**：NInfer 是 `--max-concurrency=1`，
> 同时发两个请求**引擎直接崩**。
> 哨兵已经在**客户端**排好队（同一台引擎一把锁），你不用管 ——
> 但**别自己再开一个脚本去调同一个引擎**，那就会撞上。

**密钥按厂商自动识别**（不用再单独配一个 `SENTINEL_LLM_API_KEY`）：
`DEEPSEEK_API_KEY` / `MOONSHOT_API_KEY` / `KIMI_API_KEY` /
`ZHIPU_API_KEY` / `SILICONFLOW_API_KEY` / `DASHSCOPE_API_KEY` /
`OPENROUTER_API_KEY` / `OPENAI_API_KEY`。

> ⚠️ **云端挂了不能没有解释** —— 升级模型降级时自动退回主力模型。
> 红线事件**绝不能**因为「云端抽风」而没有解释。

### 一键复制纠偏提示

`[STUCK]` 或 `LOOP` 发生了，光看告警不够 —— 用户还得知道**该跟 Agent 说什么**。
所以每张告警卡片上都有一个按钮：

- 非红线 →【复制纠偏提示】
- **红线级** →【复制拦截原因】

点一下就把「人话解释 + Agent 的错误状态 + 任务目标 + 最近几步在干什么」

### 直接发送给 Agent

复制终究要你**动手**。半夜你不想起床 —— 那就让哨兵**自己送过去**。

告警卡片上多了一个按钮：

- 非红线 →【直接发送给 Agent】
- **红线级** →【发送拦截原因】

点一下，哨兵按**优先级**试两条路：

```
                  点【直接发送给 Agent】
                            │
                            ▼
                ┌───────────────────────┐
                │  Agent 读 stdin 吗？  │
                └───────────────────────┘
                    │ 是            │ 否
                    ▼               ▼
             写进 Agent 标准输入   写进 sentinel_inbox.json
             （留言箱里也留一份    （工作目录里的留言箱）
              留痕，方便复盘）            │
                                          ▼
                                  下次启动 Agent 时
                                  拼进「任务提示」里
```

- **能写 stdin 就直接写** —— 写成功的**同时**在留言箱里也留一份
  `delivered=True` 的记录，方便事后复盘「到底发过什么」；
- **写不进去就降级** —— 指令**留在留言箱里**，绝不假装送达；
- **下次启动自动注入** —— 启动器在拼任务提示时把待投留言**渲染成一段中文块**塞进去。

> ⚠️ **「写成功」≠「对方读了」** —— 写进 stdin 只是把字节送到了管道，
> Agent 会不会照做，哨兵**不知道**，也不假装知道。

#### 哪些 CLI 收得到？

| Agent | 收得到 stdin 吗 | 实际走哪条路 |
| --- | --- | --- |
| `codex exec` | ❌ 一次性非交互模式，stdin 没人读 | 留言箱 → 重启注入 |
| `mcode exec` | ❌ 同上 | 留言箱 → 重启注入 |
| `claude -p` | ❌ 同上 | 留言箱 → 重启注入 |
| 交互式 / 长驻 CLI | ✅ | **直接写 stdin** |

这是**故意保守**的：`AgentProfile.supports_stdin` **默认 `False`**。
往没人读的管道里写字，然后告诉用户「已送达」——
那是**撒谎**，比送不到更糟。

#### 屏幕上永远有下一步

降级**不是死路**。看板会明确告诉你下一步该干什么，三条路按需给出：

```
下一步：
  1) 用同样的命令重跑一次哨兵 —— 留言会在启动时自动注入任务提示
  2) 或直接把下面这段粘给 Agent：
     【哨兵纠偏提示 · STUCK】…
  3) 查看留言箱：<工作目录>/sentinel_inbox.json
```

```yaml
# config/config.yaml
intervention:
  enabled: true
  inbox_name: "sentinel_inbox.json"
  max_inbox_messages: 20
```

### 一键回滚至拦截点

Agent 把代码改乱了怎么办？

v1.2.0 之前只能靠 git 自己救。v2.0.0 给你一个按钮：

- **守护者拦截红线级操作时**，哨兵会在**挂起进程之前**对工作目录拍一张「极速快照」；
- 看板上每条带快照的告警卡**多一个**【一键回滚至拦截点】；
- 点下去**先给你看计划**，你确认了才动手。

```
点【一键回滚至拦截点】
        │
        ▼
┌──────────────────────────────────────────┐
│ 回滚计划                                  │
│   目标安全点：20261027-175924-131552      │
│   将恢复 1 个被修改的文件                  │
│   将删除 1 个新建的文件                    │
│   预计耗时：0.002 秒                       │
│   [ 确认回滚 ]      [ 取消 ]              │
└──────────────────────────────────────────┘
        │ 确认
        ▼
   恢复文件 + 删除清单外的新文件 → 写 rollback 事件留痕
```

#### 快照存在哪

```
<工作目录>/.sentinel/safepoints/<快照ID>/
├── manifest.json      ← 完整文件清单（路径 + 大小 + sha256）
└── files/             ← 文件内容备份（按原目录结构）
```

- **清单永远完整** —— 哪怕内容因为降级没备全，
  清单也得在，因为**回滚要靠它判断「哪些文件是 Agent 新建的」**；
- 默认排除 `.git` / `.venv` / `node_modules` / `__pycache__` 等目录
  （它们**不是 Agent 的作品**，动它们只会添乱）；
- 超过阈值时**降级但不清单**：只备最近改动过的文件内容。

#### 三重降级保「极速」

| 阈值 | 默认 | 超了怎么办 |
| --- | --- | --- |
| 目录总体积 | 64 MB | 降级成增量模式（只备内容，清单仍全） |
| 文件数 | 20000 | 同上 |
| **时间预算** | **3 秒** | **立刻收手**，标 `truncated` |

最后一条是保命的：快照是**在挂起进程之前**拍的 ——
它慢一秒，Agent 就多跑一秒。

#### 回滚的边界

- **只覆盖工作目录内的文件** —— 装依赖、推远端、改全局配置，哨兵**没留备份**；
- **排除目录不动** —— `.git` / `node_modules` 不会被回滚；
- **回滚不可逆** —— 执行了，那之后的改动就没了，所以**必须先出计划**；
- **带路径穿越防护** —— 清单里的路径必须**在工作目录内**，否则跳过。

```yaml
# config/config.yaml
safe_point:
  enabled: true
  root: ""                  # 留空 = <工作目录>/.sentinel/safepoints
  max_bytes: 67108864       # 64 MB
  max_files: 20000
  max_seconds: 3            # 时间预算 —— 保证「极速」
  recent_minutes: 60        # 增量模式只备最近改动过的文件
```

### 一键复活：回滚并重试

半夜挂了 10 个任务，早上看到 3 个被红线挂起 ——

v2.0.0 还要你手动做**三步**：点回滚、点发送、再去终端重启进程。
v2.1.0 把它们合并成**一次点击**。

告警卡片上多了一个【回滚并重试】按钮（只给**红线级且打过安全点**的告警）。

```
点【回滚并重试】
        │
        ▼
┌──────────────────────────────────────────┐
│ 回滚并重试                                │
│ 回滚到安全点「基线安全点 · 会话起点」，      │
│ 并把纠偏提示交给 Agent。                  │
│   · 恢复 1 个被修改的文件                  │
│   · 删除 1 个 Agent 新建的文件             │
│   · 结束那个卡在危险命令上的挂起进程         │
│   · 重新拉起 Agent，任务提示里会带上纠偏提示  │
│ ⚠️ 这三步不可逆：被拦下的那条命令不会再执行， │
│   但 Agent 在那之后的改动也会一起没了。      │
│   [ 取消 ]      [ 确认复活 ]              │
└──────────────────────────────────────────┘
        │ 确认
        ▼
  回滚 → 写留言箱 → 结束挂起进程 → 重拉 Agent
        │
        ▼
  [SENTINEL] 已回滚至安全点，并注入纠偏提示，重新唤醒 Agent。
```

#### ⚠️ 为什么是「结束」而不是「放行」

被哨兵挂起的进程，正卡在一条**危险命令**上 ——
挂起就是为了让它来不及执行那条命令。

所以**放行它不是复活，那是闯祸**：刚被拦下的 `rm -rf` 一放行就跑了。

于是复活只能是「结束它 + 重新拉起一个带着纠偏提示的干净进程」。

> ⚠️ 这是「哨兵绝不 kill 进程」的**唯一例外**，
> 而且作用域收得死死的：**只针对哨兵自己挂起过的进程**，
> 别的进程它连碰都不碰；保护 PID（0 / 1 / 哨兵自身 / 父进程）一律拒绝；
> 每次终止都写审计留痕。
> 而且**必须你先看计划、先点头**。

#### 并发防呆

- **同一个会话**连点两次 → 第二个被挡住（每个会话一把自己的锁）；
- **多个会话同时挂起** → 各自独立回滚，**互不影响**。

实测：全流程 **0.019 秒**。

### Web Diff 预览

纯看 JSON 日志不够直观 —— 你要看的是「**Agent 到底改了啥**」。

告警卡片上多了一个【查看改动】按钮，点开是一个弹窗：

- **绿底** = 新增的行，**红底** = 删除的行，**蓝底** = 块头（`@@`）；
- 顶部一行摘要：`修改 1 个、新增 1 个、删除 0 个`；
- 底下单独列出 Agent **新建**的文件。

```
Agent 到底改了什么
────────────────────────────────────────────
对比安全点 基线安全点 · 会话起点 → 当前工作目录：修改 1 个、新增 1 个、删除 0 个

src/app.py（+2 / −2）
  --- 安全点/src/app.py
  +++ 现在/src/app.py
  @@ -1,3 +1,3 @@
   def main():
-    # 正常版本：返回 'good'
-    return 'good'
+    # Agent 改坏的版本
+    return 'broken'

+ src/scratch.py
────────────────────────────────────────────
                              [ 关闭 ]
```

- 差异在**快照时**就已经算好「哪些文件变了」（只比清单，不读内容，
  所以不会拖慢「极速」快照）；
- **行级 diff 是按需算的** —— 你点按钮才算；
- **二进制文件自动跳过**（给二进制做行级 diff 只会得到乱码）。

### 案发时间线：复盘

早上看到 Diff 的时候，你真正想知道的是「**它是怎么一步步走到这一步的**」：

- 它是在第 3 分钟就偏了，还是第 40 分钟才偏的？
- 那次红线拦截之前，它已经连着跑失败 5 次了吗？
- 中间我手动点过【回滚并重试】吗？点了之后它老实了吗？

挂一整夜的用户面对的是**一屏告警**，不是一条故事线。
v2.2.0 把它变成一条线 —— 顶栏点【时间线】：

```
案发时间线
──────────────────────────────────────────────
共 7 个节点 · 21:29:38 → 21:30:31 · 跨度 53 秒

21:29:38  安全点
           基线安全点 · 会话开始
           [ 看当时的改动 ]

21:29:38  操作      距上一步 0 秒
           开始目标
           重构 auth 模块并修复登录后偶发 401 的问题

21:30:16  告警      距上一步 38 秒
           高危命令 · dangerous_command
           匹配到高危命令: rm -rf —— rm -rf ./build && rm -rf ./dist
           [ 看当时的改动 ]

21:30:26  红线拦截   距上一步 10 秒
           红线拦截 · catastrophic_disk_wipe
           红线级命中：重建文件系统（抹掉整盘数据）
           [ 看当时的改动 ]
```

三件事值得单独说：

1. **间隔**才是这里最值钱的东西 ——
   你问的「**在触发拦截的 10 分钟前，Agent 到底在干什么**」，
   那个答案不在某一条日志里，在**两条日志的时间差**里；
2. 节点**直接关联**到当时的安全点与 Diff ——
   点【看当时的改动】就回到那一刻；
3. 守护者缺席时红线告警**没带快照** ——
   这时节点挂到**基线**上，但**不会假装**打过快照。

### 规则热重载：半夜改策略不用重启

半夜发现某条命令该拦却没拦，v2.1.0 的选择是：
起来 → 改配置 → 重启 → 祈祷重启后 Agent 还能接上。

v2.2.0 把这条链路压成：**改文件 → 保存 → 自动生效**。

```
[SENTINEL] 检测到规则更新，热重载完成。
```

三条底线：

- **只换规则引擎** —— 通知通道与守护者**不重建**
  （重建它们等于把服务重启一遍，那就不是热重载了）；
- **原子替换** —— 新规则整体建好才换上去，
  审查线程**绝不会**看到半成品规则；
- **坏配置保留旧规则** —— YAML 写坏了会报错并**保留原规则**，
  绝不会让防线一次手滑就清零。

⚠️ **没用 `watchdog`**：那个库**从来不是本项目依赖**、当前也**没装**。
这里走的是项目**一直以来的约定**：`src/tailer.py` 那套 **mtime 轮询**。
代价是约 1 秒延迟，收益是**零新增依赖、打包体积不增**。

### 双击 exe：不再闪退

`sentinel.exe` **双击就能跑** —— 不带任何参数会自动进**演示模式**并打开浏览器。
这是 v2.2.1 修的（之前会报错退出，窗口瞬间就没了）。

```
双击 sentinel.exe
        │
        ├─ 体检报告（**只有一份**）
        ├─ 生成模拟日志 → 审查一遍
        ├─ 看板启动：http://127.0.0.1:8000
        └─ 浏览器自动打开
```

万一出了**致命错误**（端口被占、参数写错、依赖缺失），
窗口也**不会自己关**：

```
[SENTINEL] 哨兵没能正常启动（退出码 2）。
```

⚠️ 挂住等回车**只在真终端下生效** ——
被管道 / 脚本调用时**不会**把调用方挂住（那比闪退更糟）。

体检报告的「快照排除规则」看的是**启动时的当前目录** ——
双击时那是 **exe 所在目录**，不是你的项目目录。
想体检真实项目目录，用 `--cwd <目录>` 走真实接管模式。

### v3.2.0：晨报推到你手机 · 哨兵自己量自己 · 整夜演习

v3.1.0 把「硬件」和「软件」都备齐了 —— 无窗口自启（⚠️ **v3.3.0 已删除**）、
挂载自动重连、`zstd` 接入指引。但**还没真的一整夜跑过**。
这一版做三件事：**晨报自动投递**、**哨兵自身的性能监测**、**终局 Night Crawl 演习**。

**① 晨报推到你手机（不用去电脑里翻文件了）**

晨报生成完之后**自动**转成 Markdown 摘要，通过 `WebhookChannel` 推到你配的地址
（钉钉 / 飞书 / Server酱 / Bark / 通用）。

推的是**提炼过的核心数据**，不是整篇晨报：

```text
🌅 哨兵晨报 · 2026-10-28
值守 30 分 12 秒 · 处理 428 条事件
拦截 3 次（红线 2 次）
挽回 Token 12.3k
```

⚠️ 整篇晨报可能几十 KB，塞进手机会被**截断**成一段莫名其妙断掉的话 ——
所以只推核心三项（**总拦截次数 / 红线次数 / 挽回 Token 数**）。

* 晨报推送**不受**「触发类型」和「防骚扰窗口」影响 ——
  否则你配了 `triggers: [DANGEROUS]` 的话，晨报会被当成「不是 DANGEROUS 告警」
  而**永远推不出去**；
* 推送会**等队列跑完**再报「已推送」—— 宁可收尾多等几秒，
  也不对你说「已推送」却其实没送到；
* 终端会明说：`[SENTINEL] [night-crawl] 晨报摘要已推送到你的手机。`

**② 哨兵自己量自己（防资源黑洞）**

「监控工具本身不能变成资源消耗大户」—— 所以它得自己量自己。

* 新增 `src/selfmon.py`：CPU 占用 / 内存占用 / 运行时长 / 线程数；
  Windows 走 `ctypes` 调 Win32 API，**不引入任何新依赖**（打包版不用装东西）；
* 取不到的项一律 `None` —— **绝不编造数字**；
  第一次采样还没法算 CPU，页面显示「采样中…」而不是骗人的 `0.0%`；
* 引擎主循环每 **5 分钟**采一次，写进日志：
  `[SENTINEL] 自检：CPU 0.6% · 内存 71.5 MB · 运行时长 0 分 55 秒`；
* 设置页新增第 ⑤ 项【**关于系统**】（`/settings/system`）：
  运行时长、内存占用、版本号一眼可见。

**③ 跟读器的内存防线（`tail_stream` 不再是黑洞）**

被跟随的日志写出**超长行**（迟迟不换行）时，
跟读器的末尾缓冲有 **1 MiB 硬上限** —— 超出就丢掉最老的残片，
并**只记一次** warning（不刷屏）。单次读取本身已有 4 MiB 上限，
轮转与截断也都能识别。

**④ 终局 Night Crawl（30 分钟真实长任务演习）**

新脚本 `_构建与发布/scripts/final_night_crawl.py`：

```powershell
python _构建与发布/scripts/final_night_crawl.py --minutes 30 --json report.json
```

它会**真的**拉起 `mcode exec` 去重构一个中等规模的模块，
中途按时间表注入 1 次 **STUCK**、1 次 **DRIFT**、1 次 **DANGEROUS**（红线挂起），
然后验收：终端有没有明确打印挂起提示、Mock Webhook 收到几条、
晨报有没有在退出时自动生成并投递、**内存有没有泄漏**。

**⑤ 顺手修的真缺陷（都是实机跑出来的）**

* `WebhookChannel.close()` 直接停线程会**丢掉队列里没投完的报文** ——
  而晨报恰好是**收尾时**才入队的，于是手机上什么也没收到，
  哨兵却印了一句「已推送到你的手机」。现在改成**先 flush 再停线程**；
* 设置页里把 `triggers` 列表**清空**，本意是「我全都要」，
  旧实现却当成「一个都不推」—— 深夜出事，手机上**静悄悄地什么都没收到**。
  现在空列表 = 推全部；
* ★★ **意图漂移检测静悄悄地死掉**：本机 Ollama 服务在跑，但 `ollama list`
  **一个模型都没有**，于是每次漂移判定都降级 ——
  而降级在口径上等于「没漂移」，于是**漂移检测彻底失效、一声不吭**，
  晨报却写着「意图漂移：0 次」。
  现在降级会被**明确说出来**（终端一句提示 + 晨报如实标注），
  **判定口径一个字没改**（红线 R4）——
  没有偷偷把内容送去云端。

**⚠️ 发布当夜踩到：Defender 把 exe 误判了**

打包完成后 10 分钟，Microsoft Defender 判定 `sentinel.exe` 是
`Trojan:Win32/Bearfoos.A!ml`（**机器学习**启发式，**不是**签名命中），
把它**隔离**了，还顺手结束了正在运行的进程 ——
后果是**双击 exe 打不开**（文件已经被隔离走了）。

这是**误报**：本项目源码全程可审（只读监听 / 不注入进程 / 不终止用户进程），
没有混淆壳、下载器或凭据窃取；而且同一台机器上 v3.1.0 的 exe **从未被命中**。

**你要做的（需要管理员权限）**：

```powershell
Add-MpPreference -ExclusionPath '<sentinel.exe 所在目录>'
```

或者在「Windows 安全中心 → 病毒和威胁防护 → 保护历史记录」里
把 `sentinel.exe` **还原**（还原后建议立刻加排除项，
否则下一次扫描还会再被隔离一次）。

⚠️ 哨兵**自己**查不到「exe 被杀毒软件隔离了」这件事 ——
双击没反应时，先查上面那条命令。

| ④ 挂载管理 | `/settings/sessions` | 当前会话、雷达扫描根目录、启动命令 |

⚠️ **URL 会真的变**（`/settings` → `/settings/llm`）——
可以收藏、可以后退、刷新也记得你翻到哪一页。
右侧是**全新渲染**的页面，**只有该功能**的内容，不再挤成一堆。

**② 双击 exe 先问你再动手**

```text
============================================================
 哨兵 Sentinel —— 你想让它做什么？
============================================================

 [1] 启动演示模式 (体验界面)
       全是模拟数据，不碰你的任何进程。

 [2] 开启雷达 (扫描已有的 Agent 日志)
       只读你自己机器上的 Agent 会话日志 —— 推荐。

 [3] 接管并启动新的 Agent
       边跑边审：告警当场拦下。

============================================================
请输入 1 / 2 / 3 后回车（直接回车 = 2）：
```

* ⚠️ **默认是 `[2] 开启雷达`** —— 不问就默认给「真实的东西」
  比默认给「假的」诚实；
* 非交互环境（CI / 后台服务）**不阻塞**，直接用默认值并**明确打印**选了哪个；
* 管道与文件重定向也认：`echo 2 | sentinel.exe`、`sentinel.exe < choices.txt`。

**③ 雷达只报「正在写入的」，并且认得 MiniMax 与 DeepSeek**

* 默认只返回**正在写入**的会话 —— 静默文件**连读都不读**
  （本机实测：12.1 秒 → **0.05 秒**）；
* `.codex` 降到**最后**（里面全是历史死文件），
  `.minimax/v2/sessions` 与 `.dsh/sessions` 排前面；
* **每个扫描根各拿一份预算** —— 以前是全局一份，
  `.codex` 一家用完，MiniMax / DeepSeek **一个都轮不上**；
* 列表**各根轮流出场**，界面同时能看到三家的会话；
* **DeepSeek harness 的 zstd 压缩日志能读**（工作区 / 会话 ID / 时间）——
  ⚠️ 但压缩流**没法按字节跟读**，所以**只能发现、不能接入**，
  界面上有明确徽章，服务端也明确拒绝。

```yaml
radar:
  scan_roots:
    - ".minimax/v2/sessions"     # MiniMax Code 真正落日志的地方
    - ".dsh/sessions"             # DeepSeek harness 的会话目录
    - ".mcode"                   # MiniMax Code（社区习惯叫法）
    - ".claude"                  # Claude Code
    - ".codex"                   # Codex —— 排最后（全是历史死文件）
```

* **顺序就是优先级**；
* 相对路径按**家目录**解析，绝对路径原样使用；
* 可以在设置页「④ 挂载管理 → 雷达扫描根目录」里直接改；
* ⚠️ 雷达最多下探 **5 层**，所以要指向**会话目录本身**。

**④ 挂载管理页给你一条能抄的命令**

「怎么开一个带日志输出、而且雷达能准确定位到的 Agent 任务？」
—— 页面上写清了三条判据，并给出**一键复制**的命令：

```text
sentinel --agent codex --cwd "D:\项目\你的项目" "你的任务指令"
```

### v3.0.1：演示能退出 · 设置能展开 · 雷达认得出工作区

v3.0.0 的实测反馈里有三条要命的问题，这一版把它们都修了。

**① 演示模式不再把人带偏**

双击 exe 仍然是演示模式，但红色横幅**最右侧**多了一个大按钮
【退出演示，开始真实扫描 →】：

* 点它会**真的**停掉演示进程（终端窗口随之关闭）；
* 页面上留下**能直接复制**的三条真命令
  （接管 Agent / `--scan` 审已有日志 / `--no-gui` 只看终端）；
* 终端里会**反复**提醒「不要关闭此窗口，看板正在浏览器打开…」——
  每 8 秒一次，共 8 次。

**② 设置页改成左右分栏**

左边 **240px** 导航（模型路由 / 通知通道 / L1 规则 / 挂载管理），
点一下切右边，右边占满剩余宽度。
卡片**不再自带小滚动条**，整页统一滚动。
窄屏（<760px）下左边那列变成**顶部横向 Tab**。

**③ 雷达能挖出真正的工作区**

以前扫出来的每一条都是「未知工作区」——
根因是新版 codex 把 `cwd` 写在了 `payload.cwd` 里，
而旧代码只找顶层和 `item`。现在按
`顶层 → item → payload → message → data` 挨个找，
并按这条回退链兜底：

```
日志字段 → args/command 里的目录参数 → 进程的工作目录 → 父目录名 + 文件名
```

最后一档是**硬性兜底** —— 宁可显示「这是哪个文件」，
也**不再显示「未知工作区」**。

扫哪些目录由配置决定：

```yaml
radar:
  scan_roots:
    - ".codex"                   # Codex
    - ".mcode"                   # MiniMax Code（社区习惯叫法）
    - ".claude"                  # Claude Code
    - ".minimax/v2/sessions"     # MiniMax Code 真正落日志的地方
```

* 相对路径按**家目录**解析，绝对路径原样使用（比如 `D:\项目`）；
* 也可以在设置页「④ 挂载管理 → 雷达扫描根目录」里直接改；
* ⚠️ 雷达最多下探 **4 层**，所以要指向**会话目录本身**。

列表里还会显示**会话 ID** 与**首条消息时间**，
方便你确认「这是我刚才跑的那个任务」；
默认只显示「正在写入」的会话主日志，历史记录收在复选框后面。

详见
[`_管理文档/文档与报告/versions/v3.0.1-demo-ux-and-radar.md`](_管理文档/文档与报告/versions/v3.0.1-demo-ux-and-radar.md)。

### 真实 Webhook 触达测试

v1.x 一直只跟**本地故障注入服务器**打交道 —— 协议对不对、重试退避有没有生效，
都验证过了，但**从没打过真实服务**。

v2.1.0 补上这块：

```bash
# 贴上你自己的地址，真发一条
python _构建与发布/scripts/test_real_webhook.py \
    --url "https://oapi.dingtalk.com/robot/send?access_token=你的token"

# 只看看配置里有哪些，不发
python _构建与发布/scripts/test_real_webhook.py --list
```

它会打印**本机 IP**（钉钉 / 飞书的 IP 白名单要一个个填）、
**版本号**，以及 HTTP 状态码与响应体 ——
非 0 的 `errcode` 会**逐条翻译成人话**。

另外，哨兵**启动时**如果发现你配了真实 Webhook，会**真的发一条**出去
（含版本号与本机 IP），这是开箱即用的连通性验证：

```
[SENTINEL] Webhook 自检 → https://oapi.dingtalk.com/robot/send?access_token=xxx：已送达
```

嫌吵可以关掉：

```yaml
alert:
  webhook_startup_test: false
```

### 并发压力测试（双路真 Agent）

```bash
python _构建与发布/scripts/stress_test.py --agent codex --port 8210
```

同时拉起**两个真 codex 进程**，在两个目录里跑同一份重构任务，
连**两个真 SSE 客户端**，验七件事：
会话隔离（不串台）、资源占用、**守护者只挂起出事那一路**、
各路告警写进各自的日志、Token 计数器在切换会话后不归零、
以及「死循环只告警不挂起」这条设计规矩。
压测结束还会顺手出两份**真实**的晨报。

### 多路会话中枢（Sentinel Hub）

一个看板同时盯**多路** Agent：

- **左侧会话列表** —— 每一路一个条目，带状态徽章与告警数，**点一下切过去**；
- **顶部全局状态条** —— `Codex-运行中`、`mcode-已挂起`、`Claude-已结束`，一眼看清全局；
- **事件按会话分流** —— 各路告警**不串台**，SSE 事件带 `session_id`。

```bash
# 一个 JSON 文件描述多路会话
cat > logs/hub_sessions.json <<'JSON'
{
  "sessions": [
    {"id": "codex-a", "label": "Codex · 写脚本", "agent": "codex",
     "task": "在当前目录创建 hello.py 并运行它", "cwd": "D:/work"},
    {"id": "codex-b", "label": "Codex · 查日志", "agent": "codex",
     "task": "分析 logs 目录里的错误", "cwd": "D:/work"}
  ]
}
JSON

# 同时接管多路 Agent，一个看板统管全局
python _构建与发布/scripts/run_with_sentinel.py \
    --session-file logs/hub_sessions.json --port 8151 --keep-alive
```

`--keep-alive` 让 Agent 跑完后**看板不关**，一直留到 Ctrl+C ——
这才是「挂一整夜」该有的行为。

> 通知通道**全局共用一个** —— 每路各建一个的话，
> 同一件事会被推 N 次到手机上，那不是「多路复用」，是「多路骚扰」。

### 事故演练（Fire Drill）

自动化脚本**真跑**整条链路 —— 真拉 Agent、真触发红线、真在内核层挂进程、
真推到 Mock Webhook、真用 uvicorn 看板验证 SSE：

```bash
python _构建与发布/scripts/fire_drill.py --agent codex
```

实机结果（codex-cli 0.162.1）：

| 指标 | 结果 |
| --- | --- |
| 红线拦截耗时（判定 → 内核挂起完成） | **0.9 ms** |
| L2 解释补充耗时（原告警 → 解释回填） | **7529.4 ms** |
| 内核层已挂起 / Webhook 已推送 / 看板收到 | ✅ ✅ ✅ |

那 7.5 秒里哨兵**一秒都没停** —— 进程已经挂起、手机已经收到卡片，
解释只是在**最后**补一句人话。

### 接入外部大模型 API（可选）

L2 层统一走 `LLMProvider` 契约，所以换个后端只是改配置：

```bash
# 密钥走环境变量，不落盘
export SENTINEL_LLM_API_KEY=sk-xxxx
```

```yaml
# config/config.yaml
llm:
  provider: "openai_compatible"        # 本机 NInfer 也是这一条 | ollama | openai_compatible
  base_url: "https://api.deepseek.com/v1"
  model: "deepseek-chat"
```

换成 Kimi 把 `base_url` 改成 `https://api.moonshot.cn/v1`、
`model` 改成 `moonshot-v1-8k` 即可；
自建的 vLLM / LM Studio / one-api 网关同理。

> ⚠️ **切到外部 API = 允许被审查的日志内容离开本机。**
> 三道保险：必须显式配置才生效、送出前**强制脱敏**（密钥 / 令牌 / 个人信息）、
> 错误消息里的密钥也会被遮蔽后再进日志。
> ⚠️ 但**地址在本机**（`127.0.0.1` / `localhost`）就**不是**外部 API ——
> 哨兵会自动认出本机地址，数据**一步没出本机**，
> 也**不会**对你喊「数据会离开本机」。

跑测试：

```bash
python -m pytest
```

**v3.4.0 —— 托盘化彻底退出 · 挂载清理与状态纠偏 · 雷达排除自身。**

- **🧹 后台幽灵，根治了**：
  Windows 右下角常驻一个哨兵图标，右键菜单只有两项 ——
  【打开看板】与【**彻底退出**】。
  点【彻底退出】会**优雅地**关掉看板服务、结束哨兵**自己拉起**的子进程、
  收掉图标，然后退出程序 —— **不留任何后台残留**。
  ```
  ┌─────────────┐
  │  打开看板    │   ← 双击托盘图标也开
  ├─────────────┤
  │  彻底退出    │   ← 点了就干净退出
  └─────────────┘
  ```
  - 看板右上角另有**红色**【关闭哨兵】按钮：点一下先弹确认框，
    确认后后台彻底退出；
  - **关掉黑框**现在也真的会退出（以前会留下杀不掉的幽灵）；
  - 三条路走的是**同一套**收尾逻辑 —— 效果完全一样；
  - ⚠️ **雷达挂载进来的、你自己启动的 Agent，不受影响** ——
    哨兵只结束**自己拉起**的子进程（红线 R6）。
- **🧹 挂载删不掉了**：
  左侧每个会话卡片右上角多一个 `[×]` ——
  点一下就把这个会话从哨兵这儿卸载（`DELETE /api/sessions/{id}`），
  列表里**立刻**消失，后端停止跟随。
  雷达自己那个占位会话**不给**这个按钮。
  - ⚠️ 它**只影响哨兵**：不会删你的日志文件，也不会停你的 Agent。
- **🩺 状态不骗人了**：
  挂载时反查到了 PID 的会话，每 10 秒查一次存活 ——
  进程没了就把状态从「运行中」改成「**已退出（静默）**」，
  并且**停止重放**那份不会再变动的旧日志。
  - 判定是**三态**：活着 `True` / 死了 `False` / **不知道** `None` ——
    「查不到」**不等于**「死了」，所以绝不会误报；
  - 灰色显示，不用红色 —— Agent 跑完是正常结束，不是出事了。
- **🔦 雷达不再抓自己的垃圾**：
  新增 `radar.exclude_keywords`（默认 `sentinel` / `stress` / `test`）——
  路径命中这些词的日志**一律不显示**，哨兵压测留下的残留
  不再挤掉你真正在跑的任务。
  - ⚠️ 是**子串**匹配，所以 `contest` 也会被 `test` 命中；
    被误伤就把那一条从配置里删掉。
- **🔦 你自己的 Agent 也认得出来了**：
  新增 `radar.custom_process_features`（例如 `my-cli`）——
  **命令行或工作目录**里命中它的进程，雷达也会识别并提示。
  - 匹配时会**去掉分隔符**再比一次 ——
    你写 `my-cli`、目录叫 `MyCLI`（中间隔着分隔符）也能对上；
  - 少于 3 个字符的特征**直接忽略** —— 一个字母会命中满机的 Node 进程。
- **👀 「看不到流式滚动」不是坏了**：
  「实时审核流水」初始状态写清楚：
  「正在实时读取日志流，若无告警，此处将滚动显示正常操作。」
  设置页也说明白了：哨兵是**旁路日志跟随**、不是侵入式 Hook，
  前提是 Agent 开启了 **JSON 日志输出**。
- **红线一个字都没改** —— R1–R9 与 v2.1.0 **完全一致**。
  哨兵依然只读，不碰别人的进程，不会自动接管任何东西。

**v3.3.2 —— 雷达活跃进程感知 · 快捷重定向命令。**

- **🔦 终端里跑着 Agent、看板却抓不到？哨兵现在会告诉你**：
  雷达除了扫**文件**，也扫**进程**。
  发现「本机有正在跑的 Agent，却对不上正在监控的日志」时，
  看板**左侧**亮起橘黄提示：
  ```
  ⚠️ 检测到本机有 1 个活跃的 MCode 进程，未发现可读日志。
  若要监控，请点击此处手动填入其输出文件路径，
  或者用 > log.jsonl 重定向重启。
  ```
  - 判「有没有被监控」用**三条信号**，从确定到推断：
    命令行带着日志路径（确定）→ 工作目录对得上（确定）→
    同类型 Agent 的日志刚在雷达目录里被写过（推断）；
  - 认一个进程是不是 Agent，**两层信号缺一不可**：
    进程名要对（`node.exe`…）**且**命令行要命中特征
    （`@minimax-ai/code`…）——
    只看进程名会把满机的 Node 算进来；
  - **一切正常时它不占地方**；
  - psutil 缺失 → 整体降级，提示不出现（红线 R5）。
- **📋 挂载管理页给你一条能直接抄的命令**：
  选好 Agent、填好任务指令，命令实时生成：
  ```text
  mcode exec --output-format stream-json --cwd "D:\项目\demo" "你的任务指令" > "D:\项目\demo\logs\capture.jsonl"
  ```
  - **针对当前这台机器**：工作目录与落盘路径都是现成的；
  - ⚠️ 重定向出来的文件必须是 **JSONL**（每行一个 JSON 对象）——
    纯文本流哨兵解析不了，不会有告警；
  - 跑完以后回看板点【**＋ 发现/挂载进程**】把那个路径填进去即可。
- **红线一个字都没改** —— R1–R9 与 v2.1.0 **完全一致**：
  v3.3.2 只做了两件事：**多显示一条提示**、**多给一条命令**。
  哨兵依然只读，不碰别人的进程，也不会自动接管任何东西。

  - **留下的**：`_构建与发布/scripts/remove_startup_residue.ps1`

  - 哨兵**每次启动都会主动看一眼**残留，

  - 理念一句话：**用完即走，想开才开** ——
    哨兵**只在你手动启动时**运行，用完它**自己退出**；
- **引擎掉了不再悄无声息**：
  新增 `src/core/engine_watchdog.py`，**每 30 秒**只读探活一次
  （`GET /models`，**不触发推理、不烧显存**）；
  掉线立刻在终端 + 看板 + 手机上喊
  `[CRITICAL] NInfer 引擎已掉线！L2 判定和解释已停用！`，
  引擎回来也报一声；
  ⚠️ 探活前会**非阻塞地**抢引擎的串行锁 ——
  NInfer 是单并发，抢不到就跳过这一拍，绝不把引擎撞崩；
  ⚠️ **只监控，不替你拉起引擎** —— 保持只读边界，动手的是你；
- **「一个子任务吃掉整轮」现在会被当场拦截**：
  新增 `src/core/timebox.py` —— 同一件事（或同一类操作）磨过时间盒
  （默认 15 分钟）就判 `[CRITICAL] 严重跑偏` 并推手机；
  这条根因来自《Agent 跑偏警示录》，之前**一次都没被检测过**；
  守护者**武装着**的时候会自动挂起死磕的进程（可逆）；
- **防误杀**：
  README 有显眼的**【防误杀指南】**；
  `_构建与发布/scripts/add_defender_exclusion.ps1` 一键加排除项
  （需要管理员权限）；
  `build_exe.py` 每次打包后都会**显眼地**提醒你；
- **启动时的极度清晰提示**：
  本地引擎连不上时，体检报告尾部会**跳出表格**给一段醒目说明 ——
  写清楚「现在会怎样 / 怎么办 / 怎么自查」，
  而不是让用户对着干巴巴的告警猜哨兵是不是坏了；
- **打包目录里的旧配置会挡住一切**：
  `<exe 目录>/config/config.yaml` 优先级最高（那是设置页写回的那份）——
