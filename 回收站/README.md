# 回收站 —— 临时垃圾的指定去处

> **这里不放任何有价值的东西。**
> 确认没用的文件往这儿扔，攒够了整目录清空即可。

---

## 1. 为什么要有它

v0.6.0 之前的目录规范里，根目录只有「白名单内的」和「白名单外的」两档 ——
白名单外的东西要么进归档区（`_备份与归档/`），要么直接删掉。

直接删的问题是**没有后悔药**：删错了才发现那是重要的调研素材，就找不回来了。

所以单独开一个 `回收站/`：

- 位置在根目录，**一眼看得见** —— 不像散落在某个角落的临时文件；
- 内容**不入 Git**（`.gitignore` 已排除），不会污染仓库；
- 定期清空即可 —— 里面的东西已经确认过没用了。

---

## 2. 什么该进回收站

| 该进 | 不该进 |
| --- | --- |
| 一次性的测试输出、临时日志 | 有价值的历史资产 → `_备份与归档/` |
| 跑了一半的草稿、废弃的中间产物 | 项目文档 → `_管理文档/文档与报告/` |
| 重复下载的安装包、压缩包 | 源码 → `src/` |
| 一眼确定是垃圾的文件 | 仍有疑问的 → 先问，别急着扔 |

> **有疑问的别直接删。** 拿不准就进回收站 —— 那里至少还有一次反悔的机会。

---

## 3. 规矩

1. **只进不出**（除了清空）：进回收站的东西不迁回主线；
2. **定期清空**：建议每周清一次，别让它长成第二个归档区；
3. **不入 Git**：`.gitignore` 已排除本目录内容（保留本 `README.md`）；
4. **不影响功能**：回收站里的东西删掉，哨兵照常运行。
