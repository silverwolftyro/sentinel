## 2. 代码规范（PEP8）

### 2.1 基础要求

- 遵循 [PEP 8](https://peps.python.org/pep-0008/)；
- **行宽上限 79 字符**（含注释与文档字符串）；
- 使用 **4 空格**缩进，禁止 Tab；
- 文件末尾保留一个换行，文件使用 **UTF-8** 编码。

### 2.2 命名

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 模块 / 文件 | 小写 + 下划线 | `claude_code.py` |
| 类 | 大驼峰 | `BaseAdapter` |
| 函数 / 变量 | 小写 + 下划线 | `parse_event` |
| 常量 | 全大写 + 下划线 | `DEFAULT_TIMEOUT` |
| 私有成员 | 前置单下划线 | `_read_offset` |

### 2.3 导入顺序

标准库 → 第三方库 → 本项目，三组之间空一行，组内按字母序：

```python
import json
import os
from dataclasses import dataclass
from typing import Optional

import requests
import yaml

from src.adapters.base import BaseAdapter
```

### 2.4 类型注解与文档字符串

- **所有**公开函数与类方法必须带类型注解；
- 公开模块、类、函数必须有 docstring，说明「做什么 / 为什么」；
- 数据结构优先使用 `dataclass` 与 `Literal` 表达取值范围，而非裸字符串。

### 2.5 日志而非 print

- 库代码中**禁止**使用 `print`；
- 统一使用标准库 `logging`，日志级别遵循：调试细节 `DEBUG`、关键节点 `INFO`、
  可恢复异常 `WARNING`、不可恢复/审查失败 `ERROR`；
- 哨兵自身的日志写入 `logs/`，与被监控数据分区存放。

### 2.6 异常处理

- 只捕获**预期**的异常类型，禁止裸 `except:`；
- 审查侧的异常必须**降级并继续运行**（红线 R5），不得让被监控 Agent 因哨兵异常而受影响；
- 异常信息必须可定位：包含来源、文件路径、事件类型等上下文。

> **⚠️ v3.0.0 起：禁止 `except: pass`（包括 `except <具体异常>: pass`）。**
>
> 「降级」不等于「消失」。审查侧确实可以降级继续跑，
> 但**必须留下一条能定位的日志** ——
> 否则半年后没人说得清「为什么那行没报」。
>
> 落地方式：
>
> | 位置 | 写法 |
> | --- | --- |
> | `src/` 下的库代码 | `logger.warning(...)` / `logger.debug(...)` |
> | 验收 / 演示脚本 | `print(..., file=sys.stderr)`（走 stderr，不污染 stdout） |
> | 输出流本身就坏了 | `logging`（写 stderr，比 `print` 更有机会落地） |
>
> 这条有**回归测试**钉住（`tests/test_v300_release.py` 用 AST 扫 `src/`），
> 有人写了 `except: pass` 测试就会红。

### 2.7 静态检查（ruff）

**v3.0.0 起，静态检查是硬性门槛。**

```bash
pip install ruff
python -m ruff check .        # 必须零告警
```

配置在**根目录 `ruff.toml`**（不在根目录 ruff 就找不到它，规则全部失效）。

它**不是** `ruff check --select ALL` —— 全开是 **22240 条**，
绝大多数是「风格偏好」（`typing.List` → `list`、`.format()` → f-string），
一改就是一千多行，diff 全是噪音，真正的缺陷反而被淹掉。

配置只开**与本项目规范直接相关**的规则集，
并且**每条 ignore 都写了理由**（理由在 `ruff.toml` 的注释里）。
几条特意不开的：

| 规则 | 为什么不开 |
| --- | --- |
| `UP006` / `UP045` / `UP032` / … | 本项目**一贯**用 `typing.List`（§2.4），全项目都这么写 |
| `PLC0415` | **惰性导入是架构决定** —— GUI 应用层不许在顶层 import `src.core.*`（见 `ARCHITECTURE.md`） |
| `RUF001` / `RUF002` / `RUF003` | 中文项目，中文标点本来就长得像 ASCII |
| `RUF100` | `noqa` 是**意图声明**，规则集以后会变，留着比删掉安全 |
| `TRY401` | 本项目要求异常消息**带类型、带上下文**（§2.6），写进 message 才好按关键字检索 |

**新增 `noqa` 的规矩**：必须带**中文理由**，
写成 `# noqa: BLE001 —— 进程可能已经没了` 这种形式。
光写 `# noqa` 不算数。

### 2.8 安全与隐私

- 任何写入日志或送入模型的文本都必须先经过脱敏（密钥、令牌、个人信息）；
- **不得**把密钥、令牌、`.env` 内容写入代码、日志或文档；
- 哨兵全程只读，不写被监控目录。

**唯一的例外 —— 守护者模式（`intervention_mode: guardian`）**

守护者会对**被监控进程**做两件事，且都必须是可逆的：

- 挂起进程（`psutil.Process(pid).suspend()`）；
- 发送中断信号（POSIX 的 `SIGINT`）。

硬性约束：

- ❌ **绝不 kill 进程**。Windows 上 `os.kill(pid, SIGINT)` 等价于
  `TerminateProcess`，那是**终止**，不是中断 —— 哨兵**禁止**在 Windows 上
  使用 `os.kill` 传递 `SIGINT`；
- ✅ 干预必须可逆（随时能 `resume`）；
- ✅ 必须可被用户否决（`override`），且否决要留痕到 `logs/`；
- ❌ 不得对 PID 0 / 1 / 哨兵自身 / 哨兵的父进程动手；
- ⚠️ 守护者默认关闭，需在配置里显式开启 —— 权限必须小于用户。

## 3. 提交规范

采用 [Conventional Commits](https://www.conventionalcommits.org/zh-hans/)。

### 3.1 格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

- `subject`：祈使句，≤ 50 字符，结尾不加句号；
- `scope`：可选，取模块名（`core` / `adapters` / `rules` / `llm` / `alert` / `docs` / `config`）；
- `body`：说明**为什么**这么改，而不只说改了什么。

### 3.2 type 取值

| type | 用途 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `docs` | 文档变更 |
| `refactor` | 不改变外部行为的重构 |
| `test` | 测试新增或修正 |
| `perf` | 性能优化 |
| `chore` | 构建、依赖、脚本等杂务 |
| `ci` | CI 配置 |

### 3.3 示例

```
feat(rules): 新增密钥泄漏检测规则

规则层此前无法识别被硬编码在命令行参数中的 API Key。
新增 builtin/secret_leak.py，命中后给出 warn 级别并附证据片段。

Co-Authored-By: 浅忆QanYi <qanyi@example.com>
```

## 4. 版本迭代流程

### 4.1 语义化版本

版本号格式 `MAJOR.MINOR.PATCH`：

| 位 | 何时递增 | 示例 |
| --- | --- | --- |
| MAJOR | 不兼容的架构或配置变更，旧配置直接失效 | `v1.0.0` |
| MINOR | 向后兼容的新功能 | `v0.2.0` |
| PATCH | 向后兼容的缺陷修复 | `v0.1.1` |

**当前版本：`v3.2.0`**（3.x 阶段表示**只读审计监控**形态：哨兵**只观察、不动手**
—— 守护者最多把进程**挂起**，且随时可以放行，所有动作都留痕在 `logs/`。
因此 MINOR 位的新增**必须**继续满足「可逆 / 可否决 / 留痕」三条约束，见
[`ARCHITECTURE.md`](ARCHITECTURE.md) §1.1 的 R7 / R8 / R9）。

> ⚠️ v2.0.0 起，**修改被监控 Agent 的工作目录**这件事从「禁止」变成了
> 「**必须先出计划、用户确认才执行**」。
> ⚠️ v2.1.0 起，**终止被监控进程**从「禁止」变成了
> 「**唯一例外**：用户点【回滚并重试】，且只针对哨兵自己挂起过的 PID」。
> 代码审查时看到这两类逻辑，请确认它：
> ① 走了 `SafePointService.plan()` / `restore()` 的安全路径，
> ② 有 `_inside()` 路径穿越防护，
> ③ 留了 `rollback` / `resume` 事件。
>
> ⚠️ v2.2.0 新增的三样能力（**案发时间线 / 开箱安全体检 / 规则热重载**）
> **都不扩大动作权限**：
> - 时间线与体检是**只读**的（体检只发两个极小的探测请求）；
> - 热重载只是**换规则**，换出来的规则依然只做「告警 / 挂起」。
>
> 代码审查时看到热重载，请确认它：
> ① **只换 `RuleEngine`**，不顺带重建通知通道 / 守护者；
> ② 坏配置**保留旧规则**（绝不让防线清零）；
> ③ 替换是**原子**的（先造好新的再换上去）。
>
> ⚠️ v2.2.1 只改了**启动路径**的健壮性，**红线不变**：
> - 改入口参数处理时，请确认**无参数能进演示模式**
>   （看板的解析器只认 `--demo` / `--watch`，缺一个就 `sys.exit(2)` → 闪退）；
> - 加新的致命错误出口时，请用 `src.console.fatal_guard` 包一层，
>   **别让窗口自己关**（真终端才挂起，管道调用不能被挂住）。
>
> ⚠️ v2.2.2 只让**演示模式说破自己**，**红线不变**：
> - 演示模式与真实模式的**视觉标识必须同时出现在两端** ——
>   看板（横幅 / 斜条纹 / 徽章 / 会话名）**和**
>   终端（6 行说明）。只做一端就还会有人被误导；
> - 演示模式的标识**不许**出现在真实接管模式（`--agent`）里；
> - 终端提示在**启动路径**上，打印前必须想好编码 ——
>   stdout 被重定向时会退回 GBK，编不出来的字符会炸掉启动。
>
> ⚠️ v2.4.0 把**挂载进来的会话**从「只读」升级为「全功能」，**红线不变**：
> - 守护者**依旧要用户亲手武装** ——
>   反查得到 PID 只是**把选项摆出来**，开关**默认关着**；
>   武装之前挂载会话**只读、只报告**（R7）；
> - **反查只敢认置信度达标的结果**（≥ 0.75）——
>   置信度不够就显示「[未绑定进程]」并**禁用**开关，
>   绝不拿一个「大概是某个进程」去挂起别人；
> - 反查器**必须排除哨兵自己**（含打包版的同名子进程）——
>   否则哨兵会把自己当成被监控对象；
> - 运行中**补建**意图追踪器时，**必须**走
>   `SentinelEngine.set_intent_tracker()` ——
>   直接赋值 `engine.intent_tracker` 会**丢掉异步回调**，
>   漂移结论没人接，DRIFT 告警**永远发不出来**；
> - 挂载会话**不继承**配置里的全局 `task_goal` ——
>   硬套只会凭空造出一堆**假的**漂移告警；
> - SSE **微批处理**后，前端**必须**同时认
>   `{"type": "lines"}`（批量）与 `{"type": "line"}`（单行，兼容旧脚本）；
> - 新增**惰性导入**的模块必须同步补进
>   `build_exe.py` 的 `HIDDEN_IMPORTS` ——
>   漏了的代价是「打包成功、点按钮才崩」（`src.radar` 就是这种）。
>   `psutil` 是**可选依赖**，走 `_optional_hidden_imports()`，
>   装了才点名。
>
> ⚠️ v2.3.0 只做「**看得见**」与「**说得清**」，**红线不变**：
> - 挂载进来的会话**绝不能**写被监控目录 ——
>   告警日志一律落在哨兵自己的 `logs/attached/` 下（R1：只读）；
> - 挂载进来的会话**不许**带守护者 ——
>   在没弄清那个进程是不是用户的 Agent 之前，不许动它（R7）；
> - 写 `config.yaml` **只能用** `config_loader.save_config()`
>   的**外科手术式**改写 —— **绝不许**用 `yaml.safe_dump` 整体重写
>   （那会把用户写的中文注释全抹掉）；
> - 密钥字段下发时**必须打码**，且前端回传的**打码值不许写回去**
>   ——否则用户真正的密钥会被 `********` 覆盖掉；
> - 前端页面脚本**必须**暴露 `window.SentinelPage = { init, destroy }`，
>   `destroy()` 要关掉 EventSource 与定时器 ——
>   否则路由切走以后后台还在轮询、还在收 SSE；
> - 新增**惰性导入**的模块必须同步补进
>   `build_exe.py` 的 `HIDDEN_IMPORTS` ——
>   漏了的代价是「打包成功、点按钮才崩」（`src.radar` 就是这种）。

### 4.2 一次迭代的完整步骤

1. **确定版本号**：按上表判断递增位，写成 `vX.Y.Z`；
2. **更新 `CHANGELOG.md`**：在文件顶部新增对应条目，格式统一为
   `## [vX.Y.Z] - YYYY-MM-DD - 变更标题`，并按 `新增 / 变更 / 修复 / 移除` 分组；
3. **新增版本文档**：在 `_管理文档/文档与报告/versions/` 下创建
   `vX.Y.Z-<短标识>.md`
   （如 `v0.2.0-adapters.md`），记录本次目标、关键设计决策、影响面与后续计划；
4. **更新 `README.md`**：功能、用法或目录结构发生变化时同步更新；
5. **更新架构文档**：分层或接口变更时同步更新
   `_管理文档/文档与报告/ARCHITECTURE.md`；
6. **打标签**：`git tag -a vX.Y.Z -m "版本说明"`，标签名与 `CHANGELOG.md` 中的版本号**必须完全一致**。

### 4.3 硬性要求

- ❌ 禁止出现两个同名版本号；
- ❌ 禁止在 `CHANGELOG.md` 中留下未发布（Unreleased）却不说明状态的条目；
- ✅ 版本号在 `CHANGELOG.md`、`_管理文档/文档与报告/versions/` 文件名、
  Git 标签三处必须一致；
- ✅ 每次版本递增都必须有对应的
  `_管理文档/文档与报告/versions/*.md` 文档。

## 5. 目录与文档规范

### 5.1 文档归属

**所有项目文档统一存放在 `_管理文档/文档与报告/` 目录下**，禁止在根目录堆放 `.md` 文件。

| 文档 | 位置 |
| --- | --- |
| 架构设计 | `_管理文档/文档与报告/ARCHITECTURE.md` |
| API 定义 | `_管理文档/文档与报告/API.md`（需要时新建） |
| 贡献指南 | `_管理文档/文档与报告/CONTRIBUTING.md` |
| 版本设计与变更记录 | `_管理文档/文档与报告/versions/vX.Y.Z-<标识>.md` |
| 界面实拍与设计稿 | `_管理文档/文档与报告/assets/` |
| 变更日志 | 根目录 `CHANGELOG.md`（**唯一例外**，作为版本号事实来源） |

### 5.2 根目录白名单（硬性规范）

> 自 **v0.6.0** 起生效。v0.5.0 的白名单用的是纯英文目录名
> （`docs/` `scripts/` `archive/`）—— 看着整齐，实则把「这个目录归谁管」
> 这件事又推回给读者。现在改成**中文语义 + 下划线前缀**，
> 一眼就知道哪些是「管理类」、哪些是「工程核心」。

根目录**只允许**出现下面这些条目，一项不多、一项不少：

**管理类目录（置顶，带下划线前缀）**

| 目录 | 用途 |
| --- | --- |
| `_管理文档/` | 全部管理文档；其下 `文档与报告/` 存文档与报告 |
| `_构建与发布/` | 构建与发布物：`scripts/`（辅助脚本）与 `requirements.txt`（依赖清单） |
| `_备份与归档/` | 已退出主线的历史资产 / 外部项目副本（**内容不入库**） |

**工程核心目录（不带下划线，保持常规）**

| 目录 | 用途 |
| --- | --- |
| `src/` | 哨兵源码（四层架构，见 `ARCHITECTURE.md`） |
| `tests/` | 测试代码，目录结构镜像 `src/` |
| `config/` | 配置文件（`config.yaml` 不入库，模板为 `config.example.yaml`） |
| `logs/` | 运行时日志与截获数据（**不入库**） |

**回收站**

| 目录 | 用途 |
| --- | --- |
| `回收站/` | 临时垃圾的**指定去处**：确认没用的文件往这儿扔（**不入库**） |

**入口文件（留在根目录）**

| 文件 | 用途 |
| --- | --- |
| `README.md` | 项目门面：功能、用法、目录结构 |
| `CHANGELOG.md` | 变更日志，**版本号的唯一事实来源** |
| `.gitignore` | 忽略规则 |
| `pytest.ini` | 测试配置 —— **必须留在根目录**，否则 pytest 找不到它，配置全部失效 |
| `ruff.toml` | 静态检查配置（v3.0.0 起）—— **必须留在根目录**，否则 ruff 找不到它，规则全部失效 |
| `启动哨兵.bat` | Windows 一键启动器（v1.0.0 起）—— 自动选 venv / 系统 Python、装依赖、带上参数拉起哨兵 |

> ⚠️ `requirements.txt` **不在**根目录：它属于「构建与发布」，
> 位置是 `_构建与发布/requirements.txt`。
> 安装命令相应地变成：
> `pip install -r _构建与发布/requirements.txt`

> ⚠️ 根目录的**可执行脚本只有一个**：`启动哨兵.bat`（把哨兵跑起来）。
> 它必须和 `README.md` 放在一起，用户才知道「双击哪个」。
> 其余脚本一律归 `_构建与发布/scripts/`。
>
> ⚠️ **v3.3.0 起根目录不再有 `install_startup.bat`** ——
> 「开机自启」功能已被**彻底删除**（用户明确要求
> 「拒绝任何形式的开机自启动和后台静默驻留」）。
> 新增的自启脚本一律**不许**进来。

**唯一允许的例外**（工具自动生成、已被 `.gitignore` 排除、可随时删除重建）：

- `.pytest_cache/` —— pytest 的缓存目录
- `__pycache__/` —— Python 字节码缓存（出现在任意层级）

**处理「不在白名单里的东西」的统一动作：**

1. 是**文档** → 归入 `_管理文档/文档与报告/` 下对应的子目录；
2. 是**源码** → 归入 `src/` 下对应的分层目录；
3. 是**依赖 / 构建脚本** → 归入 `_构建与发布/`；
4. 是**已退出主线的历史资产** → 整体移入 `_备份与归档/`；
5. 是**一次性调研的原始素材** → 结论写进 `文档与报告/versions/`，原件移入 `_备份与归档/`；
6. 是**纯垃圾** → 扔进 `回收站/`（别直接删 —— 进了回收站还能后悔一次）。

> 移入 `_备份与归档/` 前请在 `_备份与归档/README.md` 的「当前归档内容」表里补一行，
> 说明它是什么、为什么被归档。

**违反本规范的处理**：提交前检查清单（第 7 节）会拦截；
Review 时发现根目录出现白名单外的条目，应直接要求作者处理，而不是「先放着」。
