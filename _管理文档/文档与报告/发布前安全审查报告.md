## 1. 审查范围与方法

### 1.1 扫描了什么

| 扫描面 | 范围 | 方法 |
| --- | --- | --- |
| **已跟踪文件**（真正会发布的） | `git ls-files` → **429 个** | 密钥形态匹配 + 绝对路径匹配 |
| 全部 `.py/.yaml/.json/.md/.txt/.toml/.cfg/.ini` | 工作区（含未跟踪） | 同上，另查外部 IP 与主机名 |
| 本地配置 | `config/config.yaml`（14,737 B） | 逐键检查（值只报形态） |
| 运行时产物 | `logs/`（100+ 文件）、`2026-10-31.txt`（1.26 MB） | 关键词 + 形态 |
| 第三方目录 | `third_party_agent_bridge/` | 跟踪状态 + 忽略状态 |

### 1.2 为什么只扫「已跟踪文件」最准

未跟踪的本地文件，只要 `.gitignore` 生效就**不会**进仓库；
**已跟踪**的才会。所以扫描的第一优先级是 `git ls-files`。

> 扫描器第一版扫的是「整个工作区」，结果把 `_管理文档/` 整个跳过了 ——
> 而那里面全是**已跟踪、会发布**的文档。发现后改成
> **只扫 `git ls-files` 的输出**，结论才成立。

### 1.3 扫描器怎么判「真密钥」

两道门，**都过**才算：

1. **键名门** —— 键名含 `api_key` / `token` / `secret` / `password` /
   `access_key` / `private_key` / `client_secret` / `authorization` /
   `credential` 等片段，**且**值不是占位符、长度 ≥ 8；
2. **形态门** —— 值本身像真凭据：
   `sk-…`、`ghp_/gho_/ghs_…`、`AKIA…`、`xox[baprs]-…`、`AIza…`、
   `sk-ant-…`、JWT（三段式）、≥32 位十六进制串、≥40 位 base64。

**占位符判定**：`your` / `changeme` / `example` / `fake` / `dummy` /
`<` / `填` / `写` / `这里` / `***` 等一律不算。

## 3. 发现二（高危）：`2026-10-31.txt` —— 1.2 MB 真实网关日志

### 3.1 它是什么

**本地 LLM 网关（`127.0.0.1:8888`）的请求/响应日志**，JSONL 格式，
每行一条完整往返。内容包含：

| 内容 | 敏感性 |
| --- | --- |
| `client.ip` / `client.port` / `client.user_agent` / `client.client_id` | **客户端 IP 与标识** |
| `headers`（含 `Host`、`User-Agent`、`Content-Type`） | 低 |
| `messages[]` —— **完整的 system prompt + user prompt** | **真实会话内容** |
| `response.raw_body` + `reasoning_content` | **模型推理全文** |
| `engine_request_id`（`req_…`）、`chatcmpl-…` | 请求标识 |
| `model`（`bonsai2-27b`）、`usage`、`timings` | 低 |

### 3.2 为什么它是最高风险项

它的关键词统计看着像有密钥：

| 关键词 | 命中 |
| --- | --- |
| `api_key` | 61 |
| `token` | 61 |
| `sk-` | **0** |
| `password` | **0** |
| `Authorization` / `Bearer` | **0** |
| `C:\Users\…` / `D:\项目\…` | **0** |

那 61 处 `token` 全部来自 `max_tokens` / `total_tokens` /
`completion_tokens` / `prompt_tokens` 这类**计数字段名** ——
**不是密钥**。所以它不是「凭据泄露」，而是**「真实会话内容泄露」**：
你的工作记录、prompt 全文、模型推理链、以及本机客户端 IP。

### 3.3 处置

1. **移入回收站**（`shutil.move`，可逆，没删）：
   `2026-10-31.txt` → `回收站/2026-10-31.txt`（1,262,856 字节，文件保留在磁盘上）；
2. **加进 `.gitignore`**（`/2026-10-31.txt`），附注释说明它是什么、为什么必须排除。

> ⚠️ 之前它**既没被跟踪、也没被忽略** —— 这是最危险的状态：
> 一旦执行 `git add .`，它就会**连同 1.2 MB 真实会话内容**进版本库。
> 现在两道防线都补上了。

> 审查报告本身会进公开仓库，把原值印在表里等于没脱敏。

### 4.2 脱敏规则（脱敏 ≠ 篡改历史）

这里有一条**必须讲清楚**的界线，和 v4.3.1 的「文案中性化」不是一回事：

| 类别 | 处理 | 理由 |
| --- | --- | --- |
| **实质内容**（如「上游派发的进程」这个功能名） | **保留** | 它是当时的技术事实，改掉等于篡改历史 |
| **偶然的环境细节**（账号名、本机目录名） | **脱敏** | 它**不承载任何技术含义**，只暴露「谁在什么机器上」，公开仓库会永久留存 |

脱敏只把环境细节换成占位符，**技术结论一个字没改**。

替换（尖括号里是**形态描述**，不是原值）：

```
C:\Users\<Windows账号名>     → C:\Users\<用户名>
D:\项目\<本项目目录名>        → D:\项目\<项目目录>
D:/项目/<本项目目录名>        → D:/项目/<项目目录>
D:\项目\<另一个项目的工作区名> → D:\项目\<你的工作区>
```

**结果**：25 个文件、**66 处**全部替换，**残留 0 处**。

### 4.3 刻意**保留**的路径

| 形态 | 理由 |
| --- | --- |
| `D:\项目\N.E.K.O`（5 处） | 上游项目的**公开目录名**（GitHub 上就有），不是隐私；而且 v3.1.0「自定义进程特征」这个**功能的示例本身就是它** —— 改了连功能说明一起改掉，还有测试断言依赖它（`tests/test_v350_cascade_and_streams.py`） |
| `D:\项目\demo`、`D:\项目\你的项目`、`D:\项目\my-cli`（9 处） | 本来就是**占位示例** |
| `C:\Users\x`、`C:\Users\...`（5 处） | 本来就是**占位示例** |
| `127.0.0.1:8888`（多处） | **回环地址**，本机 LLM 网关的默认端口 |

### 4.4 顺手修掉的真隐患：构建脚本里的硬编码路径

`_构建与发布/scripts/build_v401_drift_fixtures.py:53` 与
`eval_v401_drift_ab.py:54` 原来写的是：

```python
ROOT = r"D:\项目\<项目目录>"
if ROOT not in sys.path:
    sys.path.insert(0, ROOT)
```
这不只是隐私问题 —— **换一台机器这两个脚本就跑不了**，
而且公开仓库里的用户 clone 下来直接跑会报错。

已改为：

```python
ROOT = str(Path(__file__).resolve().parents[2])
```

实测推导结果：`D:\项目\<项目目录>`（`src/` 存在 ✓），
哪儿 clone 都能跑。

### 4.5 追加处置：发布前**最终质检轮**才发现的整批漏网

这一节是本文档**最重要的一节** —— 它记录的是本报告**第一轮自己漏掉的东西**。

**漏在哪**：第一轮（§4.1–§4.2）的扫描器用**单反斜杠**正则
（`D:\项目\…`）去匹配。而 **JSON 文件里的反斜杠是转义过的**
（`D:\\项目\\…`），于是：

* 15+ 个**实机取证证据 JSON**
  （`v340-radar-exclude-evidence.json`、`v340-tray-evidence*.json`、
  `v350-multistream-cascade-evidence.json`、`v380-*-evidence.json` 等）
  里的 **53 处**真实本机路径，**整批没被扫出来**；
* 加上正斜杠形态 `D:/项目/…` 的 2 处 —— 第一轮的正则**两种形态都不匹配**。

**怎么发现的**：最终质检轮把扫描改成「**遍历全部提交历史里的每一个 blob**」
（不再只扫工作树），并且**按匹配到的原始片段打印出来核对** ——
正是这个「打印原始片段」的动作，让「53 处被漏扫」变成了可见的事实。

**处置**：25 个文件、**66 处**全部替换为占位符，残留 0 处。
涉及形态（**两种反斜杠都要覆盖**）：

```
D:\\项目\\<本项目目录名>   → D:\\项目\\<项目目录>     （JSON 形态）
D:\项目\<本项目目录名>     → D:\项目\<项目目录>       （文本形态）
D:/项目/<本项目目录名>     → D:/项目/<项目目录>       （正斜杠形态）
```

> 📌 **教训**：扫描「敏感信息」时，**只看工作区不够** ——
> 要扫**提交历史里的每一个 blob**；而且正则**必须覆盖同一种内容的多种转义形态**。
> 只扫工作区 + 单形态正则，会给出「零泄露」的**假通过**。

### 6.2 那 8 条正则是什么

`src/agents/auth.py` 的 `GLOBAL_AUTH_PATTERNS` 与上游
`bridge/runner.py` 的 `_AUTH_PATTERNS` **逐条一致**：

```python
GLOBAL_AUTH_PATTERNS: Tuple[Pattern[str], ...] = (
    re.compile(r"authentication\s+required", re.IGNORECASE),
    re.compile(r"unauthenticated", re.IGNORECASE),
    re.compile(r"not\s+(?:logged\s?in|authenticated|signed\s?in)", re.IGNORECASE),
    re.compile(r"(?:please\s+)?use\s+`?/login`?", re.IGNORECASE),
    re.compile(r"(?:please\s+)?run\s+`?/login`?", re.IGNORECASE),
    re.compile(r"invalid\s+api\s*key", re.IGNORECASE),
    re.compile(r"credentials?\s+(?:expired|invalid|not\s+found|missing)", re.IGNORECASE),
    re.compile(r"请(?:先)?登录|尚未登录|未登录|需要登录|登录后(?:再|才)"),
)
```

这是**代码移植**，不只是「思路参考」。上游是 MIT 协议，
MIT 要求「版权声明与许可声明随软件副本一同提供」。

>    ⚠️ 其中**鉴权措辞表本身**（`src/agents/auth.py` 的 `GLOBAL_AUTH_PATTERNS`，
>    8 条正则）是**从上游 `bridge/runner.py` 的 `_AUTH_PATTERNS` 逐条移植**的 ——
>    属于**代码**，不只是思路。上游采用 MIT 协议，MIT 要求
>    「版权声明与许可声明随软件副本一同提供」，故本文件即为该声明的载体。
