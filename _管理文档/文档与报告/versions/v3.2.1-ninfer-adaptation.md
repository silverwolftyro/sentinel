## 1. 红线：这一版一个字都没改

**本版未新增任何红线修订。** R1–R9 与 v2.1.0 **完全一致**，**一字未改**。

逐条对照：

* 哨兵**依然只读** —— 本版只新增了「排队」与「剥离思考段」两件事，
  **一行用户代码都没改过**；
* 本版**没有**新增任何写用户文件 / 改用户代码 / 终止用户进程的路径；
* 换引擎**没有**放松任何东西 —— 新引擎跑在 `127.0.0.1`，
  数据**一步没出本机**，比原来的云端 fallback 更守红线；
* 本版新增的「思考段剥离」**只减内容**，不增内容 ——
  看板上的告警文案只会**更干净**，不会更脏；
* 本版新增的「串行排队」只影响**请求的时序**，不影响判定口径；
* 演习脚本新增的「越界看门狗」是**测试工具**的加固，
  **产品代码**没有新增任何终止用户进程的路径 ——
  它终止的只是**演习自己拉起来的那个 Agent**。

> ⚠️ 有一处**默认值**变了：配置模板的 L2 后端从 Ollama 换成 NInfer。
> 这是「把默认值改成用户当前真实在用的引擎」，**不是红线变化**。

## 2. 先探测，再动手：NInfer 到底是什么脾气

> **这一节是本版最重要的一节。**
> v3.2.0 之所以跑偏，第一条根因就是「没先问清楚环境」。
> 所以这一版**先打一次真实请求**，把结论写在下面 ——
> 后面每一条代码改动都对应下面某一条实测事实。

### 2.1 引擎身份

```
GET http://127.0.0.1:8888/v1/models
→ {"data":[{"id":"bonsai2-27b",
            "context_window":131072,
            "max_model_len":131072,
            "status":{"value":"loaded"},
            "meta":{"n_params":30377080816,"size":9506793888}}]}
```

| 项 | 实测值 |
| --- | --- |
| 引擎进程 | `ninfer-5070ti-win-x64-sm120a-v1.0.0.exe` |
| 模型文件 | `Ternary-Bonsai-2-27B-ninfer-v3.ninfer` |
| 模型名 | `bonsai2-27b` |
| 参数量 | 30,377,080,816（30.4B） |
| 权重体积 | 9.5 GB |
| 上下文 | **131072（128K）** |
| 协议 | **OpenAI 兼容**（`/v1/chat/completions`） |
| 并发 | **1**（`--max-concurrency=1`） |

### 2.2 四条硬约束（全部来自实测，不是猜的）

| # | 实测现象 | 哨兵的应对 |
| --- | --- | --- |
| ① | `response_format={"type":"json_object"}` 直接回 **HTTP 400**：`response_format_not_supported` / `structured output requires the server to start with --structured-output` | ① 配置里 `json_mode: false`；② 客户端还有一层兜底：**真收到 400 就自动摘掉字段重试一次**，并**记住**（以后不再白跑） |
| ② | 推理模型「思考」也吃 `max_tokens`：给 1024 时 `completion_tokens=1024`、`reasoning_tokens=1024`、**`content` 一个字都没有** | `max_tokens` 调到 **8192**；超时**拉满 600 秒** |
| ③ | 思考过程在 `reasoning_content` 字段里（实测 2955 字符），正文在 `content`（151 字符的 JSON） | 优先取 `content`；**`<think>…</think>` 整段剥掉**；`content` 空时**只从 `reasoning_content` 里抠出最后那段 JSON**，思考过程**只进 debug 日志** |
| ④ | **单并发** —— 同时发两个请求，引擎会**直接崩** | 客户端按 `base_url` **排队**（同一台引擎一把锁，云端 API 另排另的） |

### 2.3 速度（决定超时该给多少）

| 指标 | 实测 |
| --- | --- |
| 预填充（冷） | 1347 ms / 1322 token |
| 预填充（命中缓存） | **67 ms**（`cache_n=1317`） |
| 生成速度 | **36 ~ 44 token/秒** |
| 单次解释总耗时 | **40.5 秒**（裸请求）/ **79.9 秒**（走哨兵全链路，含首轮 400 重试） |

⇒ 60 秒的超时**必然**判不了；600 秒是合理值（超时是**上限**不是固定等待）。

### 2.4 一个必须记下来的坑：提示缓存不认 `max_tokens`

同一个提示连续请求，NInfer 会**直接返回旧结果** ——
连「被截断」都照抄：

| 请求 | 返回的 `completion_tokens` | `content` |
| --- | --- | --- |
| 第 1 次 `max_tokens=1024` | 1024（被思考段吃光） | **空** |
| 第 2 次 `max_tokens=8192`（同提示） | **1024**（命中旧缓存！） | **空** |
| 第 3 次 `max_tokens=4096`（同提示） | **1024**（还是缓存） | **空** |
| 第 4 次 `max_tokens=8192` + 提示扰动 | **2900+** | **151 字符 JSON** ✅ |

> **排查时如果一直看到「怎么给 token 都不出正文」，
> 先怀疑提示缓存，而不是引擎坏了。**
> 探针脚本因此提供了 `--nudge` 参数，专门用来绕过缓存。

## 3. 代码改动清单

### 3.1 `src/llm/api_client.py` —— OpenAI 兼容客户端

| 改动 | 说明 |
| --- | --- |
| `LOCAL_ENGINE_MIN_TIMEOUT = 600.0` | **本机**引擎的超时下限。超时不低于 600 秒（云端 API 不受影响） |
| `is_local_endpoint(url)` | 认本机地址（`localhost` / `127.0.0.1` / `0.0.0.0` / `::1` / `*.local`） |
| `chat()` 里的**串行排队** | `with engine_lock_for(self.base_url)` —— 同一台引擎绝不并发 |
| `chat()` 里的**response_format 退让** | 收到 400 且正文提到 `response_format` → 摘掉字段重试一次，并记住 |
| `_extract_content()` 重写 | 正文优先 → 剥 `<think>` → 正文空则从 `reasoning_content` 里**只抠 JSON** |
| `_warn_data_leaves_machine()` | **本机引擎不再喊「数据会离开本机」**（那是假话），改成一句本地确认 |

### 3.2 `src/llm/base.py` —— 引擎锁

新增 `engine_lock_for(base_url)`：按引擎地址分组的锁表。
**本地引擎和云端 API 各排各的队** —— 升级路由切到云端时不会被本地堵住。

### 3.3 `src/llm/parsing.py` —— 两个新函数

| 函数 | 作用 |
| --- | --- |
| `strip_thinking(text)` | 剥掉 `<think>…</think>` / `<thinking>` / `<reasoning>`，**包括没闭合的**（被 `max_tokens` 截断时很常见） |
| `extract_last_json_object(text)` | 取文本里**最后一个**配平的 JSON 对象（推理模型先聊后答，结论在末尾） |

### 3.4 配置（`config/config.yaml` + `config/config.example.yaml`）

```yaml
llm:
  provider: "openai_compatible"
  base_url: "http://127.0.0.1:8888/v1"
  model: "bonsai2-27b"
  api_key: "sk-no-key-required"
  timeout: 600
  max_tokens: 8192
  json_mode: false
  routing:
    enabled: false      # 本机默认关 —— NInfer 本身就是本地强模型
```

> ⚠️ `routing` 默认关掉了：NInfer 是本地强模型，
> 再挂一个云端 fallback 只会**把内容送出本机**（破坏红线 R4）。
> 想开随时能开，配置里写明了代价。

### 3.5 `_构建与发布/scripts/ninfer_probe.py`（新增）

**一次调用验证全链路**：模型列表 → 裸请求（看真实响应结构）→
走哨兵自己的 L2 通路（看**最终落到看板上的那段话**）。

```bash
python _构建与发布/scripts/ninfer_probe.py
python _构建与发布/scripts/ninfer_probe.py --nudge n1 --max-tokens 8192
```

## 4. 复盘：《Agent 跑偏警示录》

完整文档：[**Agent 跑偏警示录**](../Agent跑偏警示录.md)。

一句话版本：

> **跑偏不是「干了不该干的事」，而是「一直在干一件看起来相关、但不是当前最该干的事」。**

六处跑偏（原文有详述）：

1. **给一个即将被替换的引擎装权重** —— `ollama pull` 卡死 → 写补丁脚本补 blob。
   这段「成功」**对最终交付零贡献**（Ollama 后来被删了）；
2. **被一个「可能并不存在的问题」拖住** —— 事件数异常 → 先加机制后证伪；
3. **用复杂度掩盖「我还没搞懂」** —— 收尾卡死根因未知，却先写了三个「容错」机制；
4. **同一个失败重跑超过一次** —— 卡死后立刻重跑第二轮 30 分钟；
5. **交付优先级倒置** —— 工具链问题（下载 / Defender / GBK / 策略拦截）占了大头；
6. **演习 Agent 越界** —— Agent 自己跑了 `Remove-Item -Recurse`，被哨兵抓到。

六条**可执行**的规矩（v3.2.1 起照做）：

1. **环境契约先行** —— 开工前写清引擎地址 / 协议 / 模型名 / 超时 / 并发 / 上下文，**用一次真实调用验证**；
2. **结论先落盘** —— 跑长时长的验证，**结果先写文件**；
3. **同一失败最多重跑一次** —— 第二次不行就摊证据、换方法；
4. **交付物优先于工具链** —— 工具链问题最多给 10 分钟；
5. **子任务一律时间盒** —— 到点即停，把「没做完」写进交付说明；
6. **演习必须有越界看门狗** —— 见 §5。

> **哨兵能抓到跑偏，但抓不到「交付不了」。**
> 「意图漂移」看的是 Agent 的**行为序列**，
> 它没法知道「你正在给一个会被删掉的引擎装权重」。
> 这一轮真正的跑偏发生在**哨兵自己身上** —— 哨兵审 Agent，审不了自己。

## 5. 演习沙箱加固：越界看门狗

**问题**：v3.2.0 的 30 分钟演习里，被监控的 Agent 自己跑了一条

```
Remove-Item '...\__pycache__' -Recurse -Force
```

哨兵**抓到了**（`DANGEROUS` / `dangerous_command` / critical），
但这次它在沙箱里 —— **沙箱只是目录约定，不是隔离**。

**这一版加了一双眼睛**（`_构建与发布/scripts/final_night_crawl.py`）：

| 盯什么 | 怎么做 | 发现了怎么办 |
| --- | --- | --- |
| Agent 提到了哪些路径 | 尾读 `agent.jsonl`，扫**仓库根目录**、`.ssh`、`.aws`、`.config`、`C:\Windows`、`Program Files` | **记一笔**（`boundary_violations`），报告里带样例 |
| 仓库源码有没有被动 | 每 5 秒重新拍一次 `src/**/*.py` 的 SHA256 指纹 | **当场终止 Agent**（`boundary_terminated`），不等结束才发现 |

新增验收项：**「Agent 没有越界」**（越界次数 = 0）。

> ⚠️ 这个看门狗**只终止演习自己拉起来的那个 Agent**，
> **产品代码没有**新增任何终止用户进程的路径（红线 R6）。

> 取证：[`assets/ninfer-probe-v3.2.1.json`](../assets/ninfer-probe-v3.2.1.json)
> （上面这份就是它写出来的原始报文）
>
> ⚠️ 跑之前先把哨兵守护进程停掉 ——
> NInfer 的 `--max-concurrency 1` 是**硬约束**，
> 探针和守护进程同时打引擎会互相踩。

### 7.2 开机自启复测

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File '_构建与发布\scripts\install_startup.ps1' -Action install
```

| 检查项 | 结果 |
| --- | --- |
| 静默启动器 | `_构建与发布\dist\sentinel_startup.vbs`（**UTF-16LE + BOM**） |
| 快捷方式 | `…\Start Menu\Programs\Startup\哨兵 Sentinel.lnk` → `wscript.exe` + VBS |
| 通过快捷方式启动 | **2 个** `sentinel.exe`，命令行 `--daemon --radar --no-browser --no-health` |
| 端口 8000 | **HTTP 200**，`/api/system` 返回 `version: 3.2.1`、`radar_mode: true`、`memory_mb: 68.14`、`uptime_text: 0 分 13 秒` |

⚠️ **两个容易误判的点**（实测踩到，如实记下）：

1. `install_startup.ps1 -Action install` **不会立刻启动哨兵** ——
   它只写快捷方式与启动器，哨兵等**下次登录**才起来。
   装完 6 秒就去看进程，肯定看不到；
2. `wscript.exe "<中文名 .lnk>"` **起不来** ——
   wscript 对**非 ASCII 的 .lnk 路径**有脾气。
   但这**不影响开机自启**：登录时是**资源管理器**用 ShellExecute 打开快捷方式的，
   实测 `Start-Process -FilePath '<快捷方式>'`（同一条 ShellExecute 路径）
   **正常拉起** 2 个进程。
   → 测自启要用 ShellExecute，**不要**用 `wscript.exe <lnk>`。

### 7.5 「关于系统」页实拍

> 实拍：[`assets/settings-v3.2.1-system.png`](../assets/settings-v3.2.1-system.png)

顺带记一条**排查结论**（这一版踩到，害我绕了一圈）：

v3.2.1 打包后出的第一张实拍里，「关于系统」那段的粗体**「自己」看着像被画了两遍**，
一开始怀疑是 `-webkit-font-smoothing` 没配好。逐像素量完之后，结论是：

| 猜测 | 实测 | 结论 |
| --- | --- | --- |
| 页面里有两份这段文字 | DOM 只有 **1 个** `<strong>`，宽度 23px（2 个汉字 × 11.5px），正常 | **不是**重复渲染 |
| 合成粗体画成了两层 | 9 倍放大后**只有一个「自己」**，只是笔画边缘被分成红/蓝两色 | 是 **subpixel 抗锯齿的彩边** |
| 关掉 subpixel 能治 | A/B 实测两种写法的**每通道隐含 alpha 偏差几乎一样**（0.0255 vs 0.0316） | 在无头渲染器里**这一条根本没用** |

**真正的成因**：Windows 的 ClearType 式 subpixel 抗锯齿，
在 **1x** 下给 11.5px 的中文粗体描出 1 像素宽的红蓝边 ——
看着就像字被错开叠了一层。**页面本身没问题**，
2 倍以上像素密度下就干净了。

所以这一版：

* **没有**保留那个无效的 `-webkit-font-smoothing`（实测无效，
  留着只会让 Windows 上真实用户的文字变糊）；
* 给截图脚本加了 `--scale`（`capture_dashboard.py`），
  出正式实拍一律用 `--scale 2` —— 顺带把实拍清晰度提上去了。

### 8.2 ⚠️ Defender 误报（v3.2.0 发布当夜踩到，v3.2.1 仍未根治）

v3.2.0 打包完成后 10 分钟，Microsoft Defender 判定 `sentinel.exe` 是
`Trojan:Win32/Bearfoos.A!ml`（**机器学习**启发式，**不是**签名命中），
把它**隔离**了，还结束了正在运行的进程 ——
后果是**开机自启静默失效**（快捷方式还在，exe 没了，而且不报错）。

这是**误报**（本项目源码全程可审：只读监听 / 不注入进程 / 不终止用户进程，
没有混淆壳、下载器或凭据窃取；同机 v3.1.0 的 exe 从未被命中）。

**处置**：重新打包 + 交付 **zip 副本**（`_构建与发布/dist/sentinel-v3.2.1-win-x64.zip`）
+ 开机自启复测。

⚠️ **用户侧仍需管理员权限**加排除项：

```powershell
Add-MpPreference -ExclusionPath '<打包目录>'
```
