## 1. 红线：这一版一个字都没改

| 红线 | 这一版怎么守的 |
| --- | --- |
| R1 只读监听 | 档位解析、拖拽、折叠**全是读 DOM 与本地存储**；后端新增的 `/api/path_exists` **只做 `os.path` 判断，一个字节都不读文件内容**，更不写 |
| R2 不干预代码 | 新增的全是前端渲染逻辑 + 一个只读查询端点，**不含任何写被监控文件的动作** |
| R3 不注入进程 | 没有新增任何进程交互；`/api/path_exists` 与引擎无关 |
| R4 本地闭环 | 路径校验是**本地回环请求**（浏览器 → 本机 FastAPI），**没有任何内容出网** |
| R5 旁路失败 | 档位解析失败 → 退回原始 JSON 纯代码档；路径校验接口异常 → **退回直接接入，不阻断用户**；布局存储读取失败 → 用默认值，**不空转、不假死** |
| R6 不终止进程 | 这一版**没有任何**杀进程的逻辑；退出时的边界与 v3.5.2 完全一致 |
| R7 不悄悄改系统设置 | **没有**新增任何配置项；面板比例只存在**浏览器 localStorage** 里 |
| R8–R9 | 与 v2.1.0 一致 |

⚠️ 特别说明两条容易紧张的：

- **「无极调节」不是新增一条告警通道** —— 档位只改变
  **同一批事件怎么显示**，L1 / L2 / L3 的判定、阈值、口径**一字未动**；
- **「路径校验」不读文件内容** —— 只问「这个路径在不在、是不是文件」，
  **不打开、不解析、不上传**，比任何「先读一遍再说」的做法都克制。

## 2. 任务一：空态路径与报错校验

### 2.1 原来的空态为什么是假的

雷达空态此前会直接给出一条**绝对路径**，读起来像是「文件已经在那儿了」。
但那个文件**只有在你自己先跑过那条命令之后才会存在**。
用户照抄 → 接入 → 后端发现文件不在 → 400 → 前端红一片。

**问题不在于报错，在于它假装文件已经就绪。**

### 2.2 现在的双分支

`src/gui/static/dashboard.js` 新增 `radarEmptyCommand(exists, path)`：

| 文件状态 | 给出的路径 | 提示语 |
| --- | --- | --- |
| **存在** | 已验证的**绝对路径** | 原提示（可直接接入） |
| **不存在** | **相对路径** `logs/capture.jsonl` | 「请先运行该命令，生成文件后再点击接入。」 |

存在与否由后端 `_agent_activity()` 下发的 `capture_exists` 决定 ——
**前端不猜、不试、不假装**。

### 2.3 手动接入先问后端

`src/gui/server.py` 新增：

```
GET /api/path_exists?path=<待接入路径>
→ {"ok": true, "path": "<abspath>", "exists": true|false, "is_file": true|false}
```

前端 `verifyPathThenAttach()` 的流程：

1. 用户在输入框敲路径 → 点【接入】；
2. 前端 **先** `GET /api/path_exists`；
3. 文件不存在 → **不发接入请求**，直接在输入框下方飘红字
   **「文件不存在，请检查路径或重新生成」**（`.attach__error` + 淡入动画）；
4. 文件存在 → 才真正提交接入。

三条边界：

- ⚠️ **只作用于手动输入框** —— 雷达条目的路径按定义已存在，不额外往返；
- ⚠️ **校验接口异常不阻断** —— 接口挂了退回直接接入，
  **绝不让用户卡死在弹窗里**；
- ⚠️ **校验只判断「在不在 / 是不是文件」** —— 后端**不读内容**。

## 3. 任务二：被监控日志的无极调节渲染

### 3.1 三档语义

顶部一根 `#log-scale`（`min=0 max=100 step=1`，默认 50），行为分三段：

| 档位 | 名称 | 呈现 |
| --- | --- | --- |
| 0 – 30 | 纯代码 | **原始 JSON** 格式化展示 + 五色语法高亮 |
| 30 – 70 | 自然语言 | 🧑 **用户提问** / 🤖 **Agent 回答** / 💭 **思考**（灰色斜体）；**自动藏掉 `arguments` 与 `tool_result`** |
| 70 – 100 | 高度摘要 | 只保留**问题 + 回答 + 核心工具调用**，**忽略全部思考过程** |

边界是**包含左端**的：`value <= 30` 走纯代码，`value <= 70` 走自然语言。
`logScaleLabel()` 同步把档位名显示在滑条右侧。

### 3.2 覆盖 9 种真实日志形态

`parseLogEntry(text)` 认得下面这些**真实出现在机器上的**形态
（不是编的样例）：

| 来源 | 形态 | 判定 |
| --- | --- | --- |
| mcode 续接 | `{"message":{"role":"compactionSummary","summary":"## Goal…"}}` | context |
| mcode 新会话 | `{"message":{"role":"user","content":[{"type":"text","text":"…"}]}}` | user |
| codex | `{"type":"response_item","payload":{"type":"message","role":"user","content":[{"type":"input_text","text":"…"}]}}` | user |
| claude | `{"type":"user","message":{"role":"user","content":"…"}}` | user |
| v0.6 | `{"type":"item.completed","item":{"type":"user_message","content":[{"type":"text","text":"…"}]}}` | user |
| 扁平 | `{"type":"user_message","content":"…"}` | user |
| 通用 | `{"type":"thinking","text":"…"}` | thinking |
| 通用 | `{"type":"text","text":"…"}` | reply |
| 通用 | `{"type":"tool_call",…}` / `{"type":"tool_result",…}` | tool |

### 3.3 ⚠️ 噪声按「段落挖除」，不整行丢

系统噪声（`<system-reminder>`、`<environment_context>`、
`<skills_instructions>`、`<background-task-finished>`、
`<agent-context>`、`<cwd>`、`session_identity_reminder` 等）
在**同一条消息内部**。

codex 的形态尤其明显：**真实提问和 `<environment_context>` 常常在同一条里**。
所以 `stripNoiseSections(text)` 做的是**按段落挖除**，
不是「这条有噪声就整条扔掉」—— 整条扔会**连用户的问题一起丢**。

⚠️ **后端也挖同一批标签，而且顺序是「先挖、再截断」** ——
这是实机演示抓出来的**第二个真 bug**：

流水区的气泡正文来自后端 `extract_snippet()`，而它只留 **40 字**。
原来的顺序是「先截 40 字、再由前端挖噪声」——
可 40 字一刀下去，`</environment_context>` 这个**闭合标签先被切没了**，
前端再挖就只剩个光秃秃的 `<cwd>` 开标签。

结果就是：气泡里显示的既不是用户问的，也不是完整的框架提示，
而是半截 `<cwd>D:\项目\…` —— **两头不靠**。

现在 `src/core/live_audit.py` 的 `extract_snippet()` 改成
**先 `_strip_noise_sections()` 挖掉噪声段、再截断**，
真实提问（哪怕正文本身有 100 字）也**完整留下**。

⚠️ 两边的噪声标签清单**必须一致** ——
前端 `LOG_NOISE_TAGS` 与后端 `_NOISE_TAGS` 有一条 pytest 断言
直接比对两个集合（不一致就会红），避免出现
「日志面板干净、流水气泡全是标签」的分裂。

### 3.4 ⚠️ 调节不闪的关键：缓存重绘

朴素的实现是「切档位就重新拉后端」，那会**清空整屏**、丢掉阅读位置。

现在的做法：

1. 追加日志时，**原始行同时存进 `state.logRaw`** 缓存；
2. 档位变化 → `redrawLogLines()` **只从缓存重绘**，
   **不重新拉后端、不清空逐条追加**；
3. 用 `DocumentFragment` **一次性替换**整块日志，替换前后**保留 `scrollTop`**；
4. `logContentUnchanged()` 改成**比对 `state.logRaw` 末元素**，
   不再查 DOM —— 否则每 15 秒轮询都会重画，冲掉读者的位置。

摘要模式**保留原始行号**（raw 索引 +1），不会让行号「跳号」。

### 3.5 高亮不用 innerHTML

`logJsonTokens(text)` 用正则把 JSON 切成一串 token，
`renderLogJson()` 用 `createTextNode` / `createElement` 拼 DOM。

- **不引第三方库**（保持零新增依赖）；
- **不用 innerHTML** —— 被监控日志是**外部内容**，
  一旦里面带 `<script>` 就是注入面。用文本节点拼装就没有这个面。

## 4. 任务三：多面板自由拖拽与折叠

### 4.1 布局从固定 Grid 变成变量驱动

`.body` 从固定三列改成五列：

```css
grid-template-columns:
  var(--sessions-w) var(--resizer-w)
  minmax(0, 1fr)
  var(--resizer-w) var(--stream-w);
```

- `--sessions-w` —— 左侧会话栏宽度；
- `--stream-w` —— 右侧被监控日志宽度；
- `--audit-h` —— 中间「实时审核流水」高度；
- `--resizer-w` —— 分隔条自身占位宽度。

**JS 只改变量，CSS 只读变量** —— 这样窄屏断点、折叠态都能自然接管。

### 4.2 三条真 DOM 分隔条

`role="separator"` 的真元素（**不是伪元素** —— 伪元素拿不到指针事件）：

| 元素 | 位置 | 作用 |
| --- | --- | --- |
| `#resizer-sessions` | 会话栏右侧 | 左右拖 → 改会话栏宽度 |
| `#resizer-stream` | 日志面板左侧 | 左右拖 → 改日志宽度 |
| `#resizer-audit` | 告警与流水之间 | 上下拖 → 改流水高度 |

拖拽用 `pointerdown` / `pointermove` / `pointerup` 三段式，
移动过程中用 `requestAnimationFrame` 节流。

### 4.3 左侧会话栏可折叠成窄条

点会话栏标题栏的 `#sessions-collapse`（文字「⟨」，带 `aria-expanded`）：

- 折叠 → 容器加 `.is-sessions-collapsed` → `--sessions-w` 变成 **46px**，
  面板主体隐藏，**只剩一条窄边条**；
- 窄条上显示**会话数量图标**（`#sessions-rail-count`）与 ☰ 展开按钮；
- 再点窄条 → 展开回原宽度。

⚠️ **折叠时故意不写内联 `--sessions-w`** ——
内联样式的优先级高于样式表，会把 46px 顶掉。
折叠态完全交给 CSS 类控制。

⚠️⚠️ **折叠时左分隔条只能 `visibility: hidden`，不能 `display: none`** ——
这是实机演示抓出来的**第一个真 bug**。

`display: none` 会让 `#resizer-sessions` **退出网格流**，
而 `.body` 是五列网格、**子元素靠自动补位**：
摘掉第 2 格之后，后面的三格全部往前挪一格 ——

| 元素 | 本该在 | 实际落到了 |
| --- | --- | --- |
| `.panel--alerts`（实时告警） | 第 3 列（1fr） | 第 2 列（**8px**，分隔条那列） |
| `#resizer-stream` | 第 4 列（8px） | 第 3 列（**1fr 整列**） |
| `.panel--stream`（被监控日志） | 第 5 列 | 第 4 列（**8px**） |

结果就是：**收起源话栏之后，整页只剩一条空窄条** ——
告警面板和日志面板都被压成 8px 宽，中间那条分隔条反倒霸占了整列。

改成 `visibility: hidden` 之后，它**保留网格占位**，
列宽不变、其它面板纹丝不动，窄屏（单列）那侧不受影响。

⚠️ 这个 bug 是**演示脚本截图复查**发现的 ——
断言当时只量了「窄条宽度 46px」，没量别的面板。
现在演示脚本加了「折叠后告警面板还在」「折叠后日志面板还在」
两条断言，pytest 也钉了「折叠规则里不许出现 `display: none`」。

### 4.4 布局持久化

- 键 `sentinel.layout.v1` 存会话栏宽度、日志宽度、流水高度、折叠态；
- 键 `sentinel.logScale.v1` 存日志档位；
- 页面加载时 `loadLayoutState()` 读回来 → **刷新后保持上次的布局**；
- 数值都是 px，写坏/读失败 → **回落到默认值**，不崩。

### 4.5 窄屏

≤980px 时**隐藏分隔条**（拖拽在小屏没意义），
`.body` 改成单列 `minmax(0, 1fr)` 上下堆叠，
移动端继续用原有 760px 断点布局。

⚠️ 窄屏是**单列**网格，所以那里 `display: none` 摘掉分隔条
**不会**造成宽屏那种错位（单列只有一列，摘掉一个只是往上挪一格）——
两条规则的差别正是因为网格列数不同。

## 5. 任务四：流水区的问答高亮

### 5.1 前端拿不到用户原话，所以后端得先补

`src/core/live_audit.py` 的 `extract_snippet()` 此前只处理
`thinking` 与 `text` 两种事件 —— **`user_message` 没有分支**，
于是「用户问了什么」在流水里**根本没被带出来**。

现在补上 `user_message`，与 `thinking` / `text` 一样取 `event["text"]`，
并按 §3.3 的说法**先挖噪声段、再截断**。

### 5.2 判定与呈现分开做

- 新增 `auditEntryKind()` —— 判定该条流水是不是**核心上下文**
  （`user_message` / `text`）；
- `auditSentence()` 的**返回结构一个字都没改** —— v3.5.1 的前端夹具
  逐字 JSON 比对，**改结构就会红**；
- 样式上用**边框 + 底色**（`.live-audit__line--user` / `--reply`），
  **不抢文字颜色** —— 告警区已经占用了绿/橘黄/红三种语义色，
  再改文字颜色就乱套了。

呈现效果：

| 类型 | 样式类 | 视觉 |
| --- | --- | --- |
| 用户提问 | `--user` | 左侧实线边框 + 浅底色 |
| Agent 回答 | `--reply` | 右侧虚线边框 + 浅底色 |
| 其它 | — | 保持原来的普通行样式 |

⚠️ 流水气泡里的正文**也挖噪声段** ——
不然「核心上下文」气泡里塞的全是 `<environment_context>` 的原始标签。

## 9. 已知边界（说清楚，别假装没有）

- **档位滑条只影响「被监控日志」这一个面板** ——
  「实时审核流水」是**另一份数据**（告警引擎推过来的摘要），
  不受档位控制；
- **解析器认的是已知形态** —— 换了日志格式（比如换了个 Agent 客户端）
  可能认不出来；此时**退回原始 JSON 纯代码档**，
  **不会崩、不会空白**，但也**不会自动识别**；
- **摘要模式按「类型」过滤，不做语义摘要** ——
  「核心工具调用」指的是 `tool_call` 类事件，
  **不是** LLM 总结出来的「哪句工具调用最关键」；
- **布局存在浏览器本地** —— 换浏览器/清缓存就没了，
  **这是刻意的**：面板比例是个人阅读偏好，不该进配置文件；
- **窄屏下没有分隔条** —— ≤980px 时拖拽被禁用，
  这是为了避免小屏上误触；
- **未实机验证的能力不写在文档里** ——
  这一版声称的每一项能力都有对应的断言或截图，
  **没有**「据说支持」这种话。
