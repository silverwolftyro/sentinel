# v5.0.1 — 强制单例锁下沉与「两个同名进程」归因

> **一句话**：把进程级单例锁**下沉到无头内核的最早期入口**，
> 并查明「任务管理器里两个同名进程」其实是
> **一个引导器 + 一个核心进程**（一个实例，不是双开）。

日期：2026-11-03
上一版：v5.0.0（无头守护进程、会话级隔离与轻量集成）

---

## 1. 问题现象

打包出来的 `sentinel-daemon.exe` 双击运行后，任务管理器里出现
**两个同名进程**（PID 27280、14532）。怀疑 v5.0.0 的重构把单例锁
逻辑绕过去了。

---

## 2. 根因分析

### 2.1 「两个同名进程」不是双开 —— 是 PyInstaller 单文件的父子结构

`--onefile` 模式下，exe 双击之后是**两个进程**：

```
资源管理器 ──► 引导器（bootloader）──► 核心进程（真正的 Python）
                 ├─ 解压到 %TEMP%\_MEIxxxxxx
                 ├─ 等子进程退出，然后自己退出
                 └─ ⚠️ 它不跑任何 Python 代码
```

**引导器根本不执行 Python 代码**，所以它**永远不会**碰到单例锁 ——
锁天然就落在**真正的核心执行进程**上。

判据不靠环境变量，靠**父子关系**（跟 PyInstaller 版本无关）：

* 核心进程的**父进程也是** `sentinel-daemon.exe`；
* 引导器的**父进程不是**（它是资源管理器拉起来的）。

> 实测（v5.0.1 打包产物）：
> `PID 29804`（父 `39888`）= 核心进程；`PID 39888`（父 `37636`）= 引导器。
> **一个实例，两个进程 —— 符合预期。**

### 2.2 真正的 bug：第二个实例会**弹 10 秒模态框**才退出

v3.8.0 留下的 `report_already_running()` 会调
`show_already_running_dialog()` → `MessageBoxTimeoutW`，
**默认超时 10 秒**。

于是「连点 5 次」的现场是：

* 第 1 个：抢到锁，正常跑；
* 第 2—5 个：打印提示后**卡在模态框里最多 10 秒**才退出。

**任务管理器里于是出现 4—5 个同名进程** —— 看起来就是双开。
这才是用户看到的「两个同名进程」的来源。

而且这段文案在 v5.0.0 之后已经是**错的**：

> 请到系统托盘（右下角）找到哨兵图标，右键 →【彻底退出】，

**v5.0.0 把前端整体剥离了，哨兵压根没有托盘图标** ——
用户被指引去找一个不存在的东西。

### 2.3 第三个洞：守护进程的绝对入口**没有锁**

`src/daemon/server.py:main()` 是无头守护进程的入口，
**它自己完全不拿单例锁** —— 只靠 `sentinel_entry._dispatch()` 那一层兜。
任何绕过统一入口的调用路径（`python -m src.daemon.server`、
将来新增的入口）都会变成**不限实例**。

### 2.4 排除掉的假设

| 假设 | 结论 |
|---|---|
| `src.gui` 被 `--exclude-module` 排除，冻结版里锁模块没打进去 | ❌ 不成立 —— 排除表里只有 fastapi / uvicorn / jinja2 / pystray / PIL / PyQt 等第三方库，**没有 `src.gui`** |
| 冻结版 import `src.gui.single_instance` 失败被 `try/except` 吞掉 | ❌ 不成立 —— PyInstaller 静态分析会跟进 `try` 块里的 import，模块在包里 |
| 互斥体命名空间问题（`Global\` 前缀） | ❌ 不成立 —— 无前缀落在**当前会话**命名空间，双击是同一会话，够用 |

## 3. 改动清单

### 3.1 新增 `src/core/singleton.py`（内核层，零依赖）

把单例锁从 `src/gui/`（GUI 包）搬到 `src/core/`（内核层）——
v5.0.0 之后哨兵是无头守护进程，**核心逻辑不该依赖 GUI 包**。

只 import 标准库（`ctypes` / `os` / `sys` / `tempfile` / `logging`），
**不 import 任何 `src.*` 子模块** —— 这是它能被放在**入口最早期**的前提。

| 能力 | 说明 |
|---|---|
| Windows 命名互斥体 | `CreateMutexW` + `ERROR_ALREADY_EXISTS`（183）判定 |
| 其它平台 | `fcntl.flock` 文件锁 |
| 进程内幂等 | 同进程重复调用拿到**同一个**对象（入口两处上锁不会自锁） |
| **旧版本互斥体探测** | 老哨兵还在跑时，新版本同样拒绝启动（平滑升级） |
| **核心进程判定** | `core_process_info()` 给出可核对的依据，不靠假设 |
| **无弹窗提示** | 只写终端，打印完立刻退出 |

**核心进程判定**用了三个独立信号：

1. `PYINSTALLER_RESET_ENVIRONMENT=1` → 单文件子进程（父进程给子进程打的标记）；
2. Toolhelp32 快照比对**父进程 exe 名**与自己 → 父进程是同名引导器；
3. `SENTINEL_SINGLE_INSTANCE_ROLE=bootstrap|core` 环境变量
   → 万一将来某个打包方式真的在父进程里跑 Python，**不用改代码**就能把锁只绑在核心进程上。

### 3.2 新增 `_构建与发布/scripts/daemon_bootstrap.py`（最早期入口）

刻意做到**极小**，只做三件事：

1. 把 `sys.path` 摆好；
2. **抢进程级单例锁**；
3. 抢到了才 `import sentinel_entry`。

这样锁落在**任何大模块被加载、任何线程被创建之前**。
（v5.0.0 之前入口是 55 KB 的 `sentinel_entry`，模块级 import 了一堆东西，
锁是在它**内部**抢的 —— 大模块早加载完了。）

`--help` / `--version` / `--scan` **不上锁** —— 与 `sentinel_entry._dispatch`
保持一致：打包脚本的自检就是「再跑一次 `sentinel-daemon.exe --help`」，
它必须**永远**能跑通。

### 3.3 锁下沉到 `src/daemon/server.py:main()`

守护进程的绝对入口**自己也拿锁** —— 不再只靠统一入口那一层。
打包版走到这里时拿到的必然是**同一把**（进程内幂等），不会自锁。

### 3.4 提示行为修正

| 改动 | 之前 | 之后 |
|---|---|---|
| 弹窗 | 默认弹 `MessageBoxTimeoutW`（挂 10 秒） | **默认不弹**（`SENTINEL_SINGLE_INSTANCE_DIALOG=1` 可显式打开） |
| 文案 | 「请到系统托盘（右下角）找到哨兵图标，右键 →【彻底退出】」 | 「请先**彻底退出**已经在跑的那一个（关掉它的命令行窗口，或用任务管理器结束它的进程）」 |
| 退出码 | 3（GUI/接管模式沿用） | **0**（守护进程：「已经有实例在跑」是**成功的空操作**） |

> 退出码 0 只用于**无头守护进程**这条路径；
> 接管模式（launcher）仍用 3 —— v3.8.0 起就有这个约定，
> `tests/test_v380_single_instance.py` 也钉住了它。

### 3.5 `src/gui/single_instance.py` 改为**转手**

保留全部公开 API（`SingleInstance` / `acquire_single_instance` /
`release_single_instance` / `ProcessGroup` / `install_process_group` /
`show_already_running_dialog` / `report_already_running`），
但**锁的实现**委派给 `src.core.singleton`。

⚠️ **必须共用同一个缓存** —— 入口会在「最早期引导」与「正式入口」两处上锁，
它们在同一个进程里，各自一份缓存会**自己把自己拦下来**。

### 3.6 `build_exe.py`

* `ENTRY_SCRIPT` → `daemon_bootstrap.py`；
* `HIDDEN_IMPORTS` 增加 `src.core.singleton`
  （漏掉的代价：打包版 exe 能被无限双开，而且**不会报错**）。

## 6. 已知边界

1. **任务管理器里仍然是两个同名进程** —— 这是 PyInstaller 单文件的固有结构，
   **不是 bug**。要彻底消掉只能改用 `--onedir` 模式（会多出一堆文件），
   本版不做这个取舍。
2. **互斥体是会话级的**（无 `Global\` 前缀）—— 不同 Windows 会话可以各跑一个。
   对「一个用户一台机器只跑一个哨兵」够用。
3. **锁建不出来时放行**（`mode="unavailable"`）—— 宁可双开，也别让哨兵永远起不来。
   这条沿用 v3.8.0 的取舍。
4. **本版没有解决**：`config/config.example.yaml` 里仍保留全局 `task_goal` 兜底项
   （`src/core/engine.py:4499`、`src/core/session_server.py:3864` 仍会读它）。
