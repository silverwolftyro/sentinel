# v0.1.0 —— 项目初始化

> 版本：v0.1.0 · 日期：2026-10-26 · 类型：工程骨架与文档规范
> 本版本**不包含任何可运行的哨兵功能**，只建立结构、约定与红线。

---

## 1. 本次迭代目标

哨兵（Sentinel）是一个面向外部 AI CLI Agent 的 **自动审计员**：读取 Agent 的流式日志，
用规则与本地模型双层审查，异常时告警。迭代的第一步不是写功能，而是**把工程结构与文档
规范定死**——否则随着适配器、规则、模型的增多，文件会迅速失控。

本次迭代要达成的目标：

1. **建立标准目录结构**，让每个模块有唯一明确的归属位置；
2. **建立文档规范**，架构、API、贡献指南、版本记录各归其位；
3. **建立版本控制规则**，语义化版本 + `CHANGELOG.md` + `docs/versions/` 三处一致；
4. **确立只读红线**，把「哨兵不修改被监控 Agent 代码」写进架构文档，
   让后续实现者一开始就知道边界在哪。

### 1.1 非目标（本次明确不做）

- ❌ 不实现任何 adapter / 规则 / 模型调用逻辑
- ❌ 不实现可运行的入口与 CLI 参数
- ❌ 不做 CI/CD 配置与容器化
- ❌ 不引入重量级依赖（ORM、消息队列、Agent 框架等）

## 2. 目录结构说明

```
哨兵审核自动化/
├── src/                          # 核心源码
│   ├── core/                     # 主流程控制逻辑
│   │                             #   · 事件循环、组件装配与生命周期
│   │                             #   · 配置文件加载与校验
│   │                             #   · 分层调度与背压
│   ├── adapters/                 # 各种 CLI 工具的流解析适配器
│   │                             #   · 各家 JSONL / stdout 格式 → 统一事件
│   │                             #   · Claude Code / Codex / Aider ...
│   ├── rules/                    # L1 基础规则检测逻辑
│   │                             #   · 确定性检测：正则、关键字、阈值、频次
│   │                             #   · 输出命中详情与证据片段
│   └── llm/                      # 本地大模型（Ollama）交互逻辑
│                                 #   · 连接管理、prompt 构造、输入脱敏
│                                 #   · 输出解析为结构化裁决、超时降级
├── config/                       # 配置文件夹
│   └── config.yaml               # 主配置（占位，已在 .gitignore 中忽略）
├── docs/                         # 文档管理区（禁止根目录堆 .md）
│   ├── ARCHITECTURE.md           # 四层架构与模块职责边界
│   ├── CONTRIBUTING.md           # 代码/提交/版本规范
│   └── versions/                 # 各版本的设计与变更记录
│       └── v0.1.0-init.md        # 本文档
├── tests/                        # 测试代码
├── logs/                         # 运行时日志及截获的 JSONL 落盘目录（已忽略）
├── scripts/                      # 辅助启动脚本
├── README.md                     # 项目定位与快速开始
├── CHANGELOG.md                  # 迭代记录（版本号唯一事实来源）
├── requirements.txt              # requests / pyyaml / watchdog
└── .gitignore                    # Python 缓存、.env、/logs/*、/config/config.yaml
```

### 2.1 各目录职责一览

| 目录 | 职责 | 边界约束 |
| --- | --- | --- |
| `src/core/` | 主流程控制：事件循环、组件装配、配置加载、分层调度 | 不写具体规则与模型调用细节 |
| `src/adapters/` | 各 CLI 工具流式日志的解析适配器 | 只读解析，不做内容判断 |
| `src/rules/` | L1 确定性规则检测 | 不允许调模型或发网络请求 |
| `src/llm/` | 本地 Ollama 交互、prompt、脱敏、裁决解析 | 只接收传入片段，不读敏感文件 |
| `config/` | 主配置与本地覆盖 | `config.yaml` 不入库，模板另建 `config.example.yaml` |
| `docs/` | 全部项目文档 | 根目录只允许 README / CHANGELOG 等标准文件 |
| `docs/versions/` | 每个版本一份设计与变更记录 | 文件名 `vX.Y.Z-<标识>.md`，与标签一致 |
| `tests/` | 单元与集成测试，结构镜像 `src/` | 不访问真实网络 |
| `logs/` | 哨兵自身日志 + 截获的 JSONL 落盘 | 整体忽略，不入库 |
| `scripts/` | 辅助启动脚本 | 不放业务逻辑 |

## 3. 本次确立的关键约定

### 3.1 版本号规则

严格遵循 [语义化版本](https://semver.org/lang/zh-CN/)。当前为 `v0.1.0`。
每次迭代必须递增版本号，并在 `CHANGELOG.md` 记录、在 `docs/versions/` 补文档、
打同名 Git 标签 —— 三处版本号必须完全一致。详见
[`docs/CONTRIBUTING.md`](../CONTRIBUTING.md) 第 4 节。

### 3.2 文档规范

所有项目文档统一放在 `docs/` 下；根目录只允许 `README.md`、`CHANGELOG.md`、
`requirements.txt`、`.gitignore` 及标准工程文件。

### 3.3 只读红线

哨兵以**外部观察者**姿态工作：

- 只以只读方式打开被监控日志，不写入、不截断、不删除；
- 不修改被监控 Agent 的源码、配置、prompt 或运行环境；
- 不向被监控进程注入代码、不 hook 运行时；
- 审查侧异常一律降级继续，绝不影响被监控 Agent 的正常运行。

「中断」指**发出中断信号**（告警 / 通知 / 写入中断请求），默认模式 `advisory` 下不终止任何进程。

### 3.4 四层架构

采集层 → 规则层(L1) → 本地模型层(L2) → 告警干预层，单向依赖、事件驱动、可插拔。
详见 [`docs/ARCHITECTURE.md`](../ARCHITECTURE.md)。
