# v3.5.2 —— 流水与告警彻底分离 · 任务锚点自动拔取

> v3.5.1 的日志跟随与自然语言流水都很好，但中间面板出了**灾难级**的问题：
>
> 1. 实时审核流水被做成了 `position: absolute` 的**背景层**，
>    告警卡片靠 `z-index: 2` 压在上面 ——
>    **文字全部叠在一起，完全没法看**；
> 2. 上一轮遗留的「雷达挂载会话提不出初始 Prompt」也一直没修。
>
> 这一版把两件事都钉住：
>
> - **任务一：中间面板彻底改成 Flex 纵向布局** ——
>   实时告警在上（`flex: 1` + 自己滚），实时审核流水在下
>   （`flex-shrink: 0` + 定高 200px / 30vh + 自己滚），
>   **绝对定位与 z-index 穿透全部清除**；
> - **任务二：任务锚点自动拔取** ——
>   雷达扫描日志时读**前 10 行**，找第一条真正的用户消息；
>   mcode 这类命令行里带 Prompt 的，再从进程 `cmdline` 里取；
>   **所有手段都失败**才保留「请手动输入」；
> - **任务三：测试与发布 v3.5.2** —— 截图取证、打包 exe、Git 标签。
>
> ⚠️ **红线一字未改** —— R1–R9 与 v2.1.0 **完全一致**。
> 退出时依然**只结束哨兵自己拉起的子进程**；
> 雷达挂载进来的用户进程**绝不**去杀（R6）。
> ⚠️ **引擎判定一字未改** —— L1 / L2 / L3 的规则、阈值、告警口径
> 与 v3.5.1 **完全一致**；这一版只改「呈现」与「锚点从哪来」。

## 2. 任务一：中间面板改 Flex 纵向布局

### 2.1 重叠的根因

v3.3.1 引入「实时审核流水」时，用的是这个办法：

```text
.panel--alerts        position: relative;
  .live-audit         position: absolute;  ← 流水做成背景层，铺满整个面板
  .alert-card         z-index: 2;          ← 告警卡片压在上面
```

流水与卡片**共用同一块视觉空间**，于是字叠字。

当时为了让卡片能"透出"底下的流水，
还留了一条 `padding-bottom: 182px` 让位 —— 那条内边距本身就是这个设计的**证据**。

### 2.2 新布局

```css
.panel--alerts {
  display: flex;
  flex-direction: column;
  min-height: 0;                 /* ← 允许子项收缩，别被内容撑破 */
}

.panel--alerts .panel__body {
  flex: 1 1 auto;                 /* ← 上半：吃掉剩余高度 */
  min-height: 0;
  overflow-y: auto;               /* ← 自己滚 */
  padding-bottom: 12px;           /* ← 182px 让位内边距已删除 */
}

.live-audit {
  position: static;               /* ← 不再是背景层 */
  flex: 0 0 auto;                 /* ← 不被压缩 */
  height: 200px;
  max-height: 30vh;
  overflow: hidden;               /* ← 外层不滚，内层滚 */
}

.live-audit__lines {
  flex: 1;
  min-height: 0;
  overflow-y: auto;               /* ← 内部自带滚动 */
}
```

DOM 结构**一个标签都没动**：

```text
.panel--alerts
  ├─ .panel__head      面板标题
  ├─ .panel__body      实时告警（flex: 1，自己滚）
  └─ .live-audit       实时审核流水（定高，自己滚）
```

### 2.3 z-index 复查

中间面板内**一个 z-index 都不剩**：

| 元素 | v3.5.1 | v3.5.2 |
| --- | --- | --- |
| `.live-audit` | `position: absolute` | `position: static` |
| `.live-audit__head` | `position: relative; z-index: 3` | **两者都删掉** |
| `.alert-card` | `z-index: 2` | **删掉** |
| `.panel--alerts` | `position: relative` | **删掉** |

⚠️ `.alert-card` 的 `position: relative` **保留** ——
它不是用来压谁的，是给左侧的 `::before` 色条做定位基准。

### 2.4 窄屏

760px 断点下面板最小高度只有 260px，流水区再占 200px 就把告警区挤没了：

```css
@media (max-width: 760px) {
  .live-audit {
    height: 140px;
    max-height: 22vh;
  }
}
```

## 3. 任务二：任务锚点自动拔取

### 3.1 为什么需要它

旁路挂载进来的会话，哨兵是从文件**尾部**开始跟随的 ——
用户那句「我要重构 auth 模块」很可能**根本不在**你看到的这段日志里。

没有锚点 → 没有意图滑窗 → **没有意图漂移（DRIFT）监控**。
v2.4.0 只能让用户**手动输入**任务目标，
而「你得先知道自己当初想干什么」本身就是一道坎。

### 3.2 三级回退

[`src/radar.py`](../../../src/radar.py) 新增：

| 函数 | 职责 |
| --- | --- |
| `extract_task_goal(path, *, agent="", max_lines=10)` | 读日志**前 10 行**，找第一条真正的用户消息 |
| `extract_task_goal_from_cmdline(args)` | 从进程命令行里取 Prompt |
| `build_prompt_index(*, extra_features=None)` | `psutil` 枚举 Agent 进程 → `{归一化cwd: prompt}` |
| `resolve_task_goal(path, *, agent="", cwd="", prompt_index=None)` | **日志头部 → 命令行 → 空串** 三级回退 |

顺序不能换：**日志头部最可靠**（用户真的说过那句话），
命令行只是「一次性启动」时的第二条路。

### 3.3 支持的日志形态

代码**直接解析 JSON**，绕过适配器的归一化 ——
这是 v3.5.1 遗留问题的根因（见 §3.6）。

| 形态 | 实际结构（实测） |
| --- | --- |
| mcode 续接 | `{"message":{"role":"compactionSummary","summary":"## Goal\n\n…\n\n## Constraints…"}}` |
| mcode 新会话 | `{"message":{"role":"user","content":[{"type":"text","text":"…"}]}}` |
| codex | `{"type":"response_item","payload":{"type":"message","role":"user","content":[{"type":"input_text","text":"…"}]}}` |
| claude | `{"type":"user","message":{"role":"user","content":"…"}}` |
| v0.6 | `{"type":"item.completed","item":{"type":"user_message","content":[{"type":"text","text":"…"}]}}` |
| 扁平 | `{"type":"user_message","content":"…"}` |

查找是**递归**的（深度上限 6），所以不写死路径 ——
codex 在 `payload` 里、mcode 在 `message` 里、v0.6 在 `item` 里，都能命中。

⚠️ **mcode 续接会话优先取 `## Goal` 段** ——
`compactionSummary.summary` 里就是压缩时保留下来的任务目标，
比正文更准。取法是：从 `## Goal` 取到下一个 `##` 为止。

### 3.4 ⚠️ 铁律：宁可找不到，也不能找错

系统噪声**绝不能**当成任务目标：

| 噪声 | 为什么危险 |
| --- | --- |
| `<system-reminder>` | 会把「YOUR SESSION ID: …」当成任务 |
| `<environment_context>` | codex 的第 3 行就是它 —— 提早了后面全是假锚点 |
| `<background-task-finished>` | 后台任务的结束通知 |
| `<agent-context>` / `<skills_instructions>` | 系统装配说明 |
| `session_identity_reminder` | mcode 的会话身份提醒 |

做法是**两段式**：

1. 先剥开头的噪声块（没有闭合标签就**整段丢弃**，
   避免半截标签把后面的真话也吃掉）；
2. 再把正文里**残留**的噪声块截断掉。

长度 < 4 字一律视为**没找到**（不拿「嗯」「好」当锚点）。

⚠️ **为什么这么严** ——
假锚点不会让哨兵「更聪明」，只会让意图漂移判定**整体跑偏**：
拿 `<system-reminder>` 当任务目标，后面每一句正常干活都会被判成「偏离目标」。

### 3.5 挂载流程复用同一条链

[`src/gui/server.py`](../../../src/gui/server.py) 新增：

```python
def _resolve_attached_goal(watch_path, adapter_name="mcode", cwd=""):
    """日志头部 → 命令行索引 → 旧适配器，三级回退。"""
```

挂载时**服务端自行重新推导**锚点，**不信任客户端输入** ——
客户端传来的路径由服务端自己再查一遍。

⚠️ `goal.set()` 仍然在 `goal.on_change(runner.apply_goal)` **之后**调用 ——
设定目标的同一刻，漂移监控**立即生效**（这个次序是 v2.4.0 定下的，没动）。

### 3.6 上一轮遗留问题的根因

旧 `_extract_initial_goal()` 只认 `type == "user_message"`，而适配器
`_parse_message_container()` 把真实的
`{"message": {"role": "user", "content": [...]}}`
判成了 `text` 事件 —— 于是**真实 mcode / codex 日志根本提不出锚点**。

这一版由 `radar.py` **直接解析 JSON**，不再依赖适配器的归一化结果。
旧适配器**保留**为最后一层兜底（`radar` 提不到时仍会试）。

### 8.2 ⚠️ 取证时踩到的三个**真实**坑（都绕过去了，说明一下）

1. **挂载持久化（v3.1.0）** ——
   上一轮演示挂过的会话会被**自动接回来**，
   而雷达**不列已经挂载的文件** ——
   结果雷达面板显示「发现 0 个正在写入的会话」。
   演示脚本因此在启动前清掉 `logs/v352-demo/attached_sessions.json`。
2. **雷达只列「正在写入」的会话** ——
   演示日志静静躺着就会被当成历史会话收进「显示其余」。
   脚本因此**真写**一条心跳（普通 `thinking`，**不含**用户消息，
   不影响锚点提取）让它保持活跃。
3. **告警面板只渲染「当前活动会话」的卡片** ——
   漂移告警属**挂载**会话，不切换就看不到。
   脚本因此先点会话条目切到挂载会话；拍漂移截图前还要**先关掉雷达弹窗**，
   否则 DRIFT 卡片被遮在弹窗后面，截图就证明不了「漂移监控真的开着」。

⚠️ 这三条**不是**哨兵的缺陷，是它本来就有的行为；
   这里写出来是为了让「截图为什么长这样」有据可查。

## 9. 已知边界（说清楚，别假装没有）

- ⚠️ **「前 10 行」是个经验值** ——
  它覆盖了 claude / mcode / codex / v0.6 的实测形态，
  但**不能保证**覆盖所有 Agent 的所有日志格式；
  提不到时**如实回退**，不硬猜。
- ⚠️ **锚点截断到 200 字** ——
  超长任务描述会被砍掉尾巴，这是有意的（滑窗里塞不下）；
  砍掉的是**长度**，不是**语义**。
- ⚠️ **命令行回退只对「一次性启动」有效** ——
  `--continue` 这类续接模式的命令行**没有 Prompt**，详见 §6.3。
- ⚠️ **锚点找错比找不到更糟** ——
  宁可显示「请手动输入」，也不给一个假锚点。
  噪声过滤是**硬要求**，不是可选优化。
- ⚠️ **雷达面板的锚点行只是展示** ——
  真正生效的锚点是挂载时服务端**重新推导**的那一份，
  不依赖前端回传。
- ⚠️ **挂载会话仍不继承配置里的全局目标** ——
  `inherit_config_goal=False` 是 v2.4.0 的既有决定，**本版不动**。
