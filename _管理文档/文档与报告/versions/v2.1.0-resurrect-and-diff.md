## 1. 红线修订（R6）

### 1.1 改了什么

v2.0.0 的哨兵**绝不 kill** 被监控进程。v2.1.0 要结束那个**被挂起**的进程 ——
所以这条必须**如实改写**，而不是嘴上说没变。

| 红线 | v2.0.0 | **v2.1.0** |
| --- | --- | --- |
| 终止被监控进程 | **绝不** | **绝不** —— 唯一例外：用户明确点【回滚并重试】，且只针对**哨兵自己挂起过**的 PID |

### 1.2 为什么必须终止

**放行 ≠ 复活。**

被哨兵挂起的进程，正卡在一条**危险命令**上 ——
挂起就是为了让它来不及执行那条命令。

所以「放行它」不是复活，那是**闯祸**：
刚被拦下的 `rm -rf` 一放行就跑了。

于是复活只有一条安全的路：

```
回滚  →  写留言箱  →  结束挂起进程  →  重拉 Agent
```

### 1.3 作用域收得死死的

`Guardian.terminate_suspended()` 的三重限制：

| 限制 | 落地 |
| --- | --- |
| 只认**哨兵自己挂起过**的 PID | 别的进程**连碰都不碰**（返回「不是哨兵挂起的，不去动它」） |
| 保护 PID 一律拒绝 | 0 / 1 / 哨兵自身 / 哨兵父进程 |
| 每次终止都留痕 | 写 `guardian.log` 审计记录 |

### 1.4 而且必须先看计划

复活会做三件**不可逆**的事。所以：

- `plan()` **只算不动** —— 看板先弹「将恢复 N 个、删除 M 个、
  结束挂起进程、重拉 Agent」，**用户点头才动手**；
- 权限小于用户：哨兵不能替用户决定删他的文件、杀他的进程。

## 2. 任务一：一键复活

### 2.1 编排：四步，顺序不能乱

`src/core/resurrect.py` 的 `ResurrectService`：

| 步 | 做什么 | 谁做 |
| --- | --- | --- |
| 1 | **回滚**工作目录到生效安全点 | `SafePointService.restore()` |
| 2 | **注入**纠偏提示（拦截原因 + 纠偏建议） | `AgentInjector`（**只走留言箱**） |
| 3 | **结束**挂起进程 | `Guardian.terminate_suspended()` |
| 4 | **重拉** Agent（任务提示带上纠偏提示） | `agent_control.relaunch()` |

⚠️ **先注入、再重拉** —— 重拉时任务提示才会把纠偏提示带上。

⚠️ **注入只走留言箱** —— 旧进程马上就要被结束了，
往它的 stdin 写是白写。启动器构造复活服务时刻意**不给** `stdin_writer`。

### 2.2 模块边界：鸭子类型

这一层**不认识** Agent 进程，只认识一个「鸭子类型」：

```python
state()      # → {"pid": …, "alive": …, "suspended": …}
terminate()  # → 结束挂起进程
relaunch()   # → 重新拉起一个带纠偏提示的 Agent
```

真正干活的由**启动器**实现（它手上有 `Popen`），
看板只负责调 `ResurrectService.execute()` ——
这条边界和 v2.0.0 的 `inject_callback` / `rollback_callback` 完全一致：
**GUI 应用层不认识引擎**。

### 2.3 播报的那一句

终端与看板**打印同一句**（固定常量 `RESURRECT_MESSAGE`）：

```
[SENTINEL] 已回滚至安全点，并注入纠偏提示，重新唤醒 Agent。
```

两遍说法不一致，用户会怀疑是不是同一件事。

### 2.4 并发防呆

| 场景 | 行为 |
| --- | --- |
| 同一个会话连点两次 | 第二个被挡住（`busy: true`，提示「上一个复活操作还在进行中」） |
| 多个会话同时挂起 | **各回各的，互不影响** —— 每个会话一个 `ResurrectService` 实例、一把自己的锁 |

### 2.5 启动器侧的「重拉」

`AgentSession.relaunch()` 做的是**真的**重拉：

1. `_terminate_tree(old)` —— 结束旧进程树；
2. 用**同一套参数**重新 `Popen`（`_spawn()` 是 `prepare()` 与 `relaunch()` 共用的）；
3. **代数 +1** —— stdout 读线程带上代数，
   旧进程的 EOF 尾巴**不会**把主循环带沟里；
4. 守护者 `set_target_pid()` 重新指向新进程；
5. 新进程的 stderr 也要有人读干净（不然管道塞满、子进程卡死）。

## 3. 任务二：Web Diff 预览

### 3.1 两段式：便宜地算贵的

| 阶段 | 算什么 | 成本 |
| --- | --- | --- |
| **快照时** | 「相对上一次快照，**哪些文件**变了」 | **只比清单**（路径 + 大小 + sha256），不读内容 |
| **点按钮时** | 每个文件的**行级 unified diff** | 读两边内容，按需算 |

⚠️ 为什么分两段：快照有 **3 秒时间预算**（「极速」是它的命），
在里面算行级 diff 会把快照拖慢。

但**清单必须永远完整** —— 回滚要靠它判断哪些文件是 Agent 新建的。

### 3.2 快照里多了什么

`manifest.json` 新增 `changes` 段：

```json
{
  "version": 1,
  "point": { "id": "20261027-203221-059606", "mode": "full", … },
  "files": { "src/app.py": { "size": 32, "sha256": "44e635d4…", … } },
  "changes": {
    "modified": ["src/app.py"],
    "added":    ["src/scratch.py"],
    "removed":  []
  }
}
```

### 3.3 弹窗长什么样

实测截图（`assets/dashboard-v2.1.0-diff.png`）：

```
Agent 到底改了什么
────────────────────────────────────────────────────
对比安全点 基线安全点 · 会话起点 → 当前工作目录：修改 1 个、新增 1 个、删除 0 个

src/app.py（+2 / −2）
  --- 安全点/src/app.py
  +++ 现在/src/app.py
  @@ -1,3 +1,3 @@
   def main():
-    # 正常版本：返回 'good'
-    return 'good'
+    # Agent 改坏的版本
+    return 'broken'

+ src/scratch.py
────────────────────────────────────────────────────
                                        [ 关闭 ]
```

- **绿底** = 新增的行；
- **红底** = 删除的行；
- **蓝底** = 块头（`@@`）；
- 底下单独列出 Agent **新建**的文件。

### 3.4 二进制文件自动跳过

给二进制做行级 diff 只会得到一堆乱码，用户看了也白看 ——
所以读不出 UTF-8 / GBK 文本（含 `\x00`）的直接跳过，列进 `skipped`。

### 3.5 弹窗自己建 DOM

不用 `<dialog>` —— 老版本 Edge / WebView 上它的支持并不一致。
`openModal()` 自己建 DOM，Esc 关闭，点遮罩关闭。

## 4. 任务三：真实 Webhook 触达测试

### 4.1 两个入口

| 入口 | 什么时候 | 做什么 |
| --- | --- | --- |
| `_构建与发布/scripts/test_real_webhook.py` | 你手动跑 | 贴地址 → **真发一条** → 打印结果 |
| `src/core/webhook_probe.py` | **哨兵启动时** | 发现配了真实 Webhook → **真发一条**自检 |

### 4.2 自检消息里有什么

```
【哨兵连通性自检】
版本：v2.1.0
本机 IP：172.26.185.94、192.168.80.1、192.168.141.169
本机名：DESKTOP-PIKDTPU

如果你在手机上看到了这条消息 —— 这条链路是真通的。
把上面这几个 IP 加进机器人的白名单，以后告警就能推到了。
```

**版本号**告诉你测的是哪一版哨兵；
**IP** 告诉你该往白名单里填哪几个
（钉钉 / 飞书默认只允许内网 IP —— 这是最常见的「明明配了却收不到」）。

### 4.3 为什么值得每次启动都发一条

告警是**偶发**的 —— 等真出事才发现推不出去就太晚了。
启动时发一条，等于**每次开机自动确认一次**外网连通性、Token、加签与白名单。

嫌吵就关掉：

```yaml
alert:
  webhook_startup_test: false
```

### 4.4 错误码翻译成人话

`test_real_webhook.py` 会读响应体里的 `errcode`，逐条翻译：

| 厂商 | 错误码 | 人话 |
| --- | --- | --- |
| 钉钉 | 300001 | 关键词不匹配 —— 机器人里要加上告警里的关键词 |
| 钉钉 | 310000 | IP 不在白名单 —— 钉钉只允许内网 IP 推消息 |
| 钉钉 | 400013 | 加签不对 —— 检查 secret 是不是设成了机器人那一串 |
| 飞书 | 19021 | 签名不匹配 —— 检查 secret 与时间戳 |
| 飞书 | 19020 | 关键词不匹配 |

### 4.5 ⚠️ 还没有真的打过

**仓库里没有任何真实 Token** —— 这一版提供的是**工具**与**启动自检**，
最后那一下「真打」仍然需要用户自己的凭据。
说「已打通钉钉」是**假的**。

## 8. 实机撞出来的 2 个 bug（都已修 + 补回归）

### 8.1 ⚠️ JS 的相邻字符串字面量被 ASI 拆成两条语句

```javascript
warn.textContent =
  "⚠️ 这三步不可逆：被拦下的那条命令不会再执行，"
  "但 Agent 在那之后的改动也会一起没了。";
```

在 JavaScript 里这**语法合法** —— `node --check` **查不出来**。
但 ASI 会把第二段拆成独立的表达式语句，变成**空操作**。

表现是「复活弹窗里的警告文字**少了一半**」。

⚠️ 这是**实机截图时**撞出来的 —— 单元测试全绿，
因为它在 JS 里根本不算错误。

修法：拼成一行（或用 `+`）。另外加了一条**正则回归测试**兜住：

```python
hits = re.findall(r'"[ \t]*\r?\n[ \t]*"', js)
assert not hits
```

### 8.2 `AgentInjector.inject()` 的关键字参数被误当位置参数传

`ResurrectService` 里写成了 `injector.inject(prompt, info)`，
但 `inject()` 的签名是 `inject(prompt, *, session_id=…, verdict=…, …)` ——
`info` 被当成第二个位置参数，抛 `TypeError`。

而这个 `TypeError` 被降级逻辑**吞掉**了，
表现是「注入没生效」而**不报错** —— 最难查的那种。

测试抓到的，不是靠肉眼。

### 8.3 ⚠️ 归档时漏传 `session_id` —— 把当天的日报整个覆盖了

晨报归档脚本写成了：

```python
save_briefing(markdown, archive_dir=None)          # ← 漏了 session_id
```

`save_briefing()` 不传 `session_id` 就是**单路覆盖**模式 ——
结果 v1.2.0 那两节（`stress-a` / `stress-b`）**直接没了**，
整份日报只剩下新会话的一节。

⚠️ **库本身没问题**（`test_briefing.py` 里早有
「两路合并」「单路覆盖」两条测试）—— 是**调用方**用错了 API。

修法：

```python
save_briefing(markdown, archive_dir=None, session_id=SESSION_ID)
```

另外把标题层级也跟启动器对齐（`heading_level=2`），
不然同一个文件里会出现两套标题层级。

已加两条针对**脚本**的回归测试兜住这个用法约定。

## 9. 已知限制

- **回滚并重试不可逆** —— 执行了，那之后的改动就没了；
  所以它**必须先出计划、用户确认才动手**；
- **复活依赖启动器** —— 只有「真实管道接管」模式能重拉 Agent；
  纯看板模式点这个按钮会明确告诉你「没有配置复活功能」，
  而不是假装成功；
- **重拉的是新进程** —— 原进程里的内存状态没了
  （但工作目录已回滚，等价于「回到干净的起点重来」）；
- **目录外操作无法回滚** —— 装依赖、推远端、改全局配置没有备份；
- **Diff 只覆盖工作目录内的文件**；二进制文件不做行级 diff；
- **真实 Webhook 自检会真的发消息** —— 手机会响一声，这是有意的；
- **钉钉 / 飞书的真实服务** —— 提供了**真打**的工具与启动自检，
  但仓库里**没有任何真实 Token**，最后一步仍需用户自己的凭据；
- **Claude 适配器仍未实机验证**。
