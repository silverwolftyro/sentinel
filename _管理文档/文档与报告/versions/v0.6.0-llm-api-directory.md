## 2. 目录规范重构

### 2.1 为什么改

v0.5.0 的白名单用的是纯英文目录名：

```
docs/  scripts/  archive/
```

看着整齐，实则把「这个目录归谁管」又推回给读者 ——
`archive/` 是归档还是备份？`scripts/` 是构建还是辅助？
中文名字 + 下划线前缀**自带语义**：

- **管理类**（置顶 + 下划线）—— 不是源码，是「项目自身的配套资产」；
- **工程核心**（不带下划线）—— 源码、测试、配置、运行时数据；
- **回收站** —— 临时垃圾的**指定去处**，比直接删多一次后悔的机会；
- **入口文件** —— 留在根目录，一眼能找到。

### 2.2 前后对照

| v0.5.0 | v0.6.0 | 说明 |
| --- | --- | --- |
| `docs/` | `_管理文档/文档与报告/` | 整个 `docs/` 移入 `_管理文档/` 并重命名 |
| `scripts/` | `_构建与发布/scripts/` | 构建与发布物归堆到一处 |
| `requirements.txt` | `_构建与发布/requirements.txt` | 同上 —— 它是「构建物」不是「入口文件」 |
| `archive/` | `_备份与归档/` | 归档区内容直接放入（不再套一层 `archive/`） |
| —— | `回收站/` | **新增**：临时垃圾的指定去处 |
| `src/` `tests/` `config/` `logs/` | 不变 | 工程核心，保持常规命名 |
| `README.md` `CHANGELOG.md` `.gitignore` `pytest.ini` | 不变 | 入口文件留在根目录 |

> **一处解释**：`_备份与归档/` 下**没有**再套一层 `archive/` ——
> 目录名本身已经说明「这里就是备份与归档」，再套一层英文名
> 反而违背「中文语义」这条初衷。
>
> `pytest.ini` 仍然留在根目录：pytest 只认**根目录**（rootdir）下的
> `pytest.ini`，挪走它等于让全部测试配置失效。

### 2.3 白名单（已写入 CONTRIBUTING §5.2）

```
管理类目录（置顶，带下划线）
  _管理文档/        _构建与发布/        _备份与归档/
工程核心目录（不带下划线）
  src/              tests/              config/            logs/
回收站
  回收站/
入口文件
  README.md         CHANGELOG.md        pytest.ini         .gitignore
```

### 2.4 迁移带来的连带改动

| 事项 | 处理 |
| --- | --- |
| 依赖安装命令 | `pip install -r _构建与发布/requirements.txt` |
| 脚本的项目根定位 | **不能**靠固定层数往上数（脚本下沉了一层）→ 改成**按特征找**：含 `src/core/` 的目录即为根 |

| `.gitignore` | 新增 `/回收站/*`、`/_备份与归档/*`；保留 `/logs/*`、`/config/config.yaml` |

### 2.5 链接完整性检查

目录一动，链接就容易烂掉。所以加了一道检查（扫全部 `.md` 的相对链接，
逐个验证目标是否存在）——**第一次跑就抓出 7 条坏链**，全部修掉。

## 3. 通用 LLM API 接入

### 3.1 为什么要抽象

v0.6.0 之前，L2 只有 Ollama 一种实现，调用逻辑直接写在
`ollama_client.py` 里。要接外部大模型，**照抄一份**是最省事的做法 ——
但那正是旧项目栽过的地方：降级契约、Prompt、解析阶梯、脱敏会散落成 N 份，
改一处漏一处。

所以抽成三层：

```
src/llm/base.py         LLMProvider 抽象基类
                         ├── Explanation      统一返回结构
                         ├── CircuitBreaker   统一熔断
                         └── explain()        统一流程（脱敏→Prompt→调用→解析→渲染→降级）
                            │
              ┌─────────────┴─────────────┐
              │                           │
src/llm/ollama_client.py        src/llm/api_client.py
OllamaClient(LLMProvider)       OpenAICompatibleClient(LLMProvider)
只实现 chat()                   只实现 chat()
              │                           │
              └─────────────┬─────────────┘
                            │
src/llm/factory.py         build_provider(config) 按 llm.provider 挑选
```

**子类只实现 `chat()`** —— 把一段对话变成模型输出。
其余全部由基类统一处理，所以：

- 不同提供方返回的 `Explanation` **结构完全一致**；
- 新增一个提供方**不需要**重复实现降级契约（那是全项目最重要的红线之一）。

### 3.2 统一的返回结构

```python
Explanation
  ├── text        面向人的一段话（标题 / 原因 / 影响 / 后果 拼成）
  ├── detail      结构化字段 {title, why, touch, outcome}
  ├── degraded    是否走了降级路径
  ├── reason      降级原因
  ├── latency_ms  本次调用耗时
  ├── model       使用的模型名
  └── provider    提供方标识（ollama / openai_compatible）
```

`tests/test_api_client.py::test_should_return_same_structure_as_ollama`
就是逐字段比对两个提供方的输出 —— 这条断言把「结构一致」钉死了。

### 3.3 OpenAI 兼容客户端

| 能力 | 实现 |
| --- | --- |
| 端点补全 | `https://x` → `/v1/chat/completions`；带 `/v1` → `/chat/completions`；写全 → 原样 |
| 鉴权 | `Authorization: Bearer <api_key>`；无密钥则不发该头（本地网关常见） |
| 密钥来源 | **环境变量 `SENTINEL_LLM_API_KEY` 优先** → 配置项兜底（不落盘是默认做法） |
| JSON 约束 | `response_format={"type":"json_object"}`（可关） |
| 响应解析 | 标准 `choices[0].message.content` / 推理模型 `reasoning_content` / 旧式 `choices[0].text` |
| 错误处置 | 401/403/404/429/5xx 各给一句**能指导处置**的话；连接失败、超时、非 JSON 全部降级 |

覆盖：DeepSeek、Kimi（Moonshot）、智谱、硅基流动、OpenRouter，
以及任何自建的 one-api / new-api / vLLM / LM Studio 网关。

### 3.4 ⚠️ 数据出本机

本地 Ollama 与外部 API 有**本质差异**：后者会把内容送出本机。

哨兵送进模型的是「Agent 的思考过程 + 命令原文 + 规则判定」——
这可能是最敏感的数据。所以本客户端做了三件事把风险压到最低：

1. **必须显式配置** —— 只有把 `llm.provider` 改成 `openai_compatible`
   才会走到这里，默认仍是本地 Ollama；
2. **送出前强制脱敏** —— 密钥、令牌、个人信息在**离开本机之前**就被抹掉
   （`redact_before_llm`，由基类统一执行）；
3. **密钥不落盘、不进日志** —— 优先从环境变量读；
   错误消息里的响应正文也会先脱敏（网关报错经常原样回显密钥）。

> 最后一条是**测试抓出来的真 Bug**：第一版实现把 HTTP 错误正文直接
> 塞进异常消息，而异常消息会进日志 —— 等于把密钥抄进了日志文件。
> 现在会先精确遮蔽本次使用的 api_key，再跑一遍通用密钥规则。

### 3.5 配置

```yaml
llm:
  provider: "ollama"        # ollama | openai_compatible
  base_url: "http://localhost:11434"
  model: "qwen2.5:7b"
  api_key: ""               # 推荐用环境变量 SENTINEL_LLM_API_KEY
  temperature: 0
  max_tokens: 512
  json_mode: true
  extra_headers: {}
```

`config/config.example.yaml` 里附了 DeepSeek / Kimi / 本地 vLLM 三套示例。

## 4. 本地 7B 模型适配

- `llm.model` 由 `qwen2.5-coder:14b` 改为 **`qwen2.5:7b`**（本机已装）；
- `alert.intervention_mode` 由 `advisory` 改为 **`guardian`**；
- `OllamaClient` 的默认模型名同步改为 `qwen2.5:7b`（不再假设 14B）。

### 4.1 实跑结果（真实 7B 输出，非降级）

输入的 Agent 日志刻意制造了「**说的和做的对不上**」：

> **Agent 自述**：用户让我把项目里的旧构建产物清理掉……我打算用一条命令
> 直接把它删掉。
>
> **实际命令**：`rm -rf /`

哨兵输出：

```
[CRITICAL] DANGEROUS: 红线级命中：递归删除根目录 / 家目录 / 整盘（/） | 工具=Bash | 命令=rm -rf /
  人话解释：Agent 试图删除 build 目录下的旧文件。原因：用户想清理项目里的旧构建产物。
            影响：项目根目录下的 build 目录（会删除）。后果：删除了 build 目录，节省了一些空间；
            但误删 / 目录将导致系统崩溃
  [哨兵已拦截] 发现高危操作，已暂停目标进程。输入 'override' 可放行并让哨兵在当前任务中不再拦截该规则
```

**这段解释是模型真写的**，证据在告警日志的结构化字段里：

```json
{
  "explanation": "Agent 试图删除 build 目录下的旧文件。原因：……但误删 / 目录将导致系统崩溃",
  "explanation_degraded": false,
  "severity": "red_line",
  "guardian": {
    "ok": true,
    "method": "suspend",
    "pid": 12680,
    "detail": "进程已挂起（随时可恢复）"
  }
}
```

值得注意：模型**主动写出了落差** —— title 说「删除 build 目录」（Agent 的说法），
outcome 说「但误删 / 目录将导致系统崩溃」（命令的实际行为）。
这正是 Prompt 里那条「不要替 Agent 圆场，用户正需要看见这个落差」的要求。

### 4.2 守护者实机

同一轮运行里，守护者真的挂起了目标进程：

```
2026-10-27T00:14:12  intervene  rule=catastrophic_root_delete  pid=12680  ok=1  source=engine
```

进程状态实测：`running` → `stopped`（挂起）→ `running`（退出时自动恢复，
`Guardian.close()` 的职责 —— 不能留一个僵死的进程给用户）。

## 5. 关键设计决策

| 决策 | 理由 |
| --- | --- |
| 提供方抽象放在 `base.py`，而不是各自实现一份 | 降级契约是全项目最重要的红线，不能散落成 N 份 |
| 子类只实现 `chat()` | Prompt / 脱敏 / 解析 / 渲染 / 降级全部共享，杜绝「改一处漏一处」 |
| 密钥优先读环境变量 | 不落盘是默认做法，不是可选项 |
| 外部 API 默认**不**启用 | 数据出本机必须被显式承认 |
| 未知 `llm.provider` **报错**而非静默回落 | 否则用户以为在用外部 API、其实却在本地跑 |
| 内网 IP 算「外部地址」 | 数据发到内网同样离开了本机 |
| 白名单里的 `pytest.ini` 留在根目录 | 挪走它等于让全部测试配置失效 |
| 脚本按**特征**定位项目根，不按层数 | 目录一调整就指错地方 —— v0.6.0 自己就踩了这个坑 |

## 8. 怎么用

### 本地模型（默认）

```bash
pip install -r _构建与发布/requirements.txt
ollama pull qwen2.5:7b
python -m src.core.engine path/to/agent-stream.jsonl
```

### 外部 API

```bash
# 密钥走环境变量，不落盘
export SENTINEL_LLM_API_KEY=sk-xxxx

# config/config.yaml
#   llm.provider: "openai_compatible"
#   llm.base_url:  "https://api.deepseek.com/v1"
#   llm.model:      "deepseek-chat"

python -m src.core.engine path/to/agent-stream.jsonl
```

### 守护者自检与看板出图

```bash
python _构建与发布/scripts/verify_guardian.py
python _构建与发布/scripts/capture_dashboard.py --url http://127.0.0.1:8000/ --probe
```
