# v3.3.1 —— 实时审核流水 · 无目标强引导 · 进程反查宽容度

> 这一版做四件事，全部来自**用户实测反馈**：
>
> 1. **让「它一直在看」看得见** ——
>    L1 判定为 `ON_TRACK` 的事件以前只被**计数**，从不外送，
>    用户盯着看板只看到「什么也没发生」，
>    反而以为哨兵没在工作。
>    现在每次正常判定都会在告警面板底部留下一行极简灰字；
> 2. **没目标时给出强引导** ——
>    挂载进来的会话常常没有初始 Prompt，雷达找不到初始目标。
>    顶部那一句「未设置」以前只是灰字，
>    现在它是**橘黄高亮**，旁边**常驻**一个气泡告诉你该做什么；
> 3. **把「查不到进程」这件事说清楚** ——
>    `[未绑定进程]` + 灰掉的武装开关看起来像「整个哨兵瘫了」，
>    其实只是少了一项「拦截」能力：
>    L1/L2 判定、告警落盘、通知推送**全都照常**。
>    这一版把这句话**写进界面**；
> 4. **发布 v3.3.1** —— 文档、CHANGELOG、实拍图、exe、Git 标签。
>
> ⚠️ **红线一字未改** —— R1–R9 与 v2.1.0 **完全一致**。
> 这一版只做了三件事：**多显示一行字**、**多说一句话**、
> **把已有的能力说清楚**。哨兵依然只读，不碰别人的进程。

## 1. 红线：这一版一个字都没改

| 红线 | 这一版怎么守的 |
| --- | --- |
| R1 只读监听 | 引擎只往**自己的**告警日志里**多写一行**流水；被监控的 Agent 日志**一个字节都没动** |
| R2 不干预代码 | 流水只是**摘要文本**，不含任何可执行内容 |
| R3 不注入进程 | 「未设置」高亮与气泡**只是界面**；点它做的唯一一件事是把光标送到输入框 |
| R4 本地闭环 | 摘要**在本地**由 `src/core/live_audit.py` 生成，不外发任何数据 |
| R5 旁路失败 | 摘要生成失败**一律降级**成「正常处理」；写流水失败只记日志，绝不影响审查 |
| R6 不终止进程 | 这一版**没有任何**新增的进程操作路径 |
| R7 不悄悄改系统设置 | 「未绑定进程」的解释只是**说明文字**，不写任何系统设置 |
| R8–R9 | 与 v2.1.0 一致 |

⚠️ 特别说明一条容易紧张的：

- **查不到 PID 时哨兵更不是坏了** ——
  查不到进程是**正常**的事：用户重定向了输出，
  或者用了特殊启动方式，命令行里本来就没有日志路径。
  这时候哨兵**照常**做 L1/L2 判定、照常落盘、照常推送通知，
  只是**不能挂起进程**（没有 PID 就没法挂）。
  v3.3.1 把这件事**写进界面**，免得用户看着灰掉的开关就放弃了。

## 2. 任务一：实时审核流水（Live Audit Log）

### 2.1 问题出在哪

L1 规则引擎对**每一个**事件都会给出一个判定，绝大多数是 `ON_TRACK`。
但 `ON_TRACK` 在旧版本里**只被计数**，从不外送：

```python
# src/core/engine.py（v3.3.0）
verdict = self.rule_engine.check_event(event)
name = str(verdict.get("verdict") or VERDICT_ON_TRACK)
with self._alert_lock:
    self.counts[name] = self.counts.get(name, 0) + 1     # ← 只有计数
```

于是用户的体验是：面板中间**空空如也**，
右侧日志倒是滚得欢，但「看不出流式审核的表现」——
**它确实在审，只是没告诉你**。

### 2.2 这一版怎么做的

新增叶子模块 `src/core/live_audit.py`，把一个事件压成**一行**：

```
[12:01:05] 正常读取: auth.py
[12:01:06] 正常执行: pytest
[12:01:07] 正常搜索: TODO
```

三条硬约束：

1. **不显示完整 JSON** —— 完整事件在右侧「被监控日志」里已经有了，
   这里只留**意图摘要**；
2. **摘要由后端生成** —— 前端只负责渲染。
   这样「极其精简」才有唯一的解释者，也才写得出一行断言来测；
3. **失败绝不抛异常** —— 压不出来就退回「正常处理」（R5）。

### 2.3 通道：沿用既有的「日志格式契约」

哨兵与看板是两个进程，唯一现成的通道是
**「引擎写日志 → 看板尾部器读 → SSE → 浏览器」**。
所以这一版**没有另造管道**，而是照老规矩加了一对常量：

| 谁 | 常量 | 位置 |
| --- | --- | --- |
| 引擎写 | `ONTRACK_MARKER = "ONTRACK_JSON"` | `src/core/engine.py` |
| 看板读 | `ONTRACK_MARKER = "ONTRACK_JSON"` | `src/gui/server.py` |

完整链路：

```
引擎 process_event()
    → 判定 ON_TRACK
    → self.logger.warning("ONTRACK_JSON {json}")     ← 写进哨兵自己的告警日志
        → Watcher._poll_once() 读到这个标记
            → store.add_ontrack(entry)
            → hub.publish({"type": "on_track", ...})  ← SSE
                → 前端 handleEvent() → appendLiveAudit()
                    → 面板底部多一行灰字
```

### 2.4 三条「不许重复」的规则

| 情况 | 处理 | 为什么 |
| --- | --- | --- |
| `DANGEROUS` / `LOOP` | **不写**流水行 | 它走告警通道，再写一条就是重复 |
| `tool_result`（动作回执） | **不写**流水行 | 动作本身已经记过一行，回执再记一次同一次操作会出现两遍 |
| `usage`（账单事件） | 引擎在判定**之前**就排除了 | 它不是一次可审查的动作 |

### 2.5 界面：流水是**背景层**，卡片是主角

「实时审核流水」是告警面板底部的**绝对定位层**
（`position: absolute; z-index: 1`），
告警卡片是 `z-index: 2` —— 所以：

- 面板空着的时候，底部铺着一层**灰字流水**（像监控录像的走带）；
- 一旦触发告警，**卡片盖在流水上面**，
  流水继续在底下滚 —— 既看得到「一直在看」，也看得到「刚才那一下出事了」。

流水区限高 170px、自动滚到最新一行、最多留 120 行。
它是**只读背景流**（`pointer-events: none`）——
不能挡住底下告警卡片的点击。

### 2.6 刷新与切换：流水要**回放**

| 场景 | 处理 |
| --- | --- |
| 页面刷新 | `/api/sessions/{id}/state` 带着 `ontrack` → 前端**回放** |
| 切换会话 | 同上（`loadSessionContent()` 里回放） |
| 看板刚打开 | `Watcher._prime()` 也会收下历史里的流水行 |

⚠️ 这三处**缺一不可**：
少一处，用户就会看到一块**空白**面板，误以为哨兵没在工作。

## 3. 任务二：无 Prompt 挂载的强引导

### 3.1 场景

用户用「雷达」把一个**已经在跑**的 Agent 会话挂载进来。
这类会话的日志**通常没有最初的 Prompt**，
哨兵自动锚定拿不到目标 → 顶部红字提示「未设置」。

以前那个「未设置」只是一个灰字，
用户根本不知道**该往哪儿填**。

### 3.2 这一版怎么做的

| 元素 | 表现 |
| --- | --- |
| 「未设置」chip | 变成**橘黄高亮**（`--drift` 那一族橘色），带轻微呼吸动画 |
| 旁边的气泡 | **常驻**显示：「雷达找不到初始目标，请在此手动输入任务目标，以启用漂移监控。」 |
| 点「未设置」/ 点气泡 | **光标直接送到**顶部的任务目标输入框 |
| 设定成功之后 | 顶部来源变成 **`[MCode] 手动锚定`**，气泡自动消失 |

### 3.3 两个设计决定

**为什么用橘色而不是红色？**
红色在哨兵的语言里是「**出事了**」。
这里只是「你还没填」—— 该吓人的是红线级告警，不是空着的输入框。
所以用 `--drift`（意图漂移那一族橘色），跟红色明确区分。

**为什么气泡**常驻**而不是「鼠标移上去才有」？**
用户恰恰是在**没发现**问题的时候最需要这句话。
气泡常驻，他第一眼就看见；藏起来的话，等他发现的时候已经绕了一圈。

### 3.4 「手动锚定」这个说法

后端 `GOAL_SOURCE_LABELS["explicit"]` 从「人工指定」改成了「**手动锚定**」：

```python
GOAL_SOURCE_LABELS: ClassVar[Dict[str, str]] = {
    "none": "未设置",
    "config": "配置文件",
    "explicit": "手动锚定",     # v3.3.1：原「人工指定」
    "auto": "自动提取",
}
```

理由：顶部要显示的是**结果**（漂移监控已经锚上了），
不是「这个值是你手填的」这种**过程**描述。

⚠️ 前端在保存成功后**立刻**刷新目标面板（不等 SSE 绕一圈）——
那一圈里气泡还杵在那儿，像是「没设成功」。

## 4. 任务三：PID 反查失败的宽容度

### 4.1 事实

`[未绑定进程]` + 灰掉的武装开关，看起来像「整个哨兵瘫了」。
**其实不是。**

| 能力 | 没有 PID 时 |
| --- | --- |
| L1 规则判定 | ✅ **照常** |
| L2 解释 | ✅ **照常** |
| 告警落盘 | ✅ **照常** |
| 通知推送（Webhook / 弹窗 / 声音） | ✅ **照常** |
| 挂起进程（拦截） | ❌ **做不到** —— 没有 PID 就没法挂 |

### 4.2 这一版怎么做的

`[未绑定进程]` 的悬停提示：

> 未找到对应进程。如需拦截，请使用 `--agent` 模式启动，
> 或确保 Agent 命令行包含日志路径。

武装开关的禁用提示补上一句：

> L1/L2 告警与推送不受影响 —— 只是无法挂起进程。

### 4.3 钉住这条边界

新增回归测试：引擎**完全没有 PID / 守护者**时，
喂一条高危命令进去 ——
断言**告警照样出得来**、**通知器照样收得到**。

这条断言很重要：
将来谁要是「顺手」把推送逻辑挂在 PID 上，
测试会立刻红。

## 7. 给用户看的用法

### 7.1 「实时审核流水」在哪

中间「**实时告警**」面板的**底部**。
它是灰字、等宽、自动滚到最新一行。

- 看到它一路滚 → 哨兵**正在看**你的 Agent；
- 它停下来了 → 真的出事了（告警卡片会盖上来）。

### 7.2 「未设置」怎么办

1. 顶部那个橘黄的「未设置」**点一下**，
   光标会直接跳到右上角的任务目标输入框；
2. 写一句你这轮要干的事（比如「重构 auth 模块并修复登录 bug」）；
3. 点「**设定**」；
4. 顶部的来源变成「**手动锚定**」——
   意图漂移监控（DRIFT）从这一刻开始盯。

### 7.3 「未绑定进程」要紧吗

**不要紧。**

- L1/L2 判定、告警、推送**全都照常**；
- 只有「红线告警时自动挂起 Agent」这一项用不了 ——
  因为哨兵不知道该挂谁；
- 想让这一项也能用，两条路：
  - 用 `sentinel --agent <类型> <任务>` 启动（哨兵自己拉 Agent，进程一定认得）；
  - 或者让 Agent 的命令行里**带上日志路径**
    （哨兵靠它反查 PID）。
