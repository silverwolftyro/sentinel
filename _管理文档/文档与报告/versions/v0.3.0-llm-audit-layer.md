## 1. 本次迭代目标

两件事：

1. **资产考古** —— 调研废弃项目「个人项目：agent中心」（Agent Hub），
   评估其 GUI 与事件处理资产能否移植；
2. **L2 模型接入** —— 接入本地 Ollama，把 L1 拦截到的危险事件

## 2. 任务一：旧项目资产考古（结论）

完整报告见 [`v0.3.0-asset-audit.md`](v0.3.0-asset-audit.md)。

### 2.1 结论：**仅参考重写**

旧项目是**闸门**（spawn 子进程、拦截命令、人工批准才放行），
哨兵是**旁观者**（只读日志、只告警、不干预）。
`core/` 的核心价值全部服务于「阻断进程」，与哨兵只读红线逐行冲突：

| 位置 | 行为 |
| --- | --- |
| `core/proc_utils.py:226-273` | `taskkill /T /F`、`killpg(SIGTERM)`、`kill()` |
| `core/cli_executor.py:488/497/535/553` | `create_subprocess_shell/exec` + `kill_process_tree` |
| `core/plugin_bus.py:301/324` | spawn / kill 插件进程 |
| `core/process_scanner.py:1097/1104/1112` | `psutil` suspend / resume / kill |

而且 `gui/app.py` 是 **4,115 行的单页巨物**（1 个 `@ui.page`、1,941 行的 `index()`、
55 个嵌套闭包、35 个 `core.*` 导入、3 个全局单例），**不存在可分离的页面单元**。

### 2.2 本次实际落地的三项资产

| 资产 | 来源 | 落地形式 |
| --- | --- | --- |
| `src/gui/layout_store.py` | 旧 `gui/layout_store.py`（104 行，零业务依赖） | **直接复用**，只改文件名与路径 |
| `src/gui/density_store.py` | 旧 `gui/density_store.py`（90 行，零业务依赖） | **直接复用**，去掉一处 import |
| `src/gui/density.py` | 旧 `gui/density.py` 的档位定义部分 | **只搬档位常量与夹取函数**，裁剪逻辑不搬（它依赖旧项目的聊天模型） |
| 防提示注入条款 | 旧 `core/llm_review.py:135-145` | **补进** `SENTINEL_EXPLAIN_TEMPLATE` |

> 这两个持久化模块的共同价值是**原子写范式**：先写同目录临时文件，
> 再 `os.replace` 覆盖；读失败一律回落默认值，绝不因为一个坏文件让面板起不来。
> 已迁移到哨兵并配了单测。

### 2.3 一条必须记住的坑

旧项目 `core/net_guard.py:9-12` 记录：**NiceGUI 默认 `cors_allowed_origins='*'`**，
不做 Origin 加固的话，操作者浏览器里的任意网页都能点「批准」直接绕过人工闸门。
哨兵将来若做 GUI，**必须**有等价加固（只绑回环 + Origin 白名单）。

## 3. 任务二：L2 本地模型层设计

### 3.1 三条硬约束

| # | 约束 | 实现 |
| --- | --- | --- |
| 1 | **永不抛异常** | 模型没开 / 超时 / 连不上 / 输出解析不出来，一律返回 `degraded=True` 的降级结果 |
| 2 | **只允许本地端点** | 非回环 `base_url` 直接**拒绝调用**（走降级），兑现「所有推理在本地完成」 |
| 3 | **不引入重型框架** | 不用 `pydantic-ai`，直接 HTTP 调用 Ollama 原生 `/api/chat` |

> **为什么不用 `pydantic-ai`**：旧项目自己的实测记录
> （`core/llm_review.py:206-218`，2026-10-22，本地 Ollama + qwen2.5:7b）
> 显示 `output_type=<BaseModel>`（走 tool call）**10 次失败 6 次（60%）** ——
> 模型把 tool call 当正文吐出来，报 `Invalid JSON: expected ident at line 1 column 2`。
> 哨兵改用「**纯文本 + 容错解析阶梯**」，并用 Ollama 原生端点的
> `format: "json"` 语法约束降低格式失败率。

### 3.2 对外接口

```python
class OllamaClient:
    def explain_event(self, event_data: dict) -> str:
        """把危险事件翻译成人话告警（任务书指定入口，返回一段话）。"""

    def explain(self, event_data: dict) -> Explanation:
        """结构化版本：返回 Explanation（含 degraded / reason / detail）。"""
```

`event_data` 除事件本身外，可携带：

| 键 | 含义 | 来源 |
| --- | --- | --- |
| `thinking` | Agent 自述（证据优先级最高） | 引擎在流中记住最近一次 thinking 事件 |
| `verdict` | L1 规则判定（**事实**，模型不得改写） | `RuleEngine.check_event()` 的返回值 |

### 3.3 `Explanation` 数据结构

```python
@dataclass(frozen=True)
class Explanation:
    text: str            # 面向人的解释（一段话）
    degraded: bool       # 是否走了降级路径
    reason: str          # 降级原因；未降级时为空串
    detail: dict         # 结构化字段：title / why / touch / outcome
    latency_ms: int
    model: str
```

### 3.4 降级契约（**本层的核心**）

抄自旧项目 `core/llm_review.py:381-435`：「**永不抛异常，缺失绝不等同于安全**」。

| 故障 | 行为 | 降级文案 |
| --- | --- | --- |
| 模型层被关闭（`llm.enabled=false`） | 降级，**一个 HTTP 请求都不发** | 「本地模型层已关闭」 |
| 端点非回环 | 降级，拒绝调用 | 「模型端点不是本机地址…已拒绝调用」 |
| 熔断器打开 | 降级，跳过调用 | 「连续失败已触发熔断」 |
| 连接被拒绝（Ollama 没开） | 降级 | 「调用本地模型失败（ConnectionError: …）」 |
| 超时（默认 20s） | 降级 | 「调用本地模型失败（Timeout: …）」 |
| HTTP 5xx | 降级 | 「调用本地模型失败（HTTPError: HTTP 500）」 |
| 模型不存在 | 降级 | 「本地模型不存在：xxx（请先执行：ollama pull xxx）」 |
| 输出为空 | 降级 | 「模型输出为空」 |
| 输出无法解析 | 降级 | 「模型输出无法解析（…）」 |

**降级时的文案 = 原始命令 + 规则原因**，这是任务书明确要求的兜底：

```
规则判定：匹配到高危命令: rm -rf
原始命令：rm -rf /tmp/sentinel-demo
（调用本地模型失败（HTTPError: …），以上为规则层原始判定）
```

> 降级**不会**让告警消失，也不会让规则判定消失 —— 人依然看得到
> 「命中了什么、命令长什么样」。

### 3.5 熔断器

连续失败 `failure_threshold` 次（默认 3）→ **打开**熔断，
持续 `breaker_open_seconds` 秒（默认 300），期间直接跳过 L2。

抄自 `dsh-plain-approval/src/ollama-guard.js:50-57, :174-185`。
目的：日志洪峰时不要把本地模型压垮，也不要让每条告警都等一次超时。

### 3.6 容错解析阶梯（`src/llm/parsing.py`）

抄自 `dsh-plain-approval/src/parse.js:69-92`，并针对哨兵扩展：

1. `strip_noise` —— 去代码围栏 / BOM / 首尾空白
2. `extract_json_object` —— 找第一个**配平**的 `{...}`
   （正确跳过字符串字面量内部的括号与转义，
   这是简单 `text.find("{")` 做不到的）
3. `remove_trailing_commas` —— 去掉 JSON 尾逗号
4. `parse_labelled_text` —— 标注式文本兜底（`title: xxx`）
5. 失败 → `ok=False`，调用方走降级

### 3.7 后端强制脱敏（`src/llm/redaction.py`）

抄自旧项目 `core/stream_parser.py:129-131`。

哨兵喂给模型的是**未经信任的 Agent 日志原文**，里面完全可能出现密钥。
脱敏发生在**两个位置**：

1. **送模型前** —— 不让模型看到密钥（模型可能把它复述进解释里）；
2. **落盘前** —— 不让密钥进 `logs/sentinel_alert.log`
   （告警日志往往比原日志更容易被随手打开、随手转发）。

覆盖：私钥块、各家 API Key 格式（OpenAI / Anthropic / GitHub / AWS / Google /
Slack / Stripe）、显式赋值（`api_key=xxx`）、JWT、Bearer 头、带密码的连接串。

### 3.8 引擎集成

```
Adapter.read_stream()
   └─▶ 记住最近一次 thinking（作为 Agent 自述证据）
   └─▶ RuleEngine.check_event()
        └─ DANGEROUS / LOOP
             └─▶ OllamaClient.explain()  ← 失败自动降级，绝不影响主流程
                  └─▶ 告警挂上 explanation + explanation_degraded
                       └─▶ 终端红色告警 + logs/sentinel_alert.log
```

`SentinelEngine` 新增 `llm_client` 参数；为 `None` 时只输出规则层原始判定。

## 5. 实测结果（真实本地模型）

环境：本机 Ollama 可用，但 `qwen2.5-coder:14b` **未安装**
（已安装：`qwen2.5:7b`、`qwen2.5vl:7b`）。

**降级路径（默认模型缺失）** —— 全部按契约工作：

```
本地模型调用失败：OllamaError: 本地模型不存在：qwen2.5-coder:14b（请先执行：ollama pull qwen2.5-coder:14b）
本地模型连续失败 3 次，熔断 300 秒
[WARN] LOOP: 连续 3 次读取同一个文件，疑似死循环: D:/proj/package.json | 工具=Read | 命令=-
  人话解释：规则判定：连续 3 次读取同一个文件，疑似死循环: D:/proj/package.json
（调用本地模型失败（OllamaError: …），以上为规则层原始判定）
```

**正常路径（切到 qwen2.5:7b）** —— 真实模型输出：

```
[CRITICAL] DANGEROUS: 匹配到高危命令: rm -rf | 工具=Bash | 命令=rm -rf /tmp/sentinel-demo
  人话解释：清理临时构建产物。原因：用户要求清理项目的临时构建产物。影响：/tmp/sentinel-demo 目录（会删除）。
  后果：删除了临时构建产物，确保源码安全；但命令实际删除了整个 /tmp/sentinel-demo 目录，而不仅仅是 build 目录

[CRITICAL] DANGEROUS: 匹配到高危命令: git push -f | 工具=Bash | 命令=git push -f origin main
  人话解释：Agent 说要清理临时构建产物，但命令是强制推送代码。原因：无法确定这一步的原因，请查看下方原始调用。
  影响：项目里的代码仓库（会修改）。后果：代码仓库被强制推送，可能覆盖本地未提交的更改；实际操作是清理临时构建产物
```

> ⭐ **注意第 2 条**：模型**主动发现并写出了落差** ——
> Agent 自述是「清理临时构建产物」，实际命令却是 `git push -f`。
> 这正是 `SENTINEL_EXPLAIN_TEMPLATE` 里「必须如实写出落差」那条硬约束在起作用，
> 也是「证据优先级」设计（Agent 自述 → 用户指令 → 命令实际行为）的直接收益。
