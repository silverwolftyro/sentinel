## 3. 两条必须守住的边界

### 3.1 功能性匹配串：**一个字都没动**

`src/proc_tree.py` 里这些字面量是**识别真实宿主进程的判据**：

```python
BRIDGE_HOST_CMDLINE_MARKERS = (
    "webui.server",
    "n.e.k.o_plugin_agent_bridge",
    "agent_bridge",
    ...
)

BRIDGE_HOST_DIR_MARKERS = (
    ".neko-bridge",
    "n.e.k.o",
    "neko",
    "agent_bridge",
    ...
)
```

改了它们，雷达就**认不出宿主**了 —— 整个进程树雷达会直接失效。
所以中性化时**只动文案、不动判据**，这些常量旁边的注释也保留
（它们解释的正是这些常量）。

同一条原则下，**上游项目的出处标识也保留** ——
`src/agents/cloud_agents.json` 的 `source.project` 仍写着
`n.e.k.o_plugin_agent_bridge`，`src/proc_tree.py` 的模块 docstring
也仍指向上游原名 —— **合规靠的就是它**。

### 3.2 已发布版本的记录：**不追溯改写**

以下位置里的「上游」是**当时的真实称呼**，本版**原样保留**：

* `CHANGELOG.md` 里 v4.0.0 ~ v4.3.0 的历史条目；
* `_管理文档/文档与报告/versions/` 下 v4.0.0 ~ v4.3.0 的版本文档；
* 《Agent Bridge 资产盘点》报告本身。

**理由**：那些是**已发布版本（带 Git tag）的不可变记录**。
事后把它们洗成中性词，等于篡改历史 ——
读者会误以为当时就是那么写的。

出处与合规由 **`NOTICE`** 承担。`tests/test_v431_neutral_wording.py` 里
有一条断言**专门盯着这件事**：如果哪天有人「顺手」把历史也洗了，
测试会失败并说明「那是中立吗？不是，那是篡改」。
