# v0.4.0 —— 哨兵看板与告警通道

> 版本：v0.4.0 · 日期：2026-10-26 · 类型：GUI 看板 + 多通道通知 + 上下文感知
> 界面实拍：[`docs/assets/dashboard-v0.4.0.png`](../assets/dashboard-v0.4.0.png)

## 1. 本次迭代目标

三件事：

1. **轻量级本地监控面板** —— 从「只能在终端看日志」变成「有可视化看板」；
2. **系统级告警通道** —— 桌面弹窗 + 声音 + Webhook，真实干预提醒；
3. **上下文感知** —— L1 规则不再只看单步，能识别「卡住」与「密钥外泄」这两类
   跨事件模式。

## 2. 任务一：轻量级本地监控面板

### 2.1 技术栈选择

**FastAPI + Jinja2 + SSE（Server-Sent Events）**，纯 Python，**无 Node.js 构建链**。

选型理由：

| 方案 | 判断 |
| --- | --- |
| **FastAPI + Jinja2 + SSE** | ✅ 选中。纯 Python 依赖、模板直出、EventSource 浏览器原生支持断线重连 |
| Streamlit | ❌ 启动慢、内存占用大、样式定制受限，且与「只读查看器」定位不符 |
| 裸 Vue 单页 | ❌ 违背「不引入 Node.js 构建链」的要求 |
| NiceGUI（v0.3.0 考古对象） | ❌ 考古结论已判定 `app.py` 不可移植；且 NiceGUI 默认 `cors_allowed_origins='*'` 有安全隐患 |

新增依赖：`fastapi`、`uvicorn`、`jinja2`、`httpx`（仅测试用）。

### 2.2 界面布局

参考 [`docs/assets/agent-hub-ui-reference.jpg`](../assets/agent-hub-ui-reference.jpg)
的设计语言**重新实现**（不移植旧项目代码，类名全部自成一派）：

```
┌────────────────────────────────────────────────────────────────┐
│ 哨兵 SENTINEL  │ READ-ONLY │ LOCAL-ONLY │ 127.0.0.1:8000 │ RUNNING │
│                                             [暂停推送] [立即扫描] │
├────────────────────────────────────────────────────────────────┤
│ 被监控日志 D:\…\mcode.jsonl   告警日志 D:\…\sentinel_alert.log     │
│                    25 DANGEROUS │ 7 LOOP │ 5 ON_TRACK │ 34 总数 │
├──────────────────────────────┬─────────────────────────────────┤
│ 实时告警（左）                │ 被监控日志（右，只读跟随）      │
│  ┌────────────────────────┐  │  1 {"type":"thinking",…}        │
│  │ LOOP  repeat_read_loop │  │  2 {"type":"tool_call",…}        │
│  │ 连续 3 次读取同一个文件 │  │  3 …                           │
│  │ ┌────────────────────┐ │  │                                 │
│  │ │ rm -rf /tmp/demo   │ │  │                                 │
│  │ └────────────────────┘ │  │                                 │
│  │ （本次事件没有附带解释）│  │                                 │
│  └────────────────────────┘  │                                 │
├──────────────────────────────┴─────────────────────────────────┤
│ ▸ 事件流（可折叠）                                               │
└────────────────────────────────────────────────────────────────┘
```

- **红色卡片** = `DANGEROUS`，**琥珀色卡片** = `LOOP`；
- 模型解释缺失时明确标注「本次事件没有附带解释」/「规则原始判定（模型未提供解释）」，
  **不让用户误以为规则判定是模型说的**；
- 顶部徽章把安全姿态显式摆出来：`READ-ONLY` / `LOCAL-ONLY` / 绑定地址 / 运行状态。

### 2.3 实时推送：SSE 扇出

- 每个订阅者一个**有界** `asyncio.Queue`；
- `app.lifespan` 把运行中的 event loop 绑到 hub 上；
- 监听线程**从不直接碰队列**，一律通过
  `loop.call_soon_threadsafe(queue.put_nowait, event)` 投递
  —— 这是 `run_coroutine_threadsafe` 的非阻塞等价物；
- `/api/events` 订阅后 yield `data: {json}\n\n` 帧，每 15 秒发一个
  `: keep-alive` 注释帧保活；
- 无 event loop 绑定时（单元测试场景）退化为直接 `put_nowait`。

选 SSE 而非 WebSocket 的理由：单向推送场景下 SSE 足够，
且 `EventSource` **浏览器原生支持断线重连**，不需要自己写重连逻辑。

### 2.4 两个独立的文件跟随器

告警日志与被监控日志各有一个 `FileTailer`，各自维护字节偏移：

- **旋转检测**：比对 `os.stat().st_ino`（NTFS 上是**文件索引**，
  能识别「同名新文件顶替旧文件」）→ 变化则偏移与缓冲归零；
- **原地截断检测**：`size < offset` → 同样归零；
- 二进制读取 + `errors="replace"` 解码；
- **半行不丢**：末尾不完整的行**留在缓冲区**，等下次写完再吐 ——
  这正是旧项目 `log_tailer.py:853-857` 那个未修复的半行丢失 Bug 的正确做法；
- 跟随器跑在守护线程里，**每轮单独捕获异常**，一个坏文件拖不垮整个服务。

### 2.5 安全加固（继承 v0.3.0 考古结论）

v0.3.0 的考古发现旧项目栽在 NiceGUI 的 `cors_allowed_origins='*'` 上 ——
**操作者浏览器里的任意网页都能点「批准」**。哨兵的做法：

1. **只绑回环**：`127.0.0.1` / `localhost`。要绑 `0.0.0.0` 必须显式
   `--allow-remote`，否则 `create_app` 直接 `ValueError`、`main()` 退出码 2；
2. **Host 守卫**：`Host` 头必须解析到回环地址（测试环境放行 `testserver`）；
3. **Origin 守卫**：带 `Origin` 头的请求必须在白名单
   `{http://127.0.0.1:<port>, http://localhost:<port>}` 内，或与 `Host` 同源；
   否则 **403**。无 `Origin`（同源导航、curl）放行。

> 实测：外部 `Origin` 返回 **HTTP 403**，本机 `Origin` 正常 200。

### 2.6 扫描触发与告警回传

GUI **不直接 import `src.core.engine`** —— 引擎相关导入全部收在
`_build_scan_callback` 内部，通过注入的 `scan_callback` 回调解耦：

```
POST /api/scan
   └─▶ run_in_threadpool(scan_callback, watch_path)   ← 引擎是阻塞的
        └─▶ 引擎写入 logs/sentinel_alert.log（含 ALERT_JSON 行）
             └─▶ 告警日志跟随器读到新行 → parse_alert_line → normalize_alert
                  └─▶ SSE 推给浏览器 → 卡片出现
```

**实拍验证**：`POST /api/scan` → `{"ok":true}` → 告警数 24 → 25 实时跳变，
新卡片出现在左栏。

## 3. 任务二：系统级告警通道

### 3.1 模块划分

| 文件 | 内容 |
| --- | --- |
| `src/core/channels.py` | `BaseChannel` 抽象 + `ConsoleChannel` / `FileChannel` / `DesktopChannel` / `SoundChannel` / `WebhookChannel` |
| `src/core/notifier.py` | `Notifier`：读 `alert` 配置、按等级过滤、逐通道分发、失败隔离 |

### 3.2 桌面通知的回退顺序

1. `plyer`（可选依赖，动态 import，**不写进 requirements.txt**）；
2. **Windows**：`powershell.exe` + `System.Windows.Forms.NotifyIcon.ShowBalloonTip`
   （零额外依赖，气泡提示）；
3. macOS：`osascript -e 'display notification …'`；
4. Linux：`notify-send`；
5. 都没有 → 记 warning，返回 `False`，**绝不抛异常**。

### 3.3 声音告警的回退顺序

1. **Windows**：标准库 `winsound.Beep(1000, 300)`
   （**进程内调用，不起子进程**；`winsound` 是 Windows 专有，故惰性 import）；
2. macOS：`afplay /System/Library/Sounds/Basso.aiff`，再退 `osascript -e beep`；
3. Linux：`paplay`，再退 `aplay`；
4. 都没有 → warning + `False`。

### 3.4 ⭐ 注入安全：用户内容绝不进命令行

告警原因与命令是**外部输入**（Agent 写的），拼进 shell 命令行就是命令注入。

Windows 的 PowerShell 脚本里**只有环境变量引用**：

```powershell
$icon.ShowBalloonTip(10000, $env:SENTINEL_ALERT_TITLE, $env:SENTINEL_ALERT_BODY, $tip)
```

标题与正文通过 `Popen(env=...)` 传入，**argv 里一个用户字符都没有**。
macOS 用 `system attribute "SENTINEL_ALERT_BODY"`，Linux `notify-send` 用
**独立 argv 元素**且全程 `shell=False`。

> 实测：正文含 `; $(whoami) \`id\` | tee pwn` 时，从 PowerShell 原样透传，字节一致。
> 单元测试断言**原始消息不出现在 argv 里**。

### 3.5 失败隔离

`Notifier.notify()` 对**每一个** `channel.send()` 单独包
`try/except Exception` → 记 warning → 继续下一个通道；`notify()` 自身**永不抛异常**。

- 未知通道类型 → warning + 跳过；
- 通道返回 `False` → 不影响其它通道；
- 引擎侧还有一层：`_dispatch()` 也包了 `try/except` ——
  通知炸了也不能让审查中断。

### 3.6 配置

```yaml
alert:
  enabled: true
  min_level: "info"        # info < warn < critical
  channels:
    - {type: "console",  enabled: false}   # 引擎自己已带颜色地打印，默认关
    - {type: "file",     enabled: true, path: "logs/alerts.jsonl"}
    - {type: "desktop",  enabled: true, title: "哨兵告警"}
    - {type: "sound",    enabled: true}
    - {type: "webhook",  enabled: false, url: "", timeout: 10, format: "dingtalk"}
```

> **`console` 通道默认关闭**：引擎本身已经带颜色地打印到终端，
> 再开这个会重复输出两遍。单独使用 `Notifier` 时才需要打开。

Webhook 支持 `dingtalk` / `feishu` / `generic` 三种载荷格式；
空地址与非 `http(s)` 协议一律拒绝投递。

## 4. 任务三：上下文感知（Context Tracker）

### 4.1 为什么需要

L1 规则只看**单个事件**（这条命令危不危险）。
但有些危险**单步看不出来**：

- 「改代码 → 跑测试 → 还是失败 → 再改 → 再跑」—— 每一步单独看都无害；
- 「读 .env → curl 发出去」—— 两条命令单独看，第二条也很普通。

`ContextTracker` 住在 `src/core/engine.py`，是一个**纯状态机**。

### 4.2 STUCK —— 测试连续失败

```
tool_call(pytest)  →  tool_result(error)   ← 第 1 次失败
tool_call(pytest)  →  tool_result(error)   ← 第 2 次失败
tool_call(pytest)  →  tool_result(error)   ← 第 3 次失败 → 触发
```

- 判定为测试命令的特征：`pytest` / `unittest` / `tox` / `npm test` /
  `yarn run test` / `go test` / `cargo test` / `jest` / `vitest` / `mvn test` …
  刻意**不用裸的 `test` 子串**（否则 `latest` / `contest` 会被误判）；
- **测试通过**或**中途插入了非测试动作** → 失败计数清零；
- 触发后计数复位，避免同一次卡死反复刷屏；
- 告警文案：`[STUCK] 测试连续失败3次，Agent 可能卡住了`。

### 4.3 LEAK —— 疑似敏感信息外发

```
tool_call(Read  .env)   →  tool_call(curl https://…)   → 触发
```

- 敏感文件特征：`.env*` / `credentials` / `id_rsa` / `.npmrc` / `.netrc` /
  `secrets.yaml` / `.htpasswd` …
- 外发特征：命令里的 `curl` / `wget` / `fetch` / `nc` / `scp` / `rsync` /
  `Invoke-WebRequest`，或**工具名**含 `fetch` / `http` / `webhook` / `upload`
  （很多 CLI 的外发工具不经过 shell，参数里根本没有 `curl` 字样）；
- **写** `.env` 不算「读取敏感文件」—— 那不是外泄的前置动作；
- 「紧接着」= **紧邻的那一个**工具调用，标记被下一个调用消费掉；
- 告警文案：`[LEAK] 疑似敏感信息外发：刚读取过敏感文件，紧接着执行了外发操作`。

### 4.4 滑动窗口

追踪器保留最近 **5** 个工具事件（`window` 可配），并额外记下 `target`
（读写的文件路径）—— 对「读了 .env」这类判定，光看命令看不出端倪，
**路径才是关键证据**。告警里带 `context_history`，用户能看到判定依据。

### 4.5 与 L1 的关系

| | L1 规则层 | Context Tracker |
| --- | --- | --- |
| 视野 | 单个事件 | 事件序列 |
| 判定 | `DANGEROUS` / `LOOP` | `STUCK` / `LEAK` |
| 状态 | 无（纯函数） | 有状态机，可 `reset()` |
| 实现 | 纯正则 | 纯正则 + 有限状态机 |

两者都**不调用模型**，也都**不修改被监控 Agent 的任何东西**。

## 6. 使用方式

```bash
# 启动看板（默认 127.0.0.1:8000）
python -m src.gui.server --watch path/to/agent.jsonl

# 其它开关
python -m src.gui.server --watch path/to/agent.jsonl --port 8123
python -m src.gui.server --watch path/to/agent.jsonl --no-scan   # 引擎独立跑时用

# 终端模式（不开看板）
python -m src.core.engine path/to/agent.jsonl
python -m src.core.engine path/to/agent.jsonl --no-llm       # 不调模型
python -m src.core.engine path/to/agent.jsonl --no-notify    # 不弹窗
python -m src.core.engine path/to/agent.jsonl --no-context   # 关上下文检测
```

## 7. 遗留与后续

| 项 | 说明 |
| --- | --- |
| `plyer` 未进 requirements.txt | 它是可选增强，动态 import；需要时手动 `pip install plyer` |
| `ON_TRACK` 计数只在扫描后出现 | 告警日志只记录告警，不记录「正常」事件 |
| 通知的「已读/忽略」状态 | **刻意不做** —— 那需要写告警日志，而告警日志是引擎的地盘 |
| 规则层仍不区分「红线 / 软信号」 | 全部危险命令同属 `critical`，会削弱告警区分度 → v0.5.0 |
| 实时跟随仍是「轮询式扫描」 | 目前是 `run()` 一次性读完；真正的增量尾随 → v0.5.0 |

**下一步（v0.5.0）**：

1. 规则层加路径/目标分析与确定性 `consequence` 句子；
2. 危险命令表分「红线 / 软信号」两级；
3. 真正的增量尾随采集（复用本版的 `FileTailer` 逻辑）；
4. Webhook 增加签名与重试。
