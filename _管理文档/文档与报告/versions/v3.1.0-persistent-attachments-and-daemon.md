# v3.1.0 —— 持久化会话记忆与手动挂载引导

> v3.0.2 的交互式启动、MPA 设置页和精准雷达过滤极其出色。
> 「zstd 不支持接入」也是极其诚实的设计。
>
> 但还有三件事让夜里挂机的用户难受：
>
> 1. **挂载是「一次性」的** —— 哨兵崩溃重启、或者看板刷新，
>    所有挂载的会话都会丢失，用户得重新点一遍；
> 2. **压缩日志「不能接入」只说了「不行」**，
>    没说「怎么才行」—— 用户知道自己不行，却不知道怎么才行；
> 3. **夜里挂机的进程没人看着** —— 看板服务一崩，
>    整个哨兵就没了，等早上起来才发现。
>
> 这一版把这三件事补上：
> **记住**（挂载持久化）、**教会**（重定向指引）、**看住**（守护 + 开机自启）。

## 1. 红线：这一版一个字都没改

**本版未新增任何红线修订。** R1–R9 与 v2.1.0 **完全一致**，**一字未改**。

逐条对照：

* 哨兵**依然只读** —— 持久化写的是**哨兵自己**的状态文件
  （`config/attached_sessions.json`），
  **绝不**写进用户被监控的项目目录；
* 守护者**依旧要用户亲手武装** —— 本版只是**恢复**用户当初亲手开的开关，
  从不自动武装；
* **没有**新增任何写用户文件 / 改用户代码 / 终止用户进程的路径；
* 开机自启是用户**亲手双击 `install_startup.bat`** 才发生的**显式操作**，
  不是哨兵偷偷改系统设置；
* 压缩日志（zstd）**依然接不进来** —— 本版只是补上了「怎么才行」的指引，
  **没有**做 zstd 增量解压，那个结论一个字没变；
* 配置写回仍然只用 `config_loader.save_config()`
  （外科手术式，保留注释，写前备份 `.bak`）；
* 代码卫生只动哨兵**自己**的代码，**不碰**用户项目。

> ⚠️ 唯一新增的「写」有两处，都写在**哨兵自己的地盘**上：
> `config/attached_sessions.json`（挂载历史）与
> `logs/daemon_crash.log`（崩溃日志）。

## 2. 任务一：挂载会话的持久化（自动重连）

### 2.1 为什么

v3.0.2 的挂载是**一次性**的：用户在雷达面板里点「接入」，
会话就被盯上了 —— 但哨兵一重启（崩溃、更新、机器重启），
所有挂载**全部消失**，用户得重新点一遍。

夜里挂机的场景里，这特别难受：早上起来一看，
昨晚盯的那几个任务全都不在了。

### 2.2 做了什么

| 动作 | 说明 |
| --- | --- |
| 新模块 | `src/attachments.py` —— `AttachmentStore`（`load` / `save_entry` / `update` / `remove` / `prune`） |
| 落盘位置 | **哨兵自己的** `config/attached_sessions.json`（打包版落在 exe 旁） |
| 记录内容 | 路径 / Agent 类型 / 工作目录 / **是否武装** / 会话 ID / 挂载时间 |
| 恢复时机 | `lifespan` 里，在 `registry.start_all()` **之前** |
| 失效判定 | 文件已不存在 **或** 静默超过 **1 小时**（`STALE_SECONDS = 3600`） |
| 写入方式 | 临时文件 + `os.replace()` **原子替换** |

### 2.3 为什么恢复要走同一条路

恢复用的 `_attach_one()` 和面板「接入」按钮**是同一个函数**
（从 `/api/attach` 里抽出来的嵌套函数）。

不然恢复出来的会话就会缺一堆设置：进程绑定、目标提取、守护者武装回调……
「恢复出来的会话和手动接进来的会话不一样」是最难查的那种 bug。

### 2.4 关键取舍

* **持久化失败绝不能让挂载失败** ——
  用户最关心的是「现在正在盯着」，写不进去只记一条 warning；
* **用户主动卸载 = 不再持久化** —— 下次启动不该又把它接回来；
* **武装状态只在真的绑上了进程时才恢复** ——
  绑不上的话武装按钮本来就是禁用的，硬调只会得到一句「没有 PID」。

## 3. 任务二：完善「不支持的格式」的手动重定向指引

### 3.1 雷达弹窗：禁用按钮收不到 click

v3.0.2 的做法是把压缩日志的按钮**直接禁用**。诚实，但没用：

* 禁用按钮**收不到 click 事件** —— 用户点了没反应，
  只会以为「这界面坏了」；
* 用户看到「不能接入」只知道自己不行，**不知道怎么才行**。

v3.1.0 改成：

| 改动 | 之前（v3.0.2） | 现在（v3.1.0） |
| --- | --- | --- |
| 按钮 | `disabled`（点不动） | `btn--blocked` + `aria-disabled="true"`（**能点**） |
| 文案 | 「接入」 | 「**怎么接入？**」 |
| 点击后 | 什么都不会发生 | 弹出橙色**指引气泡** |

气泡文案就是任务书的原话：

> 此 Agent 使用压缩格式，无法实时跟随。请在启动 Agent 时添加输出重定向，
> 例如： `你的命令 > D:\logs\session.jsonl` ，然后通过上方的【手动指定日志路径】接入。

> 实拍：[`assets/radar-v3.1.0-zstd-guide.png`](../assets/radar-v3.1.0-zstd-guide.png)
>
> （截图里能看到：橙色 `zstd 压缩 · 暂不支持接入` 徽章、
> 虚线边框的「怎么接入？」按钮、下方展开的指引气泡。）

### 3.2 设置页：「如何让我的 Agent 被监控」折叠面板

挂在 `/settings/sessions`（挂载管理）页里，列出四个 Agent 各自
**带输出重定向**的启动命令，每条一个【复制】按钮：

| Agent | 启动命令 | 标签 |
| --- | --- | --- |
| mcode | `mcode exec --output-format stream-json --cwd "<目录>" "<任务>" > "<日志>"` | 原生 JSONL · 可直接接入 |
| codex | `codex exec --json --cd "<目录>" "<任务>" > "<日志>"` | 原生 JSONL · 可直接接入 |
| claude | `claude --output-format stream-json --print "<任务>" > "<日志>"` | 原生 JSONL · 可直接接入 |
| deepseek | `<你的 deepseek 命令> > "<日志>"` | **压缩日志 · 暂不支持接入** |

面板里还写清楚了**为什么**要重定向：Agent 自己的会话日志有两种情况 ——
① 直接就是 JSONL（mcode / codex / claude），雷达能直接扫到；
② 压缩格式（DeepSeek harness 的 `.zstd`），压缩流没法按字节增量跟读。

以及重定向之后的**两条接入路径**：

1. 直接用【手动指定日志路径】填那个文件路径；
2. 把日志目录加进「雷达扫描根目录」，让雷达自己找到它。

> 实拍：[`assets/settings-v3.1.0-agent-guide.png`](../assets/settings-v3.1.0-agent-guide.png)

### 3.3 deepseek 那条必须如实

面板里 deepseek 条目写的是**现状**，不是承诺：

> ⚠️ **说清楚现状**：DeepSeek harness 自己的会话日志是 `.zstd` 压缩的，
> 哨兵**能发现它、读出它的工作区和会话 ID**，
> 但**没法实时跟读**（跟读器按字节偏移走，压缩流读不了）。
> 如果它支持 JSONL 输出，就用上面那条重定向命令把输出存成 `.jsonl`，
> 再通过**【手动指定日志路径】**接入；
> **如果它只输出纯文本**，那这条路暂时走不通 ——
> 哨兵拿不到可解析的事件。

**压缩日志「只能发现、不能接入」这个结论一个字没变。**

### 3.4 复制按钮的兜底

浏览器在 CDP / 无焦点场景下会拒绝 `navigator.clipboard.writeText` 和
`document.execCommand("copy")`。此时退回「**把命令选中 + 提示按 Ctrl+C**」——
比只说一句「复制失败」有用。

## 4. 任务三：全局进程守护与 Windows 开机自启

### 4.1 `--daemon` 守护模式

```text
sentinel.exe --daemon --radar --no-browser --no-health
```

**两种「退出」必须分清**：

| 情况 | 行为 |
| --- | --- |
| **正常退出**（Ctrl+C / 页面【退出演示】） | 老老实实结束进程，退出码 0 |
| **异常崩溃**（异常抛出 / 自检判定失效） | 记一条崩溃日志 → 退避 → **重新拉起** uvicorn |

**自检线程**每 30 秒探一次 `http://127.0.0.1:<port>/api/sessions`：

* ⚠️ 用 HTTP 探测而不是只查 `server.started` ——
  才能发现「进程还在、端口还占着、就是不干活了」的**卡死**；
* 启动期不算失败（启动慢不是故障）；
* 连续 3 次探不到 → 置位 `restart_requested` + `server.should_exit = True`；
* 崩溃写 `logs/daemon_crash.log`（带 traceback）。

**退避与上限**：

```text
第 1 次崩 → 等 2 秒 → 第 2 次崩 → 等 4 秒 → … 最长等 30 秒
连续超过 5 次 → 放弃，退出码 1
```

不设上限的话，一个一启动就崩的版本会**无限重启** ——
用户的机器被占满、日志刷屏，还以为中毒了。

### 4.2 `install_startup.bat` 开机自启

仓库根目录，双击即可：

```text
install_startup.bat              安装开机自启
install_startup.bat uninstall    卸载开机自启
install_startup.bat status       看一眼装没装
```

**它做什么**：

1. 在 Windows「启动」文件夹（`shell:startup`）里创建一个快捷方式；
2. 快捷方式指向 `wscript.exe`，由它用 VBS 以「隐藏窗口」的方式拉起哨兵；
3. 开机后哨兵**静默**在后台跑（雷达 + 守护），之前挂载过的会话自动接回来。

### 4.3 为什么不用注册表 Run 键

往 `HKCU\...\Run` 里塞一条，等于**悄悄改了系统设置** ——
用户在「任务管理器 → 启动」里能看到，但大多数人不会去看。

放进「启动」文件夹是**看得见、可随时删**的：打开那个文件夹就能看到快捷方式。

### 4.4 为什么绕一层 VBS

直接把快捷方式指向 exe，Windows 会开一个**黑框终端**。
「开机静默」要的是**连窗口都没有**，所以用 `wscript.exe` 拉起一个 VBS：

```vbs
Set sh = CreateObject("WScript.Shell")
sh.Run """D:\项目\<项目目录>\_构建与发布\dist\sentinel.exe"" --daemon --radar --no-browser --no-health", 0, False
```

第二个参数 `0` = **隐藏窗口**，第三个 `False` = 不等它结束。

### 4.5 踩过的坑：VBS 的静默失败

⚠️ **路径的收尾引号必须写两个**：

```vbs
' 对：
sh.Run """C:\a b\x.exe"" --flag", 0, False
' 错（只写一个）：
sh.Run """C:\a b\x.exe" --flag", 0, False
```

VBScript 字符串内的引号靠**成对**转义。只写一个的话，整行会变成
「**未结束的字符串常量**」—— 而 `wscript.exe` 是**静默失败**：
开机什么都不发生，用户只会以为「自启装上了但没用」。

**这一条现在有自动化测试守着**：测试会把 PS1 里真正在用的那条模板
抠出来、拼一条 VBS、**真的交给 `cscript.exe` 编译一遍**，
有编译错误就当场失败。

同理，VBS 必须用 **UTF-16LE + BOM** 写 —— VBScript 按**系统 ANSI 代码页**
读 `.vbs`，用 ASCII 写的话中文路径会变成一串 `?`
（而且**不报错**，只是找不到 exe）。

PS1 本身也必须存成 **UTF-8 带 BOM** —— PowerShell 5.1 读没有 BOM 的
`.ps1`，中文会变乱码直接解析失败。

### 4.6 踩过的坑：守护模式在隐藏窗口里挂死

⚠️ 「出错后挂住等回车」是给**看得见窗口的人**用的。
而开机自启是**隐藏窗口**跑的 —— **没有人会来按回车**。

实测踩到过：端口被占用时，隐藏启动的哨兵打印完

```text
[127.0.0.1:8000] 端口被占用，请修改端口或关闭已有进程。
[SENTINEL] 请改用别的端口，例如：--port 8001
[SENTINEL] 雷达没能正常启动（退出码 2）。
```

就**永远挂着** —— 开机自启就此失效，而且这个僵尸进程会一直占着内存。

原因：`wait_for_user()` 判的是 `sys.stdin.isatty()`，
而 `sh.Run cmd, 0, False` 拉起来的后台进程**仍然连着一个控制台**，
所以 `isatty()` 是真的，`input()` 就真的在等。

**修法**：守护模式（`--daemon`）**一律不挂住**。
`fatal_guard()` 加了 `wait` 参数，入口脚本的三处「挂住」
都改成「非守护模式才挂」。

修好之后实测：第二个实例打印完提示就**干净退出**
（`HasExited=True`），不再留僵尸。

### 4.8 脚本自己推路径

`install_startup.ps1` 的所有路径都从 `$PSScriptRoot` **自推**
（脚本 → `_构建与发布` → 仓库根），**不从命令行收中文路径** ——
中文路径经过 bat → powershell 的命令行容易被控制台代码页搞坏。

> 打包版和源码模式各有各的挂载历史，**不会**互相污染，
> 也**不会**写进用户被监控的项目目录。

## 7. 还没做的（留个底）

* **zstd 会话的实时接入** —— 跟读器要改成「按解压后长度计偏移」，

  不重启「跟着 Agent 跑的审查引擎」；
* **开机自启的卸载提示** —— 卸载只删文件，不提示「正在运行的哨兵还在跑」。
