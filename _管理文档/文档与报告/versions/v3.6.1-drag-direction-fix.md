## 1. 现象：拖「反」了

v3.6.0 的中间面板被一条横向分隔条切成两段：

```text
┌─────────────────────────────┐
│ 实时告警                     │  ← v3.6.0：告警在上
├─────────────────────────────┤
│ ▬▬▬▬ #resizer-audit ▬▬▬▬▬▬ │  ← 上下分隔条（8px，可拖）
├─────────────────────────────┤
│ 实时审核流水                 │  ← v3.6.0：流水在下
└─────────────────────────────┘
```

用户预期：**往下拖 → 流水区变大、告警区变小**。
实际：**往下拖 → 分隔条往上跑**，流水区反而缩了。

---

## 2. 根因：**不是** `deltaY` 符号写反，是锚点选错了

### 2.1 先排除掉那个「最像」的嫌疑

前端这一行，**符号自始至终都是对的**：

```javascript
// src/gui/static/dashboard.js · bindResizer()
state.layout.audit = clampAudit(startAudit + dy);
```

`dy` 是鼠标 Y 位移，向下为正；`+ dy` 让流水高度**跟着变大**。
**这一行一个字符都没改过**，v3.6.1 也没改它 ——
只在旁边补了一段注释说明「错的不是这里」。

⚠️ 所以「`- deltaY` 写成了 `+ deltaY`」这个诊断 **不成立**。
把它改成 `- dy` 只会得到另一个方向反的版本。

### 2.2 真正的原因：把手挂在了「动不了的那条边」上

中间面板是**固定高度**的纵向 Flex 容器（高度被 Grid 的 `1fr` 钉死、
`overflow: hidden`）。v3.6.0 的子元素顺序是
「告警 → 分隔条 → 流水」，于是：

| 事实 | 后果 |
| --- | --- |
| `.live-audit` 是面板的**最后一个** flex 子项 | 它的**下沿被面板底边钉死**，高度 = `--audit-h` |
| `.live-audit` 是 `flex: 0 0 auto` | 它**不参与剩余空间分配**，高度由变量说了算 |
| 分隔条紧贴在流水的**上沿** | 把手位置 = 流水位置 − 分隔条高 |

把这三条写成一条式子：

```text
分隔条 Y = 面板底边 − 分隔条高 − 流水高
⇒ d(分隔条 Y) = −d(流水高)
```

**导数是 −1。**

也就是说：流水长高 1px，分隔条就被**顶上去** 1px ——
**方向天然与鼠标相反**。

### 2.3 实测坐实（修复前的探针）

用真实鼠标事件（CDP `Input.dispatchMouseEvent`）往下拖 90px，实测：

| 量 | 拖之前 | 往下拖 90px 之后 | 变化 |
| --- | --- | --- | --- |
| 分隔条 top | 741 | 651 | **−90**（往上跑了！） |
| 流水区高度 | 200 | 290 | +90（长度是对的） |
| 告警区高度 | 485 | 395 | −90（长度也是对的） |

⚠️ **关键就在这里**：流水区与告警区的**尺寸变化本来就是对的**，
只有**把手自己的位置**是反的。

> 这也解释了 v3.6.0 为什么「30 项断言全过」却没抓住这个 Bug ——
> 那套断言只量了**流水区盒子高度**，**没有量把手自身位移**。
> 本版把这条验收漏洞补上了（见 §6）。

## 3. 修法：让流水区的**下沿**当把手

把 `.live-audit` 挪到分隔条**上方**：

```text
┌─────────────────────────────┐
│ 实时审核流水                 │  ← v3.6.1：流水在上
├─────────────────────────────┤
│ ▬▬▬▬ #resizer-audit ▬▬▬▬▬▬ │  ← 把手 = 流水的下沿
├─────────────────────────────┤
│ 实时告警                     │  ← v3.6.1：告警在下
└─────────────────────────────┘
```

此时流水区的**上沿**被面板顶边钉死、下沿自由：

```text
分隔条 Y = 面板顶边 + 流水高
⇒ d(分隔条 Y) = +d(流水高)
```

**导数变成 +1**，把手这才跟得上鼠标。

### 3.1 改了什么（三处，一行 JS 逻辑都没动）

| 文件 | 改动 |
| --- | --- |
| `src/gui/templates/dashboard.html` | `#alert-panel` 子元素顺序改为 **`.live-audit` → `#resizer-audit` → `.panel__head` → `.panel__body`**，并把根因与推导写进注释 |
| `src/gui/static/dashboard.css` | `.live-audit` 的 `border-top` → `border-bottom`（分隔线要画在**下沿**）；新增 `.panel--alerts .panel__head { flex: none; }`（告警标题条现在夹在分隔条下面，必须锁死高度，否则空间一紧就被压扁） |
| `src/gui/static/dashboard.js` | **逻辑零改动** —— 仍是 `clampAudit(startAudit + dy)`，只补注释说明「符号一直对、错在布局」 |

### 3.2 为什么 `clampAudit()` 不用改

```javascript
clampAudit(h) → Math.max(LAYOUT_MIN_AUDIT, Math.min(h, 高度 - LAYOUT_MIN_ALERT_AREA - 48))
```

上限算的是「面板总高 − 告警区最小高 − 其它固定高度」，
**与两段的上下顺序无关**（和与差一样）。所以这一版
**没有碰任何高度计算公式**。

### 3.3 左右两条分隔条：零改动

`#resizer-sessions`（会话栏右边）、`#resizer-stream`（日志面板左边）
的 DOM、样式、映射（`+ dx` / `− dx`）**全部原样**，
本版只做回归验证（§6）。

## 4. 代价（**明说**：顺序对调了）

修复的副作用是：**中间列两段的上下顺序对调了** ——
现在是「**实时审核流水在上、实时告警在下**」。

⚠️ 这不是可以两全的事。在**固定高度的堆叠布局**里：

- 把手**贴鼠标**（往下拖把手跟着往下）⇒ 上方面板**变高**，
- 「下方面板长大」⇒ 把手必然**上移**。

这两件事**数学上互斥**（`把手 Y = 面板顶边 + 上段高` 是恒等式，
求导就是 `+1`）。**固定高度 + 把手跟手 ⇒ 只能保一头。**

所以只有两条路：

| 方案 | 把手跟手 | 下方面板长大 |
| --- | --- | --- |
| v3.6.0（流水在下） | ❌ | ✅ |
| v3.6.1（流水在上） | ✅ | ❌（流水在上方时，「下面的板子」是**告警区**） |

⚠️ **说清楚：v3.6.1 之后，往下拖是「流水区长大、告警区变小」**
—— 用户要的「拖哪边哪边大」在**布局换位后**自然成立：
拖的是**流水的下沿**，流水往下长、告警被挤小，
而**流水的下沿就是把手**，把手当然跟手。

### 4.1 其它取舍

- **窄屏断点（980px / 760px）不动** —— 760px 时 `.panel--alerts { --audit-h: 140px; }`
  依然生效，只是流水块出现在告警标题**上方**；
- **`localStorage` 键不动** —— `sentinel.layout.v1` 里存的 `--audit-h`
  语义没变（仍是「流水区高度」），旧布局**继续可用**；
- **会话栏折叠、问答高亮、无极调节渲染全部不受影响**。

### 7.1 本版新增 / 改写的测试

**`tests/test_v361_drag_direction_fix.py`**（**17 条**）钉住了：

- **DOM 顺序契约** —— `live-audit` 必须在 `resizer-audit` **之前**；
- **CSS 契约** —— `.live-audit` 用 `border-bottom`；
  `.panel--alerts .panel__head` 必须 `flex: none`；
  760px 断点仍有 `--audit-h: 140px`；
- **JS 契约** —— `+ dy` 的符号**不许改**（防止将来有人「顺手修一下」改回 `- dy`）；
  左右两条分隔条的映射**不许动**；`LAYOUT_MIN_ALERT_AREA = 120` 不许动；
- **几何模型测试** —— 把导数写成**可执行断言**：
  当前顺序下 `d(把手 Y)/d(流水高)` 必须 **+1**，
  旧顺序下必须 **−1**。
  ⚠️ 这条最有价值：将来谁把流水区挪回分隔条下面，**测试会当场变红**，
  不会再像 v3.6.0 那样「全绿但方向是反的」；
- **演示脚本契约** —— 脚本必须量**把手自身位移**、必须**两个方向都断言**、
  横向行为必须已断言；临时探针脚本**不许存在**在版本库里。

**`tests/test_v352_layout_and_auto_anchor.py`** —— 改写了那条
「流水在告警区之后」的 DOM 顺序契约（v3.5.2 时代写的是
`head < body < live-audit`）。本版按新顺序改成
`live-audit < resizer-audit < head < body`，
并在注释里写明**为什么改**（免得后人以为是误改）。
