# v2.2.2 —— 修复演示模式认知欺骗与监考源显性化

> **一句话**：用户双击 `sentinel.exe` 进了演示模式，
> 看到一屏告警卡片（包括一条**假的「删除文件」红线**），
> 于是以为**哨兵监控到了自己正在独立运行的那个 MCode 进程**。
>
> 界面**没说谎，但也没说全** —— 这就叫**认知欺骗**。
> 用户据此以为「有人在盯着我的真实进程」，
> 甚至以为「哨兵刚刚拦下了一次真实的删除」。
>
> 这一版把「演示」与「真监控」在**视觉上彻底隔离** ——
> **不加功能，只加诚实**。

## 1. 红线：这一版一个字都没改

**本版未新增任何红线修订。** R1–R9 与 v2.1.0 **完全一致**，**一字未改**。

| 改动 | 会不会扩大权限 | 为什么 |
| --- | --- | --- |
| 看板红色横幅 / 斜条纹 / 徽章 | **不会** | 纯前端渲染，**不碰**被监控的任何文件 |
| 终端 6 行演示说明 | **不会** | 只是**打印**文字 |
| 会话名加「[演示]」前缀 | **不会** | 改的是**显示名**，不是行为 |

本版只做了「把已有的事实**说清楚**」，**没有新增任何能力**：

* 哨兵**依然只读**，不写被监控的任何文件；
* 守护者**依然最多挂起进程**，随时可放行；
* 演示模式**依然不接任何真实 Agent** ——
  本版只是把「它不接」这件事**说破**了；
* **没有**新增任何写文件 / 改代码 / 终止进程的路径。

## 2. 任务一：看板上的醒目标识

### 2.1 为什么用「服务端渲染」而不是前端 JS 判断

横幅必须在**第一帧**就在。如果让前端 JS 读一个标志再决定要不要显示，
中间会有几十毫秒的空窗 —— 而用户恰恰可能在那一瞬间扫一眼界面。

所以标志是**服务端**传进模板的：

```python
# src/gui/server.py
def create_app(..., demo_mode: bool = False) -> FastAPI:
    ...
    html = template.render(
        ...,
        demo_mode=demo_mode,      # ← 透传到模板
    )
```

`demo_mode` 是**关键字参数、默认 `False`** —— 现有调用方与测试**一律不受影响**。

### 2.2 看板三层标识（从弱到强）

| 层 | 位置 | 实现 |
| --- | --- | --- |
| ① 背景斜条纹 | 铺满全屏（含面板与底栏） | `body.is-demo` + `background-image` **追加**一层 `repeating-linear-gradient` |
| ② 「模拟数据」标签 | 贴在**假告警**旁边 | 面板标题旁的 `.panel__demo-tag` |
| ③ 红色横幅 + 徽章 | 顶栏，最显眼 | `.demo-banner` + `.chip--demo`（脉冲动画） |

⚠️ 斜条纹用 `background-image` **追加**而不是 `background` 简写 ——
简写会把面板原本的渐变底色一起冲掉。

### 2.3 横幅文案（逐字固定）

```text
⚠ 当前为演示模式，展示的是模拟数据，未监控任何真实进程！
```

这段文案被**回归测试逐字钉死**（`EXPECTED_BANNER_TEXT`），
以后谁想改文案，必须先改测试 —— 这是有意的。

### 2.4 会话名：`[演示] 默认会话`

```python
DEMO_SESSION_PREFIX = "[演示] "
DEMO_DEFAULT_SESSION_LABEL = DEMO_SESSION_PREFIX + "默认会话"
```

* 多会话模式下**同样**统一加前缀；
* **不修改调用方传进来的对象** —— `copy.copy(spec)` 复制一份再改，
  免得把别人的 `SessionSpec` 改坏了；
* 前缀**幂等** —— 已有前缀不会叠加成「[演示] [演示] …」。

### 2.5 真实模式一个都不挂

| 元素 | 真实模式 |
| --- | --- |
| 红色横幅 | ❌ **不渲染**（不是 `hidden`，是模板里根本没有） |
| 斜条纹 | ❌ 无 `is-demo` 类 |
| DEMO MODE 徽章 | ❌ 不渲染 |
| 「模拟数据」标签 | ❌ 不渲染 |
| 「[演示]」前缀 | ❌ 会话名还是「默认会话」 |

## 3. 任务二：终端输出的显性化

### 3.1 打印位置

任务要求「大字报打印完后**紧接着**打印」——
所以就放在 `server.main()` 里 `print_banner()` 的**下一行**：

```python
print_banner()
if demo_mode:
    print_demo_notice()
```

这同时也覆盖了 **exe 双击**那条路 ——
打包入口 `sentinel_entry.py` 的演示分支调的就是 `server.main(demo_args)`，
两边自然一致。

### 3.2 6 行文案（逐字固定）

```text
==================================================
 注意：您当前进入的是【演示模式】！
 我们正在使用模拟数据为您展示功能。
 若要监控真实运行的 Agent，请使用以下命令：
 启动哨兵.bat --agent mcode --cwd "你的项目路径" "任务指令"
==================================================
```

**不只说「这是演示」，还直接给出「怎么用真的」** ——
光说「这是演示」会让用户以为「想用真的还得再找文档」。

文案放在 `src/console.py` 的 `DEMO_NOTICE_LINES` 常量里，
分隔线宽度由 `DEMO_NOTICE_WIDTH = 50` 控制（**不是**手写 50 个 `=`）。

### 3.3 ⚠️ 编码兜底（启动路径上不能炸）

Windows 控制台本身支持中文，但 stdout 一旦被**重定向到文件**，
Python 会退回系统 ANSI 代码页（GBK）——
碰上编不出来的字符就会 `UnicodeEncodeError`。

而这段提示恰好在**启动流程**里：**炸了就等于启动失败**。

所以 `print_demo_notice()` 做了两层兜底：

1. 按流自己的编码写；编不出来就退到**有损**写法（编不出的字符换成 `?`）；
2. 流被关掉（`OSError`）只放弃打印，**不抛给调用方**。

验证脚本：`_构建与发布/scripts/verify_demo_banner.py`
—— 不带任何参数启动打包版 exe（= 用户双击 → 演示模式），
然后查终端的 6 行说明在不在、是不是排在 ASCII 大字报**后面**，
再查看板首页的红色横幅与 `/api/sessions` 里的「[演示]」会话名。

⚠️ 顺带修掉了 `verify_double_click.py` 的一个真 bug：
PyInstaller 单文件模式会**再起一个子进程**跑真正的程序，
只 `terminate()` 启动器的话，子进程会**活下来继续占端口** ——
下一次验证就会撞上「端口被占用」，它的 stdout 还攥着上一个存档文件，
把新存档冲成一堆空洞。现在两个脚本都改用 `taskkill /F /T` 杀**整棵进程树**。
