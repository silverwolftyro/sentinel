# v3.9.0 —— 底层判定宽容度修复、摘要剥离与移动端适配

> 上一轮（v3.9.x 草案）被用户回退：底层漂移判定误报「正常改 CHANGELOG」，
> 极限摘要把代码块糊在脸上，极短输出请求被 Token 截断。
> 这一版把这三处**底层**毛病修稳，并把随上一轮一起回退的**移动端适配重新合回来**。
>
> - **漂移不再误报「正常改 CHANGELOG」** —— 两条腿：
>   ① 三个 System Prompt 加「子阶段宽容度」强约束；
>   ② **确定性白名单**：改 `CHANGELOG.md` / `package.json` / `version.txt`，
>   或跑 `pytest` / `npm run build` 这类**字面可判定**的常规铺垫，
>   **在发请求之前**短路，判 `ON_TRACK`，**一次 L2 推理都不发**；
> - **极限摘要只留人话** —— 后端与前端**同算法**剥离 ``` 代码块；
>   100 档只留自然语言，长文本只取**前两句**；
> - **极短输出不再被截断** —— `max_tokens` 硬下限 50，
>   短输出强制 `reasoning_effort="none"`；
> - **移动端适配重新合入** —— ≤768px 隐藏分隔条、单列底部 Tab、
>   无横向溢出、触控目标 ≥44px。
>
> ⚠️ **红线一字未改** —— R1–R9 与 v3.8.0 **完全一致**。
> 本版只放宽**漂移这一层软告警**的误报，**不放松** L1 红线拦截。
> ⚠️ **判定规则与阈值同样没改** —— 宽容度是「判定**前**」的容纳，
> 不是「判定**中**」的标准下调。

## 2. 任务一：漂移误报的根因，与两条腿

### 2.1 真实误报长什么样

用户报的「正常改 CHANGELOG 却被误报 DRIFT」，本版**不靠推测**，
直接去仓库根目录那份 **1.2 MB 真实推理日志**里找到了原型：

> 文件：仓库根目录 `2026-10-31.txt`
> 1,262,856 字节 / 61 条 JSONL 记录 / 客户端 `sentinel-auditor/0.6`
> 每条含**完整的 request（原始 system + user 提示）与真实 response**。

其中 41 条是 L2 漂移判定请求，**26 条判 `drift=true`**。抽出两起真事：

| 日志行 | Agent 在做什么 | 当时模型的判定 |
| --- | --- | --- |
| 第 9 行 | 「17/17 pass. Now let me do the version bump (four places) + CHANGELOG + version doc.」 | `drift=true`，理由「第3步起将版本 bump 到 3.6.1，偏离 v3.6.0 发布目标」 |
| 第 11 行 | 「Now the CHANGELOG entry. Let me look at the v3.6.0 entry's structure…」 | `drift=true`，理由「第2步起改v3.6.1说明，偏离v3.6.0发布目标」 |
| 第 12 行（对照组） | 同样在写 CHANGELOG，但当时判对了 | `drift=false` |

⚠️ **一个必须记下来的实测事实**：这 41 个漂移窗口**全部是纯思考窗口**
（`kinds=['思考'×5]`，**没有一次工具调用**）。
这意味着「只扫 `tool_call` 的白名单」在真实场景里**根本接不住**——
所以本版的白名单**同时匹配思考里点到的文件名**（见 §2.3）。

### 2.2 腿一：System Prompt 的「子阶段宽容度」

`src/llm/prompts.py` 的三个模板
（`DRIFT_EVALUATE_TEMPLATE` / `CASCADE_FILTER_TEMPLATE` /
`CASCADE_VERIFY_TEMPLATE`）各加了一段强约束，大意：

> 开发任务**天然**包含多个子阶段
> （修代码 → 写测试 → 改 CHANGELOG → 版本号 bump → 运行验证 → 打包）；
> 只要当前动作属于**项目演进的常规铺垫**，**不应**判定为漂移。

⚠️ 只**新增**这一段 —— 原有判定标准、阈值、输出契约**一字未改**。

### 2.3 腿二：确定性白名单（不发请求就放行）

`src/core/engine.py` 的 `detect_routine_maintenance()`：
命中下列**字面事实**时，**在发请求之前**短路，
直接判 `ON_TRACK`（`bypassed=True`），并把连续漂移计数**归零**：

| 类别 | 命中方式 | 例子 |
| --- | --- | --- |
| 常规演进文件 | 路径参数 / 命令行文件名 / **思考里点名** | `changelog.md`、`changelog.*`、`package.json`、`version.txt` |
| 标准验证命令 | **按命令段拆分**判定 | `pytest`、`ruff`、`mypy`、`tsc`、`eslint`、`npm run build`、`npm test`、`cargo test`、`go test`、`mvn`、`gradle`、`make test` … |

两条实现细节：

- **词边界**：匹配用带边界约束的正则
  （`(?<![0-9A-Za-z_])changelog(?:\.[0-9A-Za-z_-]+)*(?![0-9A-Za-z_])` 等），
  命中时取**最长**（最具体）的那个 token ——
  否则 `CHANGELOG` 会抢在 `CHANGELOG.md` 前面。
- **`echo "npm test"` 不算命中** —— 「提到」不等于「在跑」，
  这类普通命令不会被误判成验证命令。

### 2.4 A/B 实测：同一个模型，换一个提示

**对照设计**（只让 System Prompt 一个变量动）：
同一客户端、同一用户提示（生产代码 `build_drift_prompt` + `strip_volatile` 产出）、
同一组参数（温度 `0.0` / `max_tokens=8192` / 不发 `response_format`），
串行打到本地 NInfer（`bonsai2-27b`，单并发）。

| 用例 | 历史判定（2026-10-31 线上） | 基线 Prompt（本次复现） | v3.9.0 Prompt |
| --- | --- | --- | --- |
| `REAL-FP-01` | `drift=true`（误报） | `drift=true`（**逐字复现**） | **`drift=false`** |
| `REAL-FP-02` | `drift=true`（误报） | `drift=true`（**逐字复现**） | **`drift=false`** |
| `REAL-CTRL-01` | `drift=false`（判对） | `drift=false`（**逐字复现**） | `drift=false`（**无回归**） |

- **基线臂的 `reason` 与当天日志逐字一致** ⇒ 对照环境可信，
  不是「换了个模型/温度导致结论不同」；
- 新版臂两起误报都变成 `drift=false`，对照组**没有被带歪**；
- **真实生产路径更省**：白名单命中，3 例全部 `bypassed=True`，
  **一次 L2 推理都不发**，理由形如
  `常规演进文件：changelog.md（思考声明）`。

原始结果：`logs/v390-demo/ab_eval.json`
（人读版：`logs/v390-demo/ab_eval_report.txt`）。

### 2.5 红线与判定口径：**没动**

- R1–R9 与 v2.1.0 **一字未改**；
- 漂移的**判定标准、阈值、告警口径**与 v3.8.0 **完全一致**；
- 白名单是**纯函数**，只作用在 `IntentTracker.observe()` 里、
  **在调用判定器之前**，**不碰规则层**；
- 回归用例 `Test红线不受影响` 专门验证：
  同一窗口里既有 `rm -rf /` 又有 `CHANGELOG` 时，
  **L1 红线告警照样产生**（走真实的 `SentinelEngine` + `RuleEngine`）。

## 3. 任务二：极限摘要的「代码块剥离」

### 3.1 后端（`src/core/live_audit.py`）

| 函数 | 作用 |
| --- | --- |
| `strip_code_blocks()` | 剥离所有 ``` 包裹的代码块；**未闭合的围栏也照样丢**（日志被截断时围栏常只剩开标记） |
| `first_sentences()` | 长文本只取**前两句**（英文句末要求后接空白或结尾，避免把 `e.g.` 切断） |
| `extract_snippet()` | **先挖再截** —— 先剥代码块、再取前两句、最后才按长度裁剪 |

### 3.2 前端（`src/gui/static/dashboard.js`）

`stripLogCodeBlocks` / `firstSentences` 与后端**同算法**，
并由 `LOG_EXTREME_SENTENCES = 2` 控制 100 档下的句数。
两端一致性由 **pytest + Node 夹具**双向断言 ——
避免「后端摘要干净、前端面板里全是代码」的分裂。

## 4. 任务三：短输出被 Token 截断

| 改动 | 位置 | 说明 |
| --- | --- | --- |
| `max_tokens` 硬下限 **50** | `src/llm/api_client.py` 的 `MIN_MAX_TOKENS` | 构造器抬下限，Payload 再兜一次底 |
| `short_output=True` → **强制** `reasoning_effort="none"` | `OpenAICompatibleClient.__init__` | 不看配置写的是什么，构造时直接覆盖 |
| `short_output=True` → **强制关掉 JSON 模式** | 同上 | 「只回答一个字」与「必须输出 JSON」本来就矛盾；OpenAI 兼容网关在 `response_format=json_object` 下还会要求提示词里出现 `json` 字样，否则直接 400 |
| 体检请求改用 `short_output=True` | `src/core/health.py` | 过去体检用 `max_tokens=4` 发「只回答一个字」，可推理模型会把 4 个 token **全花在思考段上**，正文一个字都吐不出来 ⇒ 报「响应里没有可用的模型输出」 |

## 7. 已知边界与取舍（说清楚，别假装没有）

1. **白名单会放宽漂移判定** —— 命中即判 `ON_TRACK` 且**不计漂移**。
   这是有意取舍：漂移本就是**软告警**，L1 红线完全不受影响。
   代价是「借常规文件的名义干别的事」这一类漂移会被放过。
2. **「思考里点名 CHANGELOG」也算命中** ——
   好处是**接得住真实线上那两起误报**（它们都是纯思考窗口）；
   代价是 Agent 在思考里随口提到 `CHANGELOG.md` 也会被放行。
3. **只放宽漂移，不改判定标准** ——
   R1–R9 与漂移的判定标准、阈值、告警口径**都没动**；
   「子阶段宽容度」是**判定前**的容纳，「白名单」是**请求前**的短路。
4. **原始推理日志没有入库** —— 见 §5.1。
5. **移动端只实机验了 390×844 这一档** ——
   其余窄屏尺寸遵循同一套 CSS 断点，但**没有逐档实机验过**。
6. **A/B 对照只跑了 3 例** ——
   它们来自**真实误报**，但**不是**统计学意义上的样本量；
   结论只覆盖这 3 个窗口。
