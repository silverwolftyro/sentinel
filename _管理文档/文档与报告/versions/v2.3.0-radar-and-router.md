## 1. 红线：这一版一个字都没改

**本版未新增任何红线修订。** R1–R9 与 v2.1.0 **完全一致**，**一字未改**。

本版做的是「**看得见**」与「**说得清**」，**没有新增任何权限**：

* 哨兵**依然只读** —— 挂载进来的日志一个字节都不会被改；
  挂载会话的告警日志落在哨兵自己的 `logs/attached/` 下，
  **绝不**写进用户正在跑 Agent 的那个项目目录；
* 守护者**不跟着挂载走** ——
  守护者会真的挂起被监控进程，而挂载进来的会话我们并不清楚
  那个进程到底是不是用户的 Agent —— 宁可少一个能力，
  也不能在**没弄清对象**的时候动手（R7：留痕、可否决）；
* 设置页**只能改配置**，不能改哨兵的行为边界；
* **没有**新增任何写文件 / 改代码 / 终止进程的路径。

## 2. 任务一：CLI 进程与日志的「雷达发现」

### 2.1 为什么是「旁路监听」而不是「拦截 stdout」

强行拦截一个**已经在跑**的进程的 stdout，在操作系统层面几乎不可能：
那个进程的 stdout 早就绑在它的管道上了，
另一个进程插不进去，也**不该**插进去。

所以哨兵退一步，走**日志发现**：

```
你早就在自己的终端里跑着 Agent
        ↓  它正在写 ~/.codex/sessions/…/rollout.jsonl
哨兵扫这些目录，找到「最近还在被写入」的那份
        ↓  你在看板点一下「接入」
哨兵从文件尾部开始实时跟随（tail -f 语义）
        ↓  Agent 每写一行，哨兵立刻审一次
红线卡片出现在看板上
```

**你的 Agent 该怎么跑还怎么跑** —— 哨兵只**读**它的日志。

### 2.2 `src/radar.py`（新叶子模块，纯标准库）

| 函数 | 职责 |
| --- | --- |
| `agent_roots(home)` | 要扫的目录：`~/.codex` / `~/.mcode` / `~/.claude` + 环境变量 `SENTINEL_RADAR_ROOTS` 追加的任意目录 |
| `scan_agent_sessions(...)` | 递归找出最近还在被写入的 `.jsonl` / `.json` / `.log`，按 mtime 倒序 |
| `detect_agent(path, lines)` | **认出它是谁**（路径特征 + 内容特征双重判定） |
| `extract_cwd(path, lines)` | **提取工作区**（`cwd` / `workspace` / `project_root` …） |
| `format_label(agent, cwd)` | 拼成 `[Codex] D:\work\project_alpha` |
| `describe_session(path)` | 把上面几件事合成一条描述 |

### 2.3 识别：codex 与 mcode 长得极像

两者都用 v0.6 的 `item.*` 事件溯源协议，**唯一可靠的区别**是：

| | mcode | codex |
| --- | --- | --- |
| 工具调用藏在哪 | `item.toolCall` | **直接在 `item` 上** |
| 工具名 | `item.toolCall.name` | 由 `item.type` 推断 |
| 命令 | `item.toolCall.input.command` | `item.command` |

所以判定规则是：**`item` 里有 `toolCall` 键 → mcode；没有 → codex**。

另外还有几个特征：

* `thread.*` / `turn.*` → 一定是 codex；
* `message.content` 数组 + `tool_use` 块 → claude；
* `system` + `subtype: init` + `session_id` → claude。

### 2.4 看板上的挂载入口

左侧会话列表上方多一个【**＋ 发现/挂载进程**】按钮：

* 弹窗里列出扫到的活跃日志，标着「**正在写入** / 已静默」，
  点【接入】就实时挂上；
* 同时有一个**手动路径框** ——
  用户自己重定向了输出时（`mcode ... > session.jsonl`）用得上；
* 挂过的文件会标成「已接入」，**不会**被挂两次
  （挂两次会产生两份告警）。

对应接口：`GET /api/discover`、`POST /api/attach`、
`DELETE /api/sessions/{id}`。

### 2.5 挂载会话的告警日志落在哪

落在哨兵自己的 `logs/attached/<名字>-<摘要>.alerts.jsonl` ——
**绝不**写进用户正在跑 Agent 的那个项目目录（红线 R1：只读）。

## 3. 任务二：会话分类与元数据识别

| 情况 | 会话名 | 监控目标面板 |
| --- | --- | --- |
| 认出是 codex 且挖到 cwd | **`[Codex] D:\work\project_alpha`** | `[Codex] D:\work\project_alpha` |
| 认出是 claude 但挖不到 cwd | **`[Claude] 未知工作区`** | `[Claude] 未知工作区` |
| 完全认不出 | `默认会话` | `–` |

⚠️ **提取不到就说「未知工作区」** —— 不许假装知道。

### 3.1 顺带修掉的一个真问题

以前 `--watch` 一律用 **mcode 适配器**解析 ——
拿它去审 Codex 的日志，字段名对不上，**整路漏审**。

现在按日志**内容**自动选适配器（`adapter_name="auto"`），
认不出来才退回最宽容的 mcode。

## 4. 任务三：Web UI 路由化大重构

### 4.1 两条真实的路由

| 地址 | 页面 |
| --- | --- |
| `/` | **主看板** —— 实时监控 / 告警流 / 时间线 |
| `/settings` | **独立全屏**的设置页 |

设置页**不是**抽屉、**不是**弹窗、**不是**模态框 ——
它有自己的 URL，可以直接收藏、直接分享、刷新也不丢。

### 4.2 前端路由（`src/gui/static/router.js`）

原生 History API：

1. 拦截 `a[data-nav]` 的点击；
2. `fetch` 目标页面 → `DOMParser` 解析；
3. 换掉 `document.body`（**以及 head 里的页面级样式**）；
4. 重新执行新页面自己的 `<script src>`；
5. 调用新页面的 `init()`。

**页面契约**：每个页面脚本暴露 `window.SentinelPage = { init, destroy }`。
`destroy()` 负责关掉 EventSource 与定时器 ——
不收摊的话，离开看板以后后台还在轮询、还在收 SSE。

### 4.3 设置页的四块

| 分区 | 内容 |
| --- | --- |
| ① 模型路由（L2） | 主力 provider / base_url / model / 超时 / 阈值；高级项（脱敏、熔断、采样、密钥）；降级策略（路由开关、漂移阈值、降级模型） |
| ② 通知通道 | 每个通道的类型 / 启用 / 地址 / 格式 / 密钥 / 超时；Webhook 有【**测试**】按钮（**真发**一条消息） |
| ③ L1 规则 | 高危命令正则（大文本框，一行一条）、红线类别复选组、热重载开关 |
| ④ 挂载管理 | 当前被监控的会话：名字、Agent、工作区、**日志路径**、状态 + 【卸载】 |

底部 sticky 条：【**保存并应用**】+【重新载入】+ 状态区。

### 4.4 「保存并应用」做了什么

```
POST /api/config
   ↓
把表单翻译成 (yaml 路径, 新值) 列表
   ↓
config_loader.save_config()
   ├─ 先备份 config.yaml.bak
   ├─ 外科手术式改写：只改目标键的**值**
   │    注释 / 空行 / 缩进风格 / 换行风格 —— **全部保留**
   └─ 找不到的键 → 记进 skipped，**绝不新增**
   ↓
触发热重载（RuleHotReloader.reload_now）
   ↓
响应：applied / skipped / backup / reloaded / message
```

⚠️ **为什么不用 `yaml.safe_dump` 整体重写**：
那会把用户精心写的**中文注释全部抹掉**。
`config.yaml` 里的注释是用户的主要参考，抹掉它是不可接受的回归。

⚠️ **密钥怎么处理**：
服务端下发时把 `api_key` / `secret` / `token` 打码成 `********`；
前端显示为空、但**记住**这个打码值；
保存时若用户没动，就**原样回传** `********`；
服务端识别出打码值就**跳过** ——
**绝不会**把用户真正的密钥用 `********` 覆盖掉。

## 6. 已知限制

- **挂载进来的会话拿不到守护者** ——
  哨兵不敢在没弄清对象的情况下挂起别人的进程（R7）；
- **挂载会话没有任务目标** ——
  意图漂移检测需要目标锚点，挂载进来的会话**暂不支持**漂移判定；
- **新增 / 删除通知通道的写回按序号定位** ——
  删中间一项会让后面的通道前移覆盖，
  真要删请手工改 `config.yaml`（设置页已就此给出提示）；
- **钉钉 / 飞书的真实 Token 仓库里仍然没有**；
- **Claude 适配器仍未实机验证**（本次的 Claude 会话是**按格式仿造**的）。
