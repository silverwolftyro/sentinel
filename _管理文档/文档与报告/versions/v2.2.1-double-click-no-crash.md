## 2. 任务一：双击 exe 不再闪退

### 2.1 根因（复现出来的，不是猜的）

v2.2.0 的打包入口长这样：

```python
if not args or "--demo" in args:
    ...
    return int(server_main(list(args)) or 0)     # ← args 为空时就是 []
```

而看板的解析器只认两个参数：

```python
if not args.demo and not args.watch:
    parser.error("必须给 --watch <日志路径>，或用 --demo 进演示模式。")
```

`parser.error()` 会打印用法然后 **`sys.exit(2)`**。
所以双击时：体检报告打完了 → 参数报错 → **窗口瞬间消失**。

⚠️ 讽刺的是，代码里的注释**已经写对了**：

> ⚠️ `--demo` 必须**原样传下去** —— 看板自己认这个开关，摘掉它就会报「必须给 --watch」。

问题正是**无参数时压根没把 `--demo` 加上**。

### 2.2 修法

```python
demo_args = list(args)
if "--demo" not in demo_args:
    demo_args.append("--demo")      # ← 无参数时补上
```

### 2.3 与 `启动哨兵.bat` 对齐

`启动哨兵.bat` 的无参数分支传的是：

```bat
"%PYEXE%" %PYARGS% -m src.gui.server --demo
```

所以两边现在**行为完全一致**：无参数 → 演示模式。

### 2.4 顺带挖出来的第二个坑

exe 入口会把 `--no-health` 透传给看板，
但看板的解析器**不认识这个参数** → 又是一次闪退。
已补上 `--no-health` 选项（看板演示模式下据此跳过体检）。

## 3. 任务二：致命错误不闪退

### 3.1 三个新函数（在 `src/console.py`）

| 函数 | 干什么 |
| --- | --- |
| `report_fatal(exc)` | 把致命错误说成**人话**：原因 + 三条常见原因 + 「窗口不会自己关」 |
| `wait_for_user(msg)` | 出错后**挂住**等用户看完 |
| `fatal_guard(func, ...)` | 把上面两件事包成一层「**绝不闪退**」的外壳 |

放在 `src/console.py` 是因为它是**叶子模块**（只用标准库），
而打包入口与看板服务**都要**用它 ——
各写一份的话，两边很快就会长得不一样。

### 3.2 兜住三类情况

| 情况 | 处理 |
| --- | --- |
| 未捕获异常 | 打印人话提示 → 挂住 → 返回 1 |
| `SystemExit`（argparse 的参数错误走这条路） | 退出码非 0 时挂住；**0 则正常退出** |
| 看板起不来返回非零码（**端口被占**） | 打印「哨兵没能正常启动（退出码 2）」→ 挂住 |

### 3.3 ⚠️ 只有真终端才挂起

```python
if not sys.stdin or not sys.stdin.isatty():
    return
```

被管道 / 脚本调用时如果也等，**调用方会被挂住** ——
那比闪退更糟。所以判据是 `sys.stdin.isatty()`。

### 3.4 Ctrl+C 不算错误

`KeyboardInterrupt` → 打印「已中断」→ 返回 130，**不挂住**。

## 4. 任务三：体检报告只打一份

### 4.1 根因

一次启动里**不止一个地方**想体检：

```
sentinel.exe（无参数）
   ├─ sentinel_entry._startup_health()   → 打一份
   └─ server.main()（演示模式）          → 又打一份
```

两份统计**还不一样** —— 因为检查的**工作目录不同**
（一个用 `os.getcwd()`，一个用会话自己的目录），
于是终端上会出现「正常 0…」和「正常 1…」两行，用户会以为哨兵出了两次问题。

### 4.2 修法：进程级守卫

`src/core/health.py` 新增：

```python
run_startup_health_check(config, *, workdir="", skip_network=False, printer=None)
```

* **一个进程只跑一次** —— 第二次调用直接返回第一次的结果，
  **连网络请求都不重复发**；
* **只打印一次** —— 报告的「正常 X · 警告 X…」那行也只有一行。

现在三条启动路径（exe 入口 / 看板演示模式 / 真实接管启动器）
**全部**走这个守卫，结构上就不可能打两份。

### 4.3 「先把标记置位，再打印」

```python
_STARTUP_DONE = True          # ← 先置位
safe_print(text)              # ← 再打印
```

万一打印本身炸了，下一次调用也**不会**再试一遍 ——
那就又变成两份报告了。

## 6. 已知限制

- **体检报告的「快照排除规则」看的是启动时的当前目录** ——
  双击 exe 时那个目录是 **exe 所在目录**，不是你的项目目录；
  想体检真实项目目录，用 `--cwd <目录>` 走真实接管模式；
- **「挂住等回车」只在真终端下生效**（刻意的，见 §3.3）；
- **看板起不来时退出码仍是 2** —— 但窗口会**挂住**等用户看完；
- **钉钉 / 飞书的真实 Token 仓库里仍然没有**；
- **Claude 适配器仍未实机验证**。
