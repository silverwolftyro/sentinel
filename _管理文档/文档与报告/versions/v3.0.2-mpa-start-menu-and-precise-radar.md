## 1. 红线：这一版一个字都没改

**本版未新增任何红线修订。** R1–R9 与 v2.1.0 **完全一致**，**一字未改**。

v3.0.2 做的是**交互形态**与**筛选口径**的改造，不是**能力扩张**。逐条对照：

* 哨兵**依然只读** —— 雷达新增的 `.dsh/sessions` 只是**多读一个目录**，
  读的还是用户**自己**的 DeepSeek harness 会话日志；
* 守护者**依旧要用户亲手武装** —— 本版**完全没碰**武装逻辑；
* **没有**新增任何写用户文件 / 改用户代码 / 终止用户进程的路径；
* 启动菜单里的 `[3] 接管并启动新的 Agent` 走的是
  v2.x 就有的那条管道（`run_with_sentinel.py`），**不是新加的能力**；
* 压缩日志（zstd）的「接入」按钮**直接禁用**、
  服务端 `/api/attach` **明确拒绝**（400 + 说明）——
  **绝不给半成品按钮**，那比不给更糟；
* 配置写回仍然只用 `config_loader.save_config()`
  （外科手术式，保留注释，写前备份 `.bak`）；
* 代码卫生只动哨兵**自己**的代码，**不碰**用户项目。

> ⚠️ 唯一新增的「写」是**剪贴板** —— 用户点【复制命令】才写，
> 写的是那条**用户自己想复制**的命令。

## 2. 任务一：彻底分离的设置页（多级路由）

### 2.1 v3.0.1 为什么还是挤

v3.0.1 把设置页改成了「左边 240px 导航 + 右边全宽内容」，
但**四个分区仍然在同一个 HTML 里**，
靠前端 `switchSection()` 切显示。

于是「切页」变成了「显示 / 隐藏」：

* **URL 从头到尾都是 `/settings`** —— 收藏不了、分享不了、
  后退键不工作、刷新不记得你翻到哪一页；
* 四段内容**全在 DOM 里**，浏览器要把它们**全量渲染**；
* 卡片**挤成一条**的根因没被彻底解决 ——
  `.settings-section > .panel__body` 虽然被覆盖了，
  但**同页**布局里那个「只显示一个」的机制本身就是脆弱的。

### 2.2 做了什么

| 动作 | 说明 |
| --- | --- |
| 设置主页 | `/settings` 现在是**干净的菜单列表**（四张卡片墙），不塞任何表单 |
| 四个子页面 | `/settings/llm`、`/settings/webhook`、`/settings/rules`、`/settings/sessions` |
| 左侧菜单 | 从 `<button data-target>` 改成**真链接** `<a href="/settings/xxx" data-nav="/settings/xxx">` |
| 模板拆分 | `settings_base.html`（基座：布局 + 样式） + 5 个页面模板 |
| 脚本拆分 | 旧的 `settings.js` **已删除** → `settings_common.js` + 5 个页面脚本 |
| 溢出 | `.settings-page > .panel__body { flex: none; overflow: visible }` 保留 |

### 2.3 为什么用 `router.js` 拦 `a[data-nav]`

设置页的 head 里加了 `<script src="/static/router.js">`。
路由器本来就负责「拦 `a[data-nav]`、用 `fetch` 换页、
`pushState` 改 URL、支持后退」——
v3.0.1 的设置页**没带**它，所以那时只能整页跳转。

带上之后：

* URL **真的变**（`/settings` → `/settings/llm`）；
* 右侧是**全新渲染**的页面，**只有该功能**的内容；
* 后退键可用、刷新记住位置、链接可收藏。

## 3. 任务二：启动时的显式选择与雷达精准过滤

### 3.1 启动菜单

双击 `sentinel.exe`（无参数）**不再直接进演示**，
终端里先打印三个选项：

```text
============================================================
 哨兵 Sentinel —— 你想让它做什么？
============================================================

 [1] 启动演示模式 (体验界面)
       全是模拟数据，不碰你的任何进程。

 [2] 开启雷达 (扫描已有的 Agent 日志)
       只读你自己机器上的 Agent 会话日志 —— 推荐。

 [3] 接管并启动新的 Agent
       边跑边审：告警当场拦下。

============================================================
请输入 1 / 2 / 3 后回车（直接回车 = 2）：
```

**设计取舍**：

* **默认选项是 `[2] 开启雷达`** —— 不问就默认给「**真实的东西**」
  比默认给「假的」诚实；
* **非交互环境绝不阻塞** —— CI / 后台服务里没有终端可输入，
  挂在那儿等一个永远不来的按键是最糟糕的体验；
  这时直接用默认值，并**明确打印**「已按默认选择 [2]」；
* **管道与文件重定向也认**（`echo 2 | sentinel.exe`、
  `sentinel.exe < choices.txt`）——
  管道另起线程读，最多等 1.5 秒，等不到就回落默认值；
* **去掉 UTF-8 BOM** —— Windows 上重定向常带 BOM，
  不去掉的话明明写了 `1` 却选了默认项。

`启动哨兵.bat` 的无参数分支同步改成调 `sentinel_entry.py`
（以前写死 `python -m src.gui.server --demo`）。

> 实拍：[`assets/console-v3.0.2-start-menu.png`](../assets/console-v3.0.2-start-menu.png)

### 3.2 雷达：默认只报「正在写入的」

| 改动 | 之前（v3.0.1） | 现在（v3.0.2） |
| --- | --- | --- |
| 默认口径 | 扫到的一切（前端再过滤） | **服务端** `active_only=1`，只返回正在写入的 |
| 静默文件 | **照样读**（读头部才知道） | **连读都不读**（按 mtime 先筛） |
| 一次扫描耗时（本机实测） | **12.1 秒** | **0.05 秒**（活跃）/ 0.2 秒（全量） |
| `.codex` 优先级 | 排**第一** | 排**最后** |
| `.minimax/v2/sessions` | 在清单里 | 排**第一** |
| `.dsh/sessions` | **不在** | 排**第二** |
| 扫描预算 | 全局一份 | **每个根各一份** |
| 列表顺序 | mtime 倒序 | 活跃 → 根优先级 → mtime，且**各根轮流出场** |

**为什么 `.codex` 要降优先级**：实地核对过 ——
`~/.codex/sessions` 里绝大多数是**早就跑完**的历史 rollout，
它们 mtime 更新的概率低，但**数量压倒性地多**；
以前全局一份预算被它吃光，
`.minimax` / `.dsh` **一个都轮不上**。

**为什么每个根各一份预算**：这是「`.codex` 吃光预算」的同一个病根。
改完之后，谁也挤不掉谁。

**为什么各根轮流出场**：即使预算分开了，
按 mtime 全局排序仍会让「历史文件最多的那个根」霸占整页。
轮流取之后，界面上能同时看到 MiniMax / DeepSeek / Codex 三家的会话。

### 3.3 DeepSeek harness：zstd 压缩日志能读

实地核对到的真实布局：

```text
~/.dsh/sessions/<项目编码目录>/session-<uuid>/session.v4.jsonl.zstd
```

解压后首行：

```json
{"type":"session","version":4,"id":"session-964b189b-…","createdAt":1792600830272,"cwd":"D:\\项目","isSeeded":false,"delegationDepth":0,"agentPreset":"standard"}
```

于是：

* `cwd` → **工作区**（`D:\项目`、`D:\Blender\blender-dsh` …）；
* `id` → **会话 ID**（去掉 `session-` 前缀，只留 UUID，
  这样内容里取到的和路径里取到的是同一个字符串）；
* `createdAt` → **首条时间**；
* 解压用 Python 3.14 内置的 `compression.zstd`（PEP 784）**流式**读头部，
  只解压到够用的字节数，不整读（会话日志能有好几 MB）。

**⚠️ 压缩日志只能「发现」，不能「接入」**

跟读器（`src/tailer.py`）记的是**原始字节偏移**，
压缩流**没法按字节增量读** —— 硬接进去只会得到一堆乱码。
所以：

* 界面给它挂一个橙色徽章「**zstd 压缩 · 暂不支持接入**」，
  按钮**直接禁用**；
* 服务端 `POST /api/attach` **明确拒绝**（400 +
  「这是压缩日志（zstd），只能被发现，暂不支持接入实时审查。」）。

> 这是**如实降级**，不是半成品。v3.0.2 **没有**做 zstd 增量解压。

## 4. 任务三：终端与 Web 双重说明

「挂载管理」子页面（`/settings/sessions`）里有一段说明
+ 一条**可一键复制**的命令：

```text
sentinel --agent codex --cwd "D:\项目\<项目目录>" "你的任务指令"
```

说明里写清了「**怎么开一个带日志输出、而且雷达能准确定位到的 Agent 任务**」：

* 它落在**默认扫描目录**里；
* 日志**正在被写入**（不是早就跑完的历史文件）；
* 日志里**写清了工作目录**（`cwd`）。

**为什么这条命令「三样都满足」**：
`--cwd` 让 Agent 在指定目录里干活，
日志由 Agent 自己写到标准位置，
工作目录会写进日志的首行 —— 雷达一眼就能认出「这是我刚才跑的那个任务」。

**复制怎么实现的**：

1. `navigator.clipboard.writeText`；
2. 不可用（不是安全上下文）→ `document.execCommand("copy")`；
3. ⚠️ 浏览器仍然拒绝（文档没焦点 / 没有用户手势）→
   **把命令选中**并提示「按 Ctrl+C」——
   比只说一句「复制失败」有用。

> 实测（CDP 点击 + 回读）：
> 自动复制被拒时按钮变为「**已选中，按 Ctrl+C**」，
> 提示「浏览器拒绝了自动复制 —— 命令已选中，按 Ctrl+C 复制即可。」，
> `window.getSelection()` 读回的正是那条完整命令。

## 5. 踩过的坑（留档）

### 5.1 「主日志白名单」把自定义目录扫空了

第一版用「文件名必须命中主日志规则」的白名单做预筛，
结果自定义扫描目录里那些名字不规范的会话日志
（`rollout.jsonl`、`old.jsonl`）被**全部漏掉** ——
雷达直接扫不到东西。

**改成黑名单**：只标出「明确知道是附属文件」的那几个名字
（`history-catalog.json` / `llm-call.json` / `user-message-locators.jsonl` /
快照等），它们**照样会被扫到**，只是**排在后面读**。

> ⚠️ v3.0.1 的契约（附属文件也返回，只是标成 `primary=False`）**没有变**。

### 5.2 一个根吃光全局预算

`MAX_CANDIDATE_FILES` 是**全局**一份。
`~/.minimax/v2/sessions` 下面有 4238 个文件，
`.codex` 下面更多 —— 轮到 `.dsh/sessions` 时预算早没了，
**DeepSeek 的会话一个都没被扫到**。

改成**每个根各一份**（`MAX_CANDIDATE_FILES_PER_ROOT`）后，
谁也挤不掉谁。

### 5.3 「没有终端可输入」不等于「没有输入」

第一版只看 `isatty()` —— 管道输入被**直接忽略**，
`echo 1 | sentinel.exe` 选不了 1。
现在按流的类型分别处理：

| 输入 | 处理 |
| --- | --- |
| TTY | 正常等按键 |
| 普通文件 | 读到 EOF（不阻塞） |
| 管道 | 另起线程读，最多 1.5 秒 |
| 字符设备（NUL）/ 套接字 | 当作「没有输入」 |

## 8. 还没做的（留个底）

* **zstd 会话的实时接入** —— 跟读器要改成「按解压后长度计偏移」，
  v3.0.2 **没做**；
* **DeepSeek 目录名解码** —— `~/.dsh/sessions/` 下的目录名是编码过的
  （`--D-~9879~76EE--` = `D:\项目`），
  但会话头里**已经有 `cwd`**，所以**没做**路径解码；
* **mcode 会话的工作目录** —— `messages.jsonl` 里**确实没有** `cwd`，
  只能退到「父目录名 + 文件名」；
* **雷达的进程反查** —— v3.0.1 的第三档回退链仍然在，
  但实测里**很少命中**（日志自带 `cwd` 就够用了）。
