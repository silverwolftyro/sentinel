# v3.3.2 —— 雷达活跃进程感知 · 快捷重定向命令

> 这一版做三件事，全部来自**用户实测反馈**：
>
> 1. **雷达增加「活跃进程感知」** ——
>    用户在终端里跑着一个**真实的** MCode 任务，看板却抓不到它。
>    根因是：**雷达扫的是文件**，而那个 Agent 没把输出重定向成文件。
>    这一版让雷达**同时扫进程** —— 发现「本机有正在跑的 Agent，
>    却对不上正在监控的日志」时，在看板**左侧**亮起橘黄提示，
>    并给出可点击的引导；
> 2. **挂载管理页提供「快捷重定向命令」** ——
>    用户不知道该去哪儿找日志路径。
>    这一版给出一条**针对当前这台机器**的可复制命令，
>    照着跑，输出就落到哨兵认得的文件上；
> 3. **发布 v3.3.2** —— 文档、CHANGELOG、实拍图、exe、Git 标签。
>
> ⚠️ **红线一字未改** —— R1–R9 与 v2.1.0 **完全一致**。
> 这一版只做了两件事：**多显示一条提示**、**多给一条命令**。
> 哨兵依然只读，不碰别人的进程，不自动接管任何东西。

- **「检测到活跃进程」不是「哨兵要接管它」** ——

  哨兵不会自动去读那个进程的输出，也不会自动把它拖进监控。

## 2. 任务一：雷达的「活跃进程感知」

### 2.1 问题出在哪

雷达扫的是**文件**：`.codex` / `.mcode` / `.claude` 这些目录里
正在被写入的会话日志。

问题是：**Agent 在终端里跑着，不等于它的输出落成了文件。**

用户跑 `mcode exec "任务"`（不重定向），终端里滚得飞快，
但磁盘上**没有任何新文件** —— 雷达扫一圈，什么都没有。
看板于是安安静静，用户以为哨兵没在工作。

### 2.2 这一版怎么做的

雷达扫文件的同时，**再扫一遍进程表**：

```
用户终端跑着 mcode ──→ 进程表里有 ──→ 但没对应的日志被挂载
                       │
                       └─→ 看板左侧亮起橘黄提示 + 引导
```

- 后端：`src/procscan.py` 新增 `scan_agent_processes()`；
- 接口：`GET /api/process_activity`；
- 前端：看板左侧 `#radar-alert`，每 10 秒拉一次。

### 2.3 关键决定一：两层信号**缺一不可**

只看进程名是不够的 —— 各大 Agent CLI 大多是 Node 应用，
进程名就叫 `node.exe`，**满机都是**。
只看命令行宽泛片段也不够 —— 本机实测踩过这个坑：

```
npx-cli.js -y rea-agents@6.4.0 mcp
```

它跑在 `.minimax-code\runtime` 目录下，一度被误判成 Agent。
那会让提示变成「狼来了」：用户点进来发现是假的，就再也不信了。

所以判一个进程是不是 Agent，**两条都要满足**：

| 层 | 条件 | 例子 |
| --- | --- | --- |
| ① 进程名 | 在 `AGENT_HOST_IMAGES` 里 | `node` / `node.exe` / `mcode.exe` |
| ② 命令行 | 命中该 Agent 的**特征** | `@minimax-ai/code`、`@openai/codex`、`@anthropic-ai/claude-code` |

⚠️ 特征**只认包名与命令名**，**不认运行时目录名** ——
运行时目录是所有 Node 应用共用的，拿它当特征等于没筛。

### 2.4 关键决定二：同一 Agent + 同一目录 = **一个**进程

Agent CLI 常带子进程。用户关心的是「**有几个任务在跑**」，
不是「有几个 node 进程」。

所以同一 Agent 在**同一工作目录**下的多个进程合并成一个。

### 2.5 关键决定三：「有没有被监控」用**三条**信号

这是整个功能的判断核心。信号从**确定**到**推断**：

| # | 信号 | 确定度 | 命中条件 |
| --- | --- | --- | --- |
| 1 | `cmdline` | **确定** | 进程命令行里带着某个正在监控的日志路径（重定向场景） |
| 2 | `cwd` | **确定** | 会话工作目录 == 进程工作目录（同一个项目） |
| 3 | `recent` | **推断** | 同类型 Agent 的日志**落在雷达扫描目录里**且**十分钟内被写过** |

第 3 条是**推断** —— 它靠的是「同一种 Agent + 日志刚在雷达目录里被写过」，
并不能证明**就是这个进程**。

但它的代价只是「多提示一句」，
而漏判的代价是「用户以为被监控了，其实没有」——
后者严重得多。所以条件卡得很死：

- 必须是**同一种** Agent；
- 日志必须**落在雷达扫描目录内**；
- 必须是**十分钟内**被写过的。

三条**缺一不可**。

### 2.6 关键决定四：接口带 8 秒缓存

枚举系统进程不便宜（几百毫秒量级），
而看板每 10 秒就会问一次。加一层 **8 秒缓存**，
把重复枚举挡在服务端。

### 2.7 界面：提示长什么样

左侧栏「＋ 发现/挂载进程」按钮**下方**：

```
┌─────────────────────────────────────┐
│ ⚠️ 检测到本机有 1 个活跃的 MCode      │
│    进程，未发现可读日志。              │
│ 若要监控，请点击此处手动填入其输出    │
│ 文件路径，或者用 > log.jsonl 重定向   │
│ 重启。                               │
└─────────────────────────────────────┘
```

- **橘黄底**，不是红色 —— 红色在哨兵的语言里是「出事了」，
  这里只是「有个任务你可能没接上」；
- **只有一种 Agent 时用产品名**（用户认识「MCode」），
  混了好几种才写总数 + 分项；
- **一切正常时它不占地方**（`hidden`）——
  提示只有真有异常时才出现。

### 2.8 点提示之后

点提示框 → 打开「发现 / 挂载进程」面板 →
**光标直接落在「手动指定日志路径」的输入框上**，
并**预填**「快捷重定向命令」的默认落盘路径
（路径不一样的话改一下就行）。

为什么预填：用户多半就是照设置页那条命令跑的，
路径能对上就少一次手敲。

## 3. 任务二：挂载管理页的「快捷重定向命令」

### 3.1 场景

任务一解决了「**现在**有个任务没接上，怎么接」，
但用户真正缺的是「**下次**怎么一开始就别掉链子」。

### 3.2 这一版怎么做的

设置页【挂载管理】里多一块**可复制的启动命令**，
**针对当前这台机器**：

- 工作目录取哨兵所在目录；
- 落盘路径取 `<项目根>\logs\capture.jsonl`
  （目录会被**自动建出来** —— 否则 shell 的 `>` 会直接报错，
  命令根本跑不起来）；
- 可选 **mcode / codex / claude**，下拉框一换命令跟着变；
- 任务指令可编辑，命令实时跟着改。

命令原文形如：

```
mcode exec --output-format stream-json --cwd "D:\项目\demo" "你的任务指令" > "D:\项目\demo\logs\capture.jsonl"
```

### 3.3 每条命令都**必须**带 JSONL 开关

这一点很要紧，也是容易被省掉的地方：

| Agent | 开关 | 少了会怎样 |
| --- | --- | --- |
| mcode | `--output-format stream-json` | 输出是**给人看的文本**，哨兵解析不了 |
| codex | `--json` | 同上 |
| claude | `--output-format stream-json --print` | 同上；`--print` 少了还会进**交互模式**，压根不返回 |

重定向出来的文件必须是 **JSONL**（每行一个 JSON 对象）。
纯文本流哨兵**解析不了，不会有告警** —— 这是实话，不是吓唬。

### 3.4 与既有引导的关系

设置页原本就有两块东西：

- 「怎么开一个雷达能准确定位的 Agent 任务」——
  那是**用哨兵自己**启动 Agent（`sentinel --agent codex …`）；
- 「如何让我的 Agent 被监控」——
  那是**折叠面板**里的各 Agent 推荐命令。

新加的「快捷重定向命令」是**第三块**，定位不一样：

> 前两块是**说明书**（告诉你原理）；
> 新这块是**工具**（照着就能粘进终端）。

所以它做成了**独立的一块**、**不折叠**、**默认展开** ——
需要的时候不用先去展开一堆说明。

## 4. 顺带修的一个漏判

`detect_agent_process()` 原来直接拿特征去匹配命令行。

本机实测时发现：包路径写成 `@minimax-ai\code\cli.js`（**反斜杠**）
就匹配不上 `@minimax-ai/code`（**正斜杠**）——
真实的 Agent 被判成「不是 Agent」。

npm 全局装出来的包路径用正斜杠，别的安装方式可能用反斜杠。
**换个安装方式不该就认不出来了。**

现在匹配前先把 `\` 统一成 `/`。

## 7. 给用户看的用法

### 7.1 「⚠️ 检测到活跃进程」是什么意思

意思是：**本机有 Agent 在跑，但看板没在看它**。

多半是因为你在终端里跑 Agent 的时候**没把输出重定向成文件**，
雷达扫的是文件，自然扫不到。

### 7.2 我该怎么接上

两条路：

1. **点那条提示** —— 直接去填日志路径
   （预填的是设置页那条命令的落盘位置，路径不一样就改一下）；
2. **重定向重启** —— 用设置页【挂载管理】里的**快捷重定向命令**，
   把任务重新跑一遍，输出就落到哨兵认得的文件上了。

### 7.3 一切正常时为什么什么都没有

**正常就该没有。** 提示只在真有异常时出现，
不占地方、不制造噪音。

### 7.4 没有 psutil 会怎样

整体降级：不显示提示，接口照常返回（`available: false`）。
其他功能**不受影响** —— psutil 是可选依赖，
哨兵从 v2.4.0 起就一直是「有就用、没有就降级」的姿态。
