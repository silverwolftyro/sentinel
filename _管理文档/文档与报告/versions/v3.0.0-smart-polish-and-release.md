# v3.0.0 —— 智能化收尾与终极发布

> 哨兵已经能**发现**、**挂载**、**反查**、**武装**、**锚定**了。
> 但用起来还有两处「要用户自己动手」：
>
> 1. 挂载进来的会话**目标要自己填** —— 其实日志开头就有；
> 2. 武装开关**藏在列表里** —— 明明查得很准，却跟别的开关长得一样。
>
> 这一版**不新增任何能力模块**，
> 只做四件事：**让它更省心**、**把技术债清干净**、**手机上能用**、**把话说清楚**。

## 1. 红线：这一版一个字都没改

**本版未新增任何红线修订。** R1–R9 与 v2.1.0 **完全一致**，**一字未改**。

v3.0.0 做的是**收尾**，不是**扩张**。逐条对照：

* 哨兵**依然只读** —— 自动提取只**读**日志的前 200 行，
  **不写**用户目录；挂载会话的告警日志仍落在哨兵自己的 `logs/attached/` 下；
* 守护者**依旧要用户亲手武装** —— 高置信度只是**把开关高亮出来**，
  开关**默认关着**；在用户手动打开之前，挂载会话**只读、只报告**；
* **没有**新增任何写文件 / 改代码 / 终止进程的路径；
* 代码卫生只动哨兵**自己**的代码，**不碰**用户项目；
* 移动端适配只动前端样式，**不碰**后端契约。

> 唯一一条「看起来像新能力」的 —— 自动提取目标 ——
> 严格来说只是**把已有的一份信息自动抄进已有的输入框**：
> 它读的是用户**自己**的 Agent 日志，抄进的是哨兵**自己**的目标字段，
> 中间没有新增任何动作。

## 2. 任务一：全自动智能锚定与默认武装

### 2.1 自动提取意图

**问题**：v2.4.0 让挂载会话能做意图漂移检测了，但**目标要用户手打**。
而旁路日志的开头通常**就写着**用户最初那句 Prompt。

**做法**：雷达扫描到活跃日志时，读它的**前 200 行**，
找第一条 `user_message` 事件，把它设成该挂载会话的 `task_goal`，
界面上标 **`[自动提取]`**。

| 决策 | 理由 |
| --- | --- |
| **只扫前 200 行** | 用户第一句话一定在开头。扫全文件是浪费。 |
| **目标截断 200 字** | 目标是**锚点**，不是全文存档。 |
| **复用适配器**（`adapter.parse_line()`） | `user_message` 事件本来就是适配器为「自动锚定」准备的。自己再写一套正则，只会多一处会过期的知识。 |
| **提取不到就明说提取不到** | 绝不编一个目标出来 —— 编出来的目标会让漂移检测**假装在工作**。 |
| **只读，不改** | 挂载进来的日志一个字节都不会被哨兵改。 |

**顺带修了一个真 bug**：`src/adapters/codex.py` 此前**完全没有** `user_message` 分支 ——
也就是说 **codex 会话根本没法自动锚定**。已补上扁平形态
（`user_message` / `user` / `prompt` / `human`）
与 `item.type` 形态两处。

### 2.2 高置信度武装推荐

反查置信度 **≥ 0.95**（`cmdline_path` / `open_files` 两条策略）时：

* 开关文案从「武装」变成「**建议武装**」；
* 加一段脉冲动画（`@keyframes arm-suggest`）让它在列表里**一眼可见**；
* 悬停时展开气泡：「高置信度匹配（0.95），建议开启守护者」。

> ⚠️ **只建议，绝不自动武装。**
> 挂起别人的进程是**有代价**的动作（那个 Agent 会卡住），
> 置信度再高也是**机器的判断** —— 必须用户自己点（红线 R7）。
> 置信度不够就**不出现**气泡：宁可少说，也不要误导。

置信度阈值 **0.95** 前后端**各持一份常量**（`ARM_SUGGEST_CONFIDENCE`），
与日志格式契约的其它常量一样 —— 详见第 6 节。

## 3. 任务二：全局代码卫生与性能体检

### 3.1 `ruff.toml`（新，项目根目录）

为什么不直接 `ruff check --select ALL`：

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| **真缺陷** | 未使用的导入、未定义的名字、吞掉的异常、忘了关的句柄 | **必须清零** |
| **风格偏好** | `typing.List` → `list`、`.format()` → f-string | **不开** —— 一改就是上千行，diff 全是噪音，真正的缺陷反而被淹掉 |

量级对比（同一份代码）：

```
ruff check . --select ALL      →  22240 条
ruff check .（项目配置）        →  0 条
```

项目配置**只开**与本项目规范直接相关的规则集：

* CONTRIBUTING §2.3 导入顺序 → `I`
* CONTRIBUTING §2.4 类型注解 → `F`
* CONTRIBUTING §2.5 库代码禁 print → `T20`
* CONTRIBUTING §2.6 异常必须可定位 → `BLE` / `S110` / `TRY`
* CONTRIBUTING §2.2 79 字符 → `E501`
* 红线 R5「审查侧异常一律降级」→ `S110`

**特意不开**的几条，各有理由（理由写在 `ruff.toml` 的注释里）：

* `UP006` / `UP007` / `UP035` / `UP045` / `UP032` / `UP031` ——
  本项目**一贯**用 `typing.List` / `typing.Optional`
  （见 CONTRIBUTING §2.4），全项目都这么写；
  为了统一风格去改一千多行不叫「打磨」，叫「制造噪声」；
* `PLC0415` —— **惰性导入是本项目的架构决定**
  （GUI 应用层不许在顶层 import `src.core.*`，见 ARCHITECTURE.md）；
* `RUF001` / `RUF002` / `RUF003` / `PLC2401` —— 中文项目，
  中文标点本来就长得像 ASCII；
* `RUF100` —— `noqa` 是**意图声明**，规则集以后会变，留着比删掉安全；
* `TRY401` —— 本项目要求异常消息**带类型、带上下文**（§2.6），
  写进 message 才好按关键字检索日志；
* `RUF005` / `RUF015` —— 「替换其中一行」这种场景，
  `lines[:i] + [x] + lines[i + 1:]` 比解包写法更直观；
  `xs[0]` 也比 `next(iter(xs))` 更直观。

### 3.3 异常一律留痕：51 处 `try...except...pass`

这是本版**最实在**的一条 —— 之前的 `except: pass` 是**真的会吞掉东西**的。

| 批次 | 数量 | 说明 |
| --- | --- | --- |
| `S110`（`except Exception: pass`） | **34** | ruff 直接点名的 |
| `except <具体异常>: pass` | **17** | ruff 的 S110 **不管**具体异常类型，是用 AST 扫出来的 |

**统一处理原则**（红线 R5 + CONTRIBUTING §2.6）：

> 审查侧异常可以**降级**，但不能**消失**。
> 每一条都要留下一句**带类型、带上下文**的日志。

* `src/` 下的生产代码 → `logger.warning(...)` / `logger.debug(...)`；
* 验收 / 演示脚本 → `print(..., file=sys.stderr)`
  （走 stderr，**不污染**脚本的结构化 stdout 输出）；
* 出口流本身就坏了的极端情况 → `logging`（它写 stderr，比 `print` 更有机会落地）。

其中几处是**真的有信息量**的：

```python
# src/radar.py —— 路径归一化失败会让「跳过已挂载文件」悄悄失效
except (OSError, ValueError) as exc:
    logger.warning(
        "归一化路径失败（%s）：%s: %s", text, type(exc).__name__, exc
    )
```

```python
# src/core/channels.py —— 杀不掉桌面子进程会留下僵尸
except (OSError, ValueError) as exc:
    logger.warning(
        "强杀桌面提示进程失败：%s: %s", type(exc).__name__, exc
    )
```

### 3.4 前端异常不再静默

前端没有 logger —— **浏览器控制台就是它的日志**。改成：

* `EventSource.close()` 失败 → `console.error("关闭事件流失败：", err)`；
* SSE 数据 JSON 解析失败 → `console.error("事件流数据解析失败：", err, data)`。

### 3.5 路由切换不再被 SSE 卡顿

**原来的顺序**（fetch → 收摊 → 换页）看着没毛病，实际上有个真实的坑：

Agent 跑得飞起时看板每秒能收几百行，
那些 SSE 回调全是**主线程**上的 DOM 操作 ——
`fetch` 的 `.then()` 排在事件循环里，只能等它们跑完。
于是「点【⚙ 设置】→ 页面卡半秒才动」。

**改法**（`src/gui/static/router.js`）：

```javascript
// ⚠️ v3.0.0：**先收摊，再去 fetch**。
teardown();
fetch(url, { headers: { "X-Requested-With": "sentinel-router" } })
```

先关掉 EventSource，主线程立刻空出来，切页就是瞬间的事。

**配套**：切页期间在全局挂 `window.__SENTINEL_ROUTING__` 标记，
看板的 `handleEvent()` 开头就检查它 —— 为真就**立刻返回**，
丢弃在途事件（避免去改已经被换掉的 DOM 节点）。

## 4. 任务三：前端移动端适配

### 4.1 为什么用「上下流式」而不是 Tab 切换

Tab 在手机上要多点一次；堆叠可以一直往下滚。
用户半夜被 Webhook 叫醒点开看板时，**少一次点击**比「看着整齐」值钱。

### 4.2 关键的一条

```css
@media (max-width: 760px) {
  body {
    grid-template-columns: minmax(0, 1fr);
  }
}
```

⚠️ `body` 是 grid，**隐式列**是 `auto`。
`auto` 列的**基线**取子项的 min-content ——
顶栏里那些「不许换行」的东西一多（徽章行、按钮行、输入框），
整列就被撑到 **584px**，页面**横向溢出**，
右边的东西（计数器最后一个、告警卡的按钮）全跑到屏幕外。
`minmax(0, 1fr)` 把这一列**钉死**在视口宽度上。

### 4.3 其余改动

| 位置 | 改动 |
| --- | --- |
| 顶栏 | 换行；子项 `min-width: 0` |
| 徽章行 | 横向滚动，不撑破 |
| 动作区 | 换行 |
| 目标面板 | 独占整行 |
| 按钮 | `min-height: 40px`（手指点得准） |
| 元信息 | 竖排 + `overflow-wrap: anywhere` |
| 计数器 | `repeat(auto-fit, minmax(92px, 1fr))` |
| 告警卡按钮 | `flex: 1 1 auto; min-width: 44%` —— 换行排，别把最后一个挤出屏幕 |
| 设置页网格 | `minmax(230px, 1fr)` → `minmax(min(100%, 230px), 1fr)`（前者的下限是**硬**的） |
| 设置页输入框 | `font-size: 16px` —— iOS 上小于 16px 会**自动放大**，一放大就崩 |

### 4.4 实测（CDP，390×844）

| | `scrollWidth` | 溢出元素 |
| --- | --- | --- |
| 改前 | **584** | 顶栏 / 元信息 / 计数器 / 告警按钮 |
| 改后 | **390** = 视口宽 | `wide: []` |

### 4.5 一个**真问题**：媒体查询必须在文件末尾

窄屏块最初写在 `dashboard.css` 的中段，
后面还有 v2.2.0 时间线 / 体检报告 / 演示横幅的样式 ——
**CSS 同优先级后写的赢**，那些样式会覆盖窄屏块，移动端适配等于白写。

已把整块挪到**文件末尾**。这条有回归测试钉住。

## 8. 给下一个维护者

这一版之后，哨兵的**能力**已经齐了。
接下来要做的**不是加功能**，而是：

1. **保持零告警** —— `ruff check .` 必须一直是 0；
   新代码带了告警，CI / 回归测试会红（`tests/test_v300_release.py` 里有一条真的会去跑 ruff）；
2. **保持红线不变** —— 新能力要先问「这会不会让哨兵动用户的文件 / 挂用户的进程」；
   会，就先出**计划**，让用户点头；
3. **异常必须留痕** —— `except: pass` 是**技术债的形状**，
   AST 回归测试会把它揪出来；
4. **别把惰性导入改成顶层** —— `PLC0415` 是**特意关掉**的，
   原因写在 `ruff.toml` 注释里。
