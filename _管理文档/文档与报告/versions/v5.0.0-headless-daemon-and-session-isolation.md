# v5.0.0 —— 无头守护进程、会话级隔离与轻量集成

> **终极瘦身与内核重构。** 哨兵退居幕后，成为**无头守护进程**：
>
> - **剥离负资产** —— 本地监控面板（FastAPI + Jinja2 + SSE +
>   前端静态资源 + 拖拽 + 手机推送）**整体剥离**。
>   打包出来的 exe 从一个「监控客户端」变成纯粹的「后台守护进程」：
>   没有任何 UI 弹窗，内存占用大幅下降。
> - **架构去中心化** —— 目标锚点下沉到**每一个独立的 Session**，
>   引擎靠 CWD / session_id / thread_id 精准隔离；
>   **没有目标的会话，L2 自动休眠**（不调本地模型），只留 L1 纯规则拦截。
> - **确立集成地位** —— 哨兵作为独立 OS 级进程运行，
>   通过**轻量本地 HTTP API**（只用标准库 `http.server`）
>   和进程树雷达，静默为宿主提供「安检」与「挂起」能力。
>

## 2. 任务二：会话级隔离

### 2.1 隔离的原语：`src/daemon/context.py`

一个会话 = 一个 `SessionContext`，它**自己**拥有：

| 成员 | 为什么必须各有一份 |
| --- | --- |
| `goal` | 只属于这一路的目标 |
| `rules`（L1 规则引擎） | `LoopDetector` **有状态**（记着「这文件读了几次」），共享就等于把 A 路的「读同一文件三次」算到 B 路头上 |
| `tailer` | 只跟这一路自己的日志 |
| `pid` / `cwd` / `session_id` | 进程身份 |

分区键是**指纹**（`build_fingerprint`）：`thread_id` → `session_id` → `cwd` → `pid`
依次取第一个非空值。

### 2.2 目标自动绑定

`DaemonApp.attach()` 会：

1. 按指纹取/建会话；
2. 给它配**自己的**规则引擎；
3. 从日志首句抽目标（`radar.resolve_task_goal`）—— 抽不到就是空串。

### 2.3 无目标休眠

`SessionContext.l2_sleeping` = 没有目标 → 这一路 L2 **自动休眠**：
不调模型、不排队、不占额度，只留 **L1 纯规则拦截**。

> ⚠️ 这条**不是** v5.0.0 新造的 —— `src/llm/base.py:434-436` 早就有：
> 「没有目标就没有『偏离』可言 —— 直接跳过，不打扰模型」。
> v5.0.0 做的是把它**变成可观测的状态**（`/api/state` 里能看见），
> 并把「目标从哪来」从**引擎的全局变量**改成「**这一路自己的**」。

## 3. 任务三：极简对外接口

只用标准库 `http.server`，**不引入任何 Web 框架**。

| 端点 | 方法 | 用途 |
| --- | --- | --- |
| `/api/health` | GET | 活着吗？版本、模式、会话数、几路在休眠 |
| `/api/pre-check` | POST | 外部宿主在 Agent 动手**之前**问一句「这活儿能做吗」→ `{"action": "allow"|"block"}` |
| `/api/attach` | POST | `{"cwd":…, "pid":…}` → 内核开始后台静默监听那一路 |
| `/api/state` | GET | 所有会话的快照（含各自的目标与休眠状态） |

**预检只用 L1 纯规则**（不调模型，秒回），且**预检自己出错时一律放行** ——
宁可信其无，不可误杀。

**报警出口**：命中红线**不弹窗** —— 终端打一行 +
（配了 `callback_url` 就）POST 一条极简 JSON 出去。

**安全边界**：只绑 `127.0.0.1`，**没有任何鉴权** —— 它假定「同机的其他进程都是可信的」。
要跨机器用，请自己在前面加一层反代与鉴权。

## 4. 任务四：并发与队列

* **P0（红线）插队**：`_pop_locked()` 依次看 P0 → P1 → P2，跨档**严格插队**，
  同档 FIFO。已用「先投一个会卡住的 P2 占住工作线程，再投 P2/P1/P0」的测法验证：
  出来的顺序是 `卡住的 → P0 → P1 → P2`。
* **按会话隔离 NInfer 请求**：每一路的 L2 Prompt 注入的是**它自己**的目标 ——
  引擎按指纹分路（`_intent_trackers` + `IntentTracker.sibling()`），
  已在 `src/core/engine.py` 里（v3.5.0 起），v5.0.0 只是把它暴露成可观测状态。

## 6. 验收演示

### 6.1 两路不同 CWD —— 目标提取与判定完全独立

真的造了三份会话日志（A 路 / B 路 / C 路），各带各的首句 `user_message`，
再挂进守护进程：

```
cwd=…\a   pid=1001 agent=mcode   目标='把支付模块的重试逻辑改成指数退避'
    L2 休眠=False
cwd=…\b   pid=1002 agent=codex   目标='写一份给新同事看的部署手册'
    L2 休眠=False
cwd=…\c   pid=1003 agent=claude  目标=''
    L2 休眠=True

  A 路目标只出现在 A 路上 : 是
  两路目标互不相同       : 是
  提不出目标的那路在休眠 : True
```

⇒ **每一路从自己的日志首句提取目标**，
A 路的目标**没有**跑到 B 路上；提不出目标的 C 路**自动进入 L2 休眠**。

### 6.2 无目标时 L2 引擎未调用模型

用一个**计数型 mock 提供方**（每次 `chat()` 就 +1）：

```
无目标 → 降级原因 : 未设置任务目标（task_goal），跳过漂移判定
无目标 → 模型调用次数 : 0
有目标 → 模型调用次数 : 1
```

⇒ 无目标时**一次都不调模型**（静默休眠，只留 L1 纯规则拦截）；
有目标时才调一次。

对应实现：`src/llm/base.py:434-436` —— 那句
「没有目标就没有『偏离』可言 —— 直接跳过，不打扰模型」
的 `return` 就在 `self.chat(...)` **之前**。
