## 1. 现象

```
[CRITICAL] ImportError: cannot import name 'build_argv' from 'src.agents' (unknown location)
```

出问题的调用形态：

```powershell
sentinel-daemon.exe --agent mcode "看一眼 README"     # 接管模式 → 崩
sentinel-daemon.exe --session-file sessions.json      # 多路会话 → 崩
sentinel-daemon.exe --daemon                          # 守护模式 → 正常
sentinel-daemon.exe --scan agent.log                  # 命令行扫描 → 正常
```

⚠️ **注意报错里的 "unknown location"** —— 那不是「文件找不到」，
而是「这个模块**没有 `__init__.py`**」。这个细节就是破案的关键。

---

## 2. 根因：静态分析看不见的那条链

### 2.1 第一环 —— 数据文件不走静态分析

`run_with_sentinel.py` 在 `build_exe.py` 里是这么进的包：

```python
DATA_FILES = (
    (
        os.path.join("_构建与发布", "scripts", "run_with_sentinel.py"),
        os.path.join("_构建与发布", "scripts"),
    ),
    ...
)
```

`--add-data` 进去的**是数据文件，不是可导入模块** → PyInstaller 的
`Analysis` **根本不分析它** → 它函数里的

```python
# run_with_sentinel.py:445
from src.agents import build_argv, load_agents
```

从来没人告诉 PyInstaller「这俩要打包」。

### 2.2 第二环 —— 函数内导入

`src/proc_tree.py` 自己也是**函数内**导入 `src.agents` 的：

```python
# src/proc_tree.py:80
from src.agents import (
    alias_table, binary_table, label_table, load_agents, log_dir_table,
)
# :152  模块级立刻用它
_CLOUD_AGENTS = load_agents(strict=False)
```

而 `src.proc_tree` 自己也只被**函数内**导入：

```python
# src/core/session_server.py:2624
from ..proc_tree import scan_process_tree
```

⇒ 整条链对静态分析**完全隐形**。

### 2.3 落点 —— namespace package

打包后 exe 里**只有**这个数据文件：

```
src\agents\cloud_agents.json     ← --add-data 带进去的
```

**没有** `src/agents/__init__.py`。于是运行时：

1. `import src` → PYZ 里的正规包，`__path__` 指向 `_MEIPASS/src`；
2. `import src.agents` → PYZ 里**没有** `src.agents` → 落到文件系统；
3. `_MEIPASS/src/agents/` 是个**只有 JSON、没有 `__init__.py`** 的目录
   → Python 把它当成 **namespace package**；
4. `from src.agents import build_argv` → namespace package 里没有这个属性
   → `ImportError: cannot import name 'build_argv' from 'src.agents' (unknown location)`。

**「unknown location」就是 namespace package 的签名。**

---

## 3. 修法

`build_exe.py` 的 `HIDDEN_IMPORTS` 本来就是为「函数内动态导入」准备的
（那里写着「漏掉的代价是『打包成功但运行时才崩』—— 那是最糟的一种」）。
这次只是**漏了点名**：

```python
HIDDEN_IMPORTS = (
    ...
    "src.agents",
    "src.agents.auth",
    "src.agents.launcher",
    "src.proc_tree",
    ...
)
```

**只改打包脚本的模块清单** —— 一个字的审查逻辑、规则集、协议都没动。

## 5. 教训

> **「打包成功」不等于「打包版能用」。**

v5.0.1 的验收跑的是 `verify_single_instance.py`，它只启动 `--daemon` 路径；
而崩的是**接管模式**。两者走的模块集合**不一样**。

⇒ 以后每次打包，验收脚本应该**至少覆盖两种启动形态**：
守护模式（`--daemon`）与接管模式（`--agent`）。
