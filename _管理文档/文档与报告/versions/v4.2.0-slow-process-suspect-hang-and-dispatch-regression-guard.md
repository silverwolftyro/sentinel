# v4.2.0 —— 雷达「疑似挂起」状态与派发层防回退

> v4.1.0 已经把《第三方 Agent Bridge 资产盘点》建议的「阶段 A（数据层）」与
> 「阶段 B（派发层）」做完并发布（`src/agents/` 包、14 个 Agent 清单、
> 16 条别名、加固后的派发器、鉴权两层识别）。
> **v4.2.0 不是重做那两步**，而是它们的**后续修正与验收**。
>
> - **「慢/待验证」判据收紧** —— 阈值 **60 秒 → 10 秒**。
>   进程启动后 10 秒仍没吐出任何输出，就**不再显示「运行中」**，
>   改成灰色徽章「**慢/待验证 · 疑似挂起**」，
>   tooltip 把三种可能都列出来（未登录静默挂起 / 还在初始化 /
>   压根不写日志文件）。
> - **色系由琥珀改为灰** —— 10 秒只能证明「还没动静」，
>   **不能断言它挂了**。用中性灰（`--text-dim`）而不是警示色。
> - **派发层防回退** —— 新增「**超大输出不会把子进程堵死**」用例：
>   子进程往 stdout 写 2 MB（管道缓冲区只有 64 KB 左右），
>   验证后台线程确实在持续读取，且缓冲按上限**从头部截断、保留尾部**。
>   v4.1.0 只测了 `echo` 这种小输出，**没覆盖管道写满**这个真会发生的场景。
>
> ⚠️ **红线一字未改** —— R1–R9 与 v4.1.0 **完全一致**。
> 本版只改**界面反馈的灵敏度与措辞**，不动 L1/L2/L3 的判定规则与阈值，
> 也不动任何审计口径。

## 2. 任务三：雷达「疑似挂起」状态

### 2.1 判据收紧：60 秒 → 10 秒

`src/gui/static/dashboard.js`：

```javascript
/* v4.1.0：进程活了多久却一直没输出，才算「慢/待验证」。
 *
 * v4.2.0：阈值 60 秒 → **10 秒**。
 *
 * 为什么改：任务要求「进程启动后 10 秒内没有输出任何内容，
 * 就不要显示为运行中，而是提示『疑似挂起』」。
 * 10 秒是「这个 CLI 还没吐出第一行」的合理上限 ——
 * 连启动都超过 10 秒的 CLI，用户等下去已经没有意义了。
 *
 * ⚠️ 取舍：v4.1.0 曾按上游「step 未登录静默挂起 40 秒以上」的
 * 实测取 60 秒，误报更少但**发现太晚**。10 秒更灵敏，
 * 代价是「启动慢的 CLI」可能被提前标黄 —— 所以这一档是
 * **灰色**（不是警示色），提示文案写「疑似挂起」而不是断言。
 */
var SLOW_PROCESS_SECONDS = 10;
```

判定逻辑本身**没有被改坏**（`isSlowProcess()` 仍然是
「进程还活着 **且** 一直没找到它写出的日志 **且** 活了超过阈值」）：

```javascript
function isSlowProcess(item) {
  if (!item || item.attachable || item.attached) {
    return false;
  }
  var alive = slowSeconds(item);
  return alive > 0 && alive >= SLOW_PROCESS_SECONDS;
}
```

### 2.2 措辞：从「未输出」改成「疑似挂起」

```javascript
badge.className = "attach__badge attach__badge--slow";
badge.textContent =
  "慢/待验证 · 疑似挂起 · " + String(slowSeconds(item)) + "s";
badge.title =
  "进程还活着，但启动 " + String(SLOW_PROCESS_SECONDS) +
  " 秒后仍没找到它写出的日志 —— 疑似挂起。\n" +
  "可能是：① 这个 CLI 未登录时静默挂起（上游实测 step 会挂 40 秒以上）；\n" +
  "② 它还在初始化（CLI 启动慢）；\n" +
  "③ 它压根不写日志文件，只是 stdout 输出。\n" +
  "别当成「在干活」一直等；灰标只是提醒，不是断言。";
```

**「疑似」这两个字是刻意的** —— 10 秒的证据只够支撑「还没动静」，
撑不起「它挂了」。tooltip 把三种可能都摆出来，让用户自己判断。

### 2.3 色系：琥珀 → 灰

```css
.attach__badge--slow {
  border-color: rgba(147, 167, 196, 0.45);
  background: rgba(147, 167, 196, 0.12);
  color: var(--text-dim);
}
```

v4.1.0 用的是琥珀（`#f0b45a`，与 `--warn` 同族），
读起来像「**告警**」。但这一档**不是告警** —— 它是「**这里有件事你可能想知道**」。
所以改用面板自己的弱化灰（`--text-dim`），跟「已发现但没接入」这类中性状态同族。

### 2.4 ⚠️ 本次取舍的代价（必须说清楚）

**阈值降低 = 灵敏度提高 = 误报概率上升。**

根因是「**没有输出**」这件事在雷达里**只能用代理判据**表示：

> `attachable = bool(log_path)`，而 `log_path` 来自
> `find_log_for_process(cwd, agent)` ——
> 它只在进程的 **cwd** 下找**最近 1 小时内修改过**的
> `.jsonl` / `.log` 文件。

于是有两类 CLI 会被**长期误标**成「疑似挂起」：

1. 把会话日志写到 **cwd 之外**的
   （例如 Claude Code 写 `~/.claude/projects/<slug>/<session>.jsonl`）；
2. 压根不写日志文件、**只往 stdout 输出**的。

**60 秒只是让这个误报晚点出现，并没有解决它。**
真正的解法是按 Agent 登记**已知日志目录**，
在 `find_log_for_process` 找不到 cwd 日志时再查一次 ——
那是独立的一版工作（属于盘点报告 §6.2 的「阶段 C」范围），**本次没做**。

当前的缓解手段是三件套：**灰标**（不制造恐慌）+
**「疑似挂起」的措辞**（不下结论）+ **tooltip 列出三种可能**（让用户自查）。

### 2.5 任务书里「Agent 状态列表」的澄清

任务书提到「ready / running」两个状态。核对源码后的结论：

| 概念 | 本项目的实现 | 出处 |
| --- | --- | --- |
| ready | `statusOf()` 返回 `ok`（可派发），等价于 `exists && enabled && !needs_login` | `webui/index.html:343` / `webui/server.py:120` |
| running | **不在 Agent 行上** —— 只体现在派发按钮的 `disabled` 态与计时器里 | `webui/index.html:770-777` |
| 慢/待验证 | **v4.1.0 新增、v4.2.0 收紧**的第三档 | 本次 |

也就是说，上游那边**并没有**「Agent 正在运行」的状态显示。
哨兵这一档是**自己长出来的**：进程树扫描能看到「谁在跑」，
但上游的 HTTP 接口**不提供**「当前有哪些任务在跑」的查询
（`/api/dispatch` 是同步阻塞的，中途零可观测）。
哨兵能拿到「正在跑」，靠的是 `src/proc_tree.py` 的进程树扫描，
这是**比上游多出来的能力**。

## 3. 派发层：防回退（不是新功能）

v4.1.0 已经把上游 `bridge/runner.py` 的四条避坑经验吸收进
`src/agents/launcher.py`：

| 上游的坑 | 哨兵的落点 |
| --- | --- |
| stdin 必须 DEVNULL | `spawn_agent()` 里 `stdin=subprocess.DEVNULL` |
| 超时连进程树一起清 | `kill_process_tree()` → Windows `taskkill /F /T /PID`，POSIX `killpg` |
| 输出管道持续读取但限幅 | 后台读取线程 + `BoundedBuffer`（默认 256 KB，从头部截断、**留尾部**） |
| 不靠退出码判成败 | `src/agents/auth.py` 的鉴权两层机制 |

**v4.2.0 的增量是「证明它没坏」** ——
v4.1.0 的测试只覆盖了 `echo hello-sentinel` 这种**小输出**，
**没有覆盖「管道被写满」这个真会发生的场景**。
本次补上：

| 用例 | 验证什么 |
| --- | --- |
| `test_超大输出不会把子进程堵死` | 子进程写 2 MB（管道缓冲约 64 KB），**不会永久阻塞**，退出码 0 |
| `test_超大输出会被限幅` | 回收的 stdout 不超过 `DEFAULT_OUTPUT_LIMIT`（256 KB） |
| `test_输出限幅后保留的是尾部` | 头部被丢弃，**尾部标记仍在最后** |
