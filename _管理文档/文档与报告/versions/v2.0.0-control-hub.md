# v2.0.0 —— 终端接管与 Agent 控制中枢

> **一句话**：v1.2.0 让哨兵**扛得住一整夜**、并且**看得见**；
> 这一版让它**能动手** ——
> 从看板上直接把纠偏指令**送进 Agent 的标准输入**，
> 以及在 Agent 把代码改乱之后，
> 一个按钮**退回到拦截那一刻**。
>
> ⚠️ **这是第一个会写被监控方工作目录的版本**，
> 所以它是**大版本跨越**，红线也**如实修订**了（见 §1）。

## 1. 红线修订：诚实比好听重要

### 1.1 改了什么

v1.2.0 的哨兵是**全程只读**的。这次它要动手了，
所以 R1 / R2 必须**如实改写** —— 嘴上说没变、代码里写了工作目录，
那是**最坏的一种**文档。

| 红线 | v1.2.0 | **v2.0.0** |
| --- | --- | --- |
| 读被监控日志 | 只读 | **只读**（不变） |
| 改被监控 Agent 的**源码 / 配置 / prompt** | 绝不 | **绝不**（不变 —— 哨兵不会替 Agent 改代码） |
| 往 Agent 的**标准输入**写 | 不可能 | **可以**（用户点按钮触发） |
| 在工作目录里**新建文件** | 不可能 | **可以**（留言箱 / 快照目录） |
| **恢复**工作目录里的文件 | 不可能 | **可以**（**只恢复用户明确点【回滚】的**） |
| 终止进程 | 绝不 | **绝不**（不变） |

### 1.2 换来三条更高的约束

打破「只读」不是放低标准，是**换标准**：

| # | 新红线 | 含义 | 落地 |
| --- | --- | --- | --- |
| R7 | **可逆** | 每件「动手」的事都能退回去 | 注入写进留言箱有留痕；回滚前先出**计划**，用户点头才执行 |
| R8 | **可否决** | 用户随时可以说不 | 不点确认就**一个字节都不动** |
| R9 | **留痕** | 每一次动手都有记录 | `injection` / `rollback` 事件进 hub；快照有 `manifest.json` |

### 1.3 一句必须说清的话

> **「写成功」≠「对方读了」**

写进 stdin 只是把字节送到了管道。Agent 会不会照做，
哨兵**不知道**，也**不假装知道**。

## 2. 任务一：注入中枢

### 2.1 为什么不是「看板直接写 stdin」

看板和 Agent 是**两个进程**。看板手里**没有** Agent 的管道句柄。

所以「看板直接写 stdin」这条路**物理上不通**。
真正能通的是：**用文件做跨进程 IPC**。

```
   看板进程                          启动器进程                Agent 进程
┌────────────┐                  ┌──────────────┐          ┌──────────┐
│ 点【发送】 │                  │  中继线程    │          │          │
│    │       │   sentinel_      │  每秒取一次  │  stdin   │          │
│    ▼       │ ── inbox.json ──▶│              │ ───────▶ │          │
│ 写留言箱   │                  │  能写就写    │          │          │
│            │ ◀── delivered ─── │  不能就留箱 │          │          │
└────────────┘                  └──────────────┘          └──────────┘
                                     │ 启动时
                                     ▼
                              拼进「任务提示」
```

**关键**：**降级路径与成功路径是同一条链路**，不是两套代码。
留言箱既是「送不到时的存放处」，也是「送到了时的留痕处」。

### 2.2 三级通道

| 级别 | 通道 | 触发条件 | 留痕 |
| --- | --- | --- | --- |
| 1 | **stdin 直写** | Agent **确实**在读 stdin | 留言箱里也记一份 `delivered=True` |
| 2 | **留言箱** | stdin 写不进去 / CLI 不读 stdin | 留在 `sentinel_inbox.json` |
| 3 | **重启注入** | 下次启动 Agent | 待投留言**渲染成中文块**拼进任务提示 |

### 2.3 ★ `supports_stdin` 默认 `False`

| Agent | `supports_stdin` | 理由 |
| --- | --- | --- |
| `codex exec` | **False** | 一次性非交互模式，stdin 没人读 |
| `mcode exec` | **False** | 同上 |
| `claude -p` | **False** | 同上 |
| 交互式 / 长驻 CLI | True | 真的有人在读 |

**宁可承认送不到，也不要写进去以为送到了。**
往没人读的管道里写字、然后告诉用户「已送达」—— 那是**撒谎**。

所以 `Popen` **仅在 profile 支持时**才开 `stdin=subprocess.PIPE`；
不支持时**连管道都不开**，省得 Agent 白等一个永远不会关的 stdin。

### 2.4 降级之后：屏幕上永远有下一步

降级**不是死路**。看板给三条路（按需给出）：

```
下一步：
  1) 用同样的命令重跑一次哨兵 —— 留言会在启动时自动注入任务提示
  2) 或直接把下面这段粘给 Agent：
     【哨兵纠偏提示 · STUCK】…
  3) 查看留言箱：<工作目录>/sentinel_inbox.json
```

压测实测：留言箱里待投 **1 条**，「下一步指引」**177 字**。

### 2.5 看板侧怎么接

架构红线之一是「**GUI 应用层不认识 `src.core.engine`**」。
所以注入**不是**看板自己去写 stdin —— 而是**回调注入**：

```python
# 启动器（认识引擎的那一层）
SessionSpec(..., inject_callback=item.inject_callback)

# 看板（不认识引擎的那一层）
def inject(self, prompt, alert_id=""):
    if self._inject_callback:
        return self._inject_callback(prompt, alert_id)   # 只转发
    # 没有回调 → 惰性导入本地 injector 降级
```

### 2.6 新端点

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/sessions/{id}/alerts/{alert_id}/inject` | 会话级【直接发送给 Agent】 |
| POST | `/api/alerts/{alert_id}/inject` | 无会话版的同一件事 |
| POST | `/api/sessions/{id}/alerts/{alert_id}/rollback` | 回滚到**这条告警的拦截点** |
| POST | `/api/sessions/{id}/rollback` | 回滚到**基线安全点** |
| GET | `/api/sessions/{id}/safe-points` | 列出该会话的全部安全点 |

## 3. 任务二：安全点快照与一键回滚

### 3.1 时机：必须在**挂起之前**

```python
# src/core/engine.py
if self._should_intervene(verdict):
    self._capture_safe_point()        # ← 先拍快照
    self.guardian.intervene(...)      # ← 再挂起
```

顺序反了，拦完再拍就晚了 —— 那时候快照里**已经包含了损坏**。

### 3.2 回滚目标是「生效」的安全点

| 安全点 | 什么时候拍的 | 能不能当回滚目标 |
| --- | --- | --- |
| **基线安全点** | 会话起点 | ✅ **默认目标** —— 这才是「Agent 动手之前」的状态 |
| 拦截瞬间快照 | 挂起**之前** | ❌ 空操作 —— 它已经包含了损坏 |

所以每条告警上的 `safe_point` 带**两个** ID：
`safe_point.id`（现场快照，供取证）与 `safe_point.rollback_point`（基线，真正要退回去的那个）。

拦截瞬间那张仍然会拍 —— 那是**现场快照**，用来取证「Agent 到被拦时改成了什么样」。

### 3.3 ★ 快照长什么样（真实目录）

```
<工作目录>/.sentinel/safepoints/<快照ID>/
├── manifest.json      ← 完整文件清单（路径 + 大小 + mtime + sha256）
└── files/             ← 文件内容备份（按原目录结构）
```

实拍（演示现场的真实路径）：

```
logs/v2_demo/safepoints/20261027-180044-772136/
├── manifest.json
└── files/
    ├── junk.tmp
    └── src/
        └── app.py
```

`manifest.json` 真实内容：

```json
{
  "version": 1,
  "point": {
    "id": "20261027-180044-772136",
    "label": "基线安全点 · 会话起点",
    "mode": "full",
    "files_count": 2,
    "backed_up_count": 2,
    "bytes": 46,
    "elapsed": 0.009,
    "backup_dir": "...\\safepoints\\20261027-180044-772136\\files",
    "manifest_path": "...\\safepoints\\20261027-180044-772136\\manifest.json",
    "truncated": false
  },
  "files": {
    "junk.tmp": { "size": 14, "backed_up": true, "sha256": "2879667a…" },
    "src/app.py": { "size": 32, "backed_up": true, "sha256": "44e635d4…" }
  }
}
```

### 3.4 ★ 三重降级保「极速」

| 阈值 | 默认 | 超了怎么办 |
| --- | --- | --- |
| 目录总体积 | 64 MB | 降级成**增量**模式（只备内容，清单仍全） |
| 文件数 | 20000 | 同上 |
| **时间预算** | **3 秒** | **立刻收手**，标 `truncated` |

最后一条是保命的：快照是**在挂起进程之前**拍的 ——
它慢一秒，Agent 就多跑一秒。

⚠️ **无论怎么降级，清单始终完整** ——
回滚要靠清单判断「哪些文件是 Agent 新建的」。
清单缺了，回滚就成了「把用户的东西删了」。

### 3.5 ★ 先计划，后动手

`plan()` **只算不动**：

```
┌──────────────────────────────────────────┐
│ 回滚计划                                  │
│   目标安全点：20261027-175924-131552      │
│   将恢复 1 个被修改的文件                  │
│   将删除 1 个新建的文件                    │
│   预计耗时：0.002 秒                       │
│   [ 确认回滚 ]      [ 取消 ]              │
└──────────────────────────────────────────┘
```

用户点头才调 `restore()`。**权限小于用户**：哨兵不能替用户决定删他的文件。

### 3.6 回滚的边界

| 边界 | 说明 |
| --- | --- |
| **只覆盖工作目录内** | 装依赖 / 推远端 / 改全局配置 —— 哨兵**没留备份** |
| **排除目录不动** | `.git` / `node_modules` / `__pycache__` … 不会被回滚 |
| **路径穿越防护** | 清单里的路径必须**在工作目录内**（`_inside()`），否则跳过 |
| **不可逆** | 执行了，那之后的改动就没了 —— 所以必须先出计划 |

排除目录清单：

```
.git  .hg  .svn  .venv  venv  env  node_modules
__pycache__  .mypy_cache  .pytest_cache  .ruff_cache  .tox
dist  build  .idea  .vscode  .sentinel
```

## 4. 任务三：告警合并推送（防骚扰）

### 4.1 通知分两类

| 类型 | 通道 | 语义 | 合并？ |
| --- | --- | --- | --- |
| **记录型** | console / file | **流水账** —— 一条都不能少 | ❌ **不合并** |
| **通知型** | desktop / sound / webhook | **敲门** —— 敲 5 次会把人逼疯 | ✅ 走合并窗口 |

`BaseChannel.is_notification` 区分这两类。

### 4.2 合并规则

- **指纹** = `agent + rule_id + command`；
- **窗口** = `alert.merge_seconds`，默认 **60 秒**；
- ⚠️ **红线级永远直通** —— 合并绝不能盖住要紧的事。

### 4.3 ★ 尾随摘要：合并不是隐瞒

连续告警停了，看门狗线程（每 `min(窗口/4, 5)` 秒轮询）会**补推**一条：

```
（另有 N 条同类告警已合并）
```

用户不会因为合并而**不知道**发生过什么 ——
只是不会被同一件事敲 5 次门。

## 5. 任务四：「猎杀时刻」压力测试

### 5.1 测的是什么

极端的恶意 / 失控场景：**Agent 连续卡死 5 次，中途还想删库**。

### 5.2 怎么测的

`_构建与发布/scripts/kill_moment_stress.py`：

- 造一个真实测试目录（`app.py` 正常 + `junk.tmp` + 一个**必失败**的测试）；
- 起一个**可被挂起的真实子进程**当被监控进程；
- 真实 `Guardian` + 真实 `Notifier` + 真实 `ContextTracker` +
  真实 `SafePointService` + 真实 `McodeAdapter`；
- **流式**喂事件：每轮 3 次同一条失败命令 → 一次 `[STUCK]`，共 **5 轮**；
- 第 2 轮后 Agent **改坏** `app.py` 并**新建** `scratch.py`，
  再发 `find . -name '*.tmp' -delete`。

> ⚠️ 日志里那条高危命令**只作为文本出现，哨兵从不执行它**。

### 5.3 ★ 11 项断言全过

| # | 检查 | 结果 |
| --- | --- | --- |
| C1a | 5 次 `STUCK` | ✅ |
| C1b | 1 次红线 `DANGEROUS` | ✅ |
| C1c | **顺序**：先 STUCK 后 DANGEROUS | ✅ STUCK 位置 `[0,1,3,4,5]`，DANGEROUS 位置 `[2]` |
| C2 | 进程**真的被挂起** | ✅ `psutil` 读出 `STATUS_STOPPED` |
| C3 | 挂起前打了安全点 | ✅ 4 个文件 / `full` 模式 / **0.007–0.01 秒** |
| C4 | 一键回滚 | ✅ 恢复 1 个 / 删除 1 个 / **0.002 秒** / `app.py` 回到 `good` |
| C5 | 合并推送 | ✅ **6 条告警只推 2 次**（STUCK 合并 1 次 + 红线 1 次） |
| C6a | stdin 直写 | ✅ Agent **真的收到** 19 字 |
| C6b | 降级到留言箱 | ✅ 待投 1 条，下一步指引 177 字 |
| C6c | 重启注入 | ✅ 待投留言**拼进任务提示** |
| C7 | 文件通道记满 | ✅ **6 条**（一条不少） |

**6 条告警 → 2 次推送**，这正是「合并但不隐瞒」。

```

      CLI 不读 stdin 时降级为留言箱（sentinel_inbox.json），下次启动时注入。
    · 【一键回滚至拦截点】—— 先给出「恢复 N 个 / 删除 M 个」的计划，
```

## 8. 实机撞出来的 1 个 bug（已修）

【直接发送给 Agent】和【一键回滚至拦截点】加上之后，
**按钮是灰的、点了没反应**。

根因：**`disabled` 的按钮连 click 事件都不触发**。
而 `refreshGuardianButtons()` 在守护者**没武装**时，
把操作区里**所有**按钮一起禁用了 ——
包括这两个**只读便利**性质的操作。

修法：三个只读便利按钮统一挂 `alert-card__aux` 标记，
禁用选择器改为：

```javascript
.alert-actions .btn:not(.alert-card__aux)
```

> ⚠️ **同一个坑在 v1.2.0 撞过一次** —— 那次是【复制纠偏提示】。
> 两次的共同点：**单元测试全绿，但真实用户就是用不了**。
> 教训：前端「禁用」逻辑必须**逐个按钮**问一遍
> 「它需不需要守护者武装」。

## 9. 已知限制

- **`codex exec` / `mcode exec` / `claude -p` 收不到 stdin 注入** ——
  一次性非交互模式，**没有人在读 stdin**；一律走留言箱 + 重启注入；
- **回滚只覆盖工作目录内的文件** —— 装依赖、推远端、改全局配置**没有**备份；
- **快照是「尽力而为」** —— 大目录降级成「只备内容、清单仍全」，
  恢复时新增文件**会被删掉**（依据清单），但被改文件的**内容可能补不回来**；
- **回滚不可逆** —— 所以必须先出计划、用户确认才动手；
- **「写成功」≠「对方读了」**；
- **Claude 适配器仍未实机验证**；
- **钉钉 / 飞书 / Bark 的真实服务仍未打过**。
