# 实战部署指南 —— 挂机怎么配

> **面向谁**：想把哨兵挂一整夜、早上起来看结果的人。
>
> **一句话**：三个开关 —— `--keep-alive` 让看板不关、
> `intervention_mode: guardian` 让它**真的**拦、
> Webhook 让它半夜**叫你**。
>
> ⚠️ **v3.3.0 起哨兵【不自启】、不后台静默驻留** ——
> 「挂机」指的是**你手动开着那个窗口**，
> 不是「装个快捷方式以后开机自己跑」。
> 用完它会**自己退出**。

---

## 0. 先问自己一个问题：你要「看着」还是「放着」？

| 你想要的 | 用什么 | 半夜会吵醒你吗 |
| --- | --- | --- |
| 我就爱盯着看 | `启动哨兵.bat`（演示模式） | 不会 |
| 挂着跑一整夜，早上看结果 | `--keep-alive` + guardian | **会**（这才是重点） |
| 挂着跑，而且出事了要立刻知道 | 上面全部 + Webhook | 会，而且带卡片 |

**下面讲的是第三种。**

⚠️ 不想要「半夜自己跑起来」？那就不用任何自启 ——
v3.3.0 起哨兵**没有**自启功能，
你**手动**开一次，它就**只**跑那一次。

### 旧版本装过自启？清一次（v3.3.0）

v3.1.0 ~ v3.2.1 曾经在 Windows「启动」文件夹里放过一个快捷方式，
开机就会**静默**把哨兵拉起来。

v3.3.0 起这个功能**彻底删掉了** —— 但**已经装过的机器上还有残留**，
不删的话下次开机它照样会跑起来。

哨兵**每次启动都会主动看一眼**残留，发现就**显眼地**提醒你。
真要清，一条命令：

```powershell
# 只看不删
powershell -NoProfile -ExecutionPolicy Bypass -File '_构建与发布\scripts\remove_startup_residue.ps1' -Status

# 真的清（删「启动」文件夹快捷方式 + 隐藏启动器 VBS + 注册表 Run 项）
powershell -NoProfile -ExecutionPolicy Bypass -File '_构建与发布\scripts\remove_startup_residue.ps1'
```

⚠️ 这个脚本**只许清理，不许新建** ——
哨兵**不会**再往你的系统里写任何自启项（红线 R7）。

## 1. 三步部署

### 第一步：准备好配置

复制一份配置模板：

```bash
cp config/config.example.yaml config/config.yaml
```

`config/config.yaml` 已被 `.gitignore` 忽略 —— 你的 Webhook 地址、密钥**不会**进仓库。

### 第二步：打开守护者（让它真的拦）

```yaml
# config/config.yaml
alert:
  intervention_mode: "guardian"   # ← 关键：默认是 advisory（只告警不拦）

guardian:
  enabled: true
```

> ⚠️ **这一条是整篇指南里最重要的一行。**
> 默认的 `advisory` 模式下，哨兵**只报警不拦** ——
> 红线命令照样会执行，告警只是事后告诉你。
>
> 改成 `guardian` 之后，红线级命令会在执行前把 Agent **挂起**，
> 等你醒来决定放行还是终止。
>
> 挂起是**可逆**的：看板上点「放行并忽略」就能恢复。

### 第三步：接上手机告警

在 `config/config.yaml` 的 `alert.channels` 里挑一家：

```yaml
alert:
  channels:
    - type: "webhook"
      enabled: true
      url: "https://oapi.dingtalk.com/robot/send?access_token=你的token"
      format: "dingtalk"
      card: true
      secret: "SEC..."            # 机器人开了「加签」才需要
      triggers:
        - "guardian_intercept"    # 守护者真的拦下来了
        - "intent_drift"          # 连续漂移
      dedup_seconds: 60
      max_retries: 2
      retry_backoff: 1
```

**各家地址速查**：

| 平台 | `format` | `url` | 备注 |
| --- | --- | --- | --- |
| 钉钉 | `dingtalk` | `https://oapi.dingtalk.com/robot/send?access_token=xxx` | 开了「加签」要填 `secret` |
| 飞书 | `feishu` | `https://open.feishu.cn/open-apis/bot/v2/hook/xxx` | 开了「签名校验」要填 `secret` |
| Server酱 | `serverchan` | `https://sctapi.ftqq.com/xxx.send` | 只要 URL |
| Bark | `bark` | `https://api.day.app/你的key` | critical 用 `timeSensitive`，**会绕过静音** |
| 自建网关 | `generic` | `http://127.0.0.1:9000/hook` | 带完整结构化 JSON |

> **只会推两类事件**：`guardian_intercept`（真拦了）和 `intent_drift`（连续漂移）。
> 死循环、上下文异常**不推** —— 半夜一条 STUCK 就能把人吵醒，那等于没开。

## 2. 挂机跑起来

### 单路（一个 Agent 跑一整夜）

```bash
python _构建与发布/scripts/run_with_sentinel.py \
    --agent codex \
    --cwd D:/work/project \
    --permission smart \
    --keep-alive
```

### 多路（几个 Agent 同时跑，一个看板统管）

写一份会话配置 `logs/sessions.json`：

```json
{
  "sessions": [
    {
      "id": "codex-refactor",
      "label": "Codex · 重构",
      "agent": "codex",
      "task": "把 utils.py 拆成三个模块并补测试",
      "cwd": "D:/work/project"
    },
    {
      "id": "mcode-fix",
      "label": "mcode · 修 bug",
      "agent": "mcode",
      "task": "修掉 issue #42 里那个偶发失败",
      "cwd": "D:/work/another"
    }
  ]
}
```

```bash
python _构建与发布/scripts/run_with_sentinel.py \
    --session-file logs/sessions.json \
    --port 8000 \
    --keep-alive
```

### ★ `--keep-alive` 到底做了什么

不加它，Agent 一跑完**看板就关了** —— 你早上打开网页只看到一个「502 连接被拒绝」。

加上它，看板会**一直留着**直到你 `Ctrl+C`：

| 时刻 | 不加 `--keep-alive` | 加了 `--keep-alive` |
| --- | --- | --- |
| Agent 跑完 | 看板关闭 | **看板继续开着** |
| 早上打开网页 | 连不上 | **告警、日志、Token 统计全都在** |
| 想关掉 | — | `Ctrl+C` |

> ⚠️ `--keep-alive` 意味着看板会**一直占着端口**。
> 第二天想重新起，得先关掉昨天那个窗口 —— 或者换个 `--port`。

### ★ v3.4.0 起：三种方式都能干净退出

以前关掉黑框**不会**杀掉进程 —— 后台会留下一个杀不掉的「幽灵」，
只能去任务管理器手动找。v3.4.0 起，三条路走的是**同一套**收尾逻辑：

| 方式 | 怎么做 | 适合谁 |
| --- | --- | --- |
| **托盘图标** | 右下角哨兵图标 → 右键 →【**彻底退出**】 | 记不住别的的时候 |
| **看板按钮** | 看板右上角的红色【**关闭哨兵**】→ 确认 | 已经在看网页的时候 |
| **关掉黑框** | 直接关终端窗口 | 最快的那种 |

效果完全一样：看板服务停、托盘图标消失、哨兵**自己拉起**的子进程被结束。

> ⚠️ **雷达挂载进来的、你自己启动的 Agent，不受影响** ——
> 哨兵只结束**自己拉起**的子进程（红线 R6），不会去动你的进程。

> ⚠️ 托盘图标需要 `pystray` 与 `Pillow`。
> 没装就不出图标（终端会打一行「托盘不可用」），
> 哨兵的其它功能**一点不受影响** —— 上面第 2、3 条路照样能用。

### ★ 多路时通知通道**共用一个**

多路模式下哨兵**只建一个** `Notifier`，所有会话共用。
每路各建一个的话，同一件事会被推 N 次到手机上 ——
那不是「多路复用」，是「多路骚扰」。

代价是：**没法给不同会话配不同的 Webhook**。

## 3. 半夜会发生什么

| 情况 | 哨兵做什么 | 你会不会被吵醒 |
| --- | --- | --- |
| 正常干活 | 什么都不做 | 不会 |
| 意图漂移（跑偏了） | 弹窗 + 看板告警，**继续跑** | **会**（连续漂移才推） |
| 死循环（反复跑失败的测试） | 弹窗 + 看板告警，**继续跑** | 不会 |
| **红线命令**（`rm -rf`、整盘格式化…） | **挂起进程** + 推手机卡片 | **会**（而且带卡片） |

### 挂起 ≠ 杀掉

哨兵**绝不 kill 进程**。红线命中时它做的是「挂起」——
进程停在原地，你醒来可以在看板上点：

- **放行并忽略** —— 进程恢复，这次告警作废；
- **强制中断** —— 让 Agent 停下手上的活。

> ⚠️ **挂起的是 Agent 进程，不是它派生的子进程。**
> Agent 已经 spawn 出去的 shell 子进程会继续跑完。
> Windows 的进程挂起是**进程级**的，这是操作系统给不了的粒度。

### 手机卡片长什么样

```
🚨 哨兵告警 · RED_LINE

- Agent：codex
- 触发规则：catastrophic_root_delete
- 触发类型：guardian_intercept
- 任务目标：把 utils.py 拆成三个模块并补测试
- 当前操作：rm -rf /tmp/build
- 时间：2026-10-27 03:14:22

规则原因：红线级命中：递归删除根目录 / 家目录 / 整盘（/）

人话解释：AI 想清空整个 /tmp 目录。…
本次异常已拦截，预估为您挽回 3.2 万 Token 的无效消耗

守护者：已挂起目标进程（PID 25328）—— 等待你在看板上放行
```

最后那行「挽回 Token」是 v1.1.0 新增的 —— 让你知道**这次拦截省了多少钱**。

## 4. 早上怎么复盘

### 4.0 手机上直接看（v3.2.0 新增）

> 不想开电脑？**晨报会自动推到你手机上。**

晨报生成完毕（会话结束 / 收尾时）会自动转成一份**短摘要**，
通过你配的 Webhook 推出去：

```text
🌅 哨兵晨报 · 2026-10-28
值守 30 分 12 秒 · 处理 428 条事件
拦截 3 次（红线 2 次）
挽回 Token 12.3k
```

推的是**提炼过的核心数据**（总拦截次数 / 红线次数 / 挽回 Token 数），
不是整篇晨报 —— 整篇几十 KB，塞进手机会被**截断**。

| 你配的 | 手机上看到 |
| --- | --- |
| 钉钉 | Markdown 卡片 |
| 飞书 | interactive 卡片 |
| Server酱 / Bark | 标题 + 正文 |
| 通用（自建网关） | JSON，`"type": "briefing"` |

⚠️ **晨报推送不受告警的「触发类型」和「防骚扰窗口」影响** ——
否则你配了 `triggers: [DANGEROUS]` 的话，晨报会被当成「不是 DANGEROUS 告警」
而**永远推不出去**。

⚠️ 顺带一提：把 `triggers` 列表**清空**是「我全都要」的意思，
哨兵**不会**静默吞掉你的告警。

⚠️ **别忘了确认「意图漂移检测」是开着的**（v3.2.0 实机踩过的坑）

漂移判定要问本地 Ollama。**模型没装**（或超时太紧）时，哨兵会**保守算「没漂移」**——
于是**那段时间的漂移检测等于没开**，而晨报里只会写着「意图漂移：0 次」。

v3.2.0 起，失效会**被明确说出来**：

```text
[SENTINEL] L2 模型判不了，本次意图漂移判定按「未漂移」处理（调用模型失败（OllamaError: 本地模型不存在：qwen2.5:7b…））。这段时间漂移检测等于没开 —— 把主力模型装好，或改 llm.provider 指向可用的模型。
```

开跑前花十秒自检：

```powershell
# 本机 NInfer：模型列表能查到，就是装好了
curl http://127.0.0.1:8888/v1/models

# 或者直接跑一次连接测试（真实调用 + 打印最终的人话解释）
python _构建与发布/scripts/ninfer_probe.py
```

⚠️ **本机装的是 NInfer（Bonsai2-27B）**，不是 Ollama。
它说 OpenAI 兼容协议，端口 `8888`，模型名 `bonsai2-27b`。

四个**必须记住**的参数（错了就是「模型判不了」）：

| 参数 | 值 | 为什么 |
| --- | --- | --- |
| `llm.timeout` | `600` | 27B 推理模型，光「思考」就要几十秒 |
| `llm.max_tokens` | `8192` | 「思考」也吃 token，给小了正文吐不出来 |
| `llm.json_mode` | `false` | NInfer 默认**不认** `response_format`（发了回 400） |
| `llm.api_key` | `sk-no-key-required` | 它不校验密钥，但缺了这个头有些网关会 401 |

⚠️ **单并发**：NInfer 是 `--max-concurrency=1`，同时发两个请求**引擎直接崩**。
哨兵已经在客户端排好队，**但别自己再开一个脚本去调同一个引擎**。

> ⚠️ `llm.keep_alive` 是 **Ollama 专用**的参数（本机已换成 NInfer，不用管它）。
> NInfer 侧对应的是引擎自己的 `--max-context` / `--kv-capacity` 启动参数。

### 4.1 打开看板复盘

打开看板（`http://127.0.0.1:8000`）：

| 看什么 | 在哪 |
| --- | --- |
| 昨晚一共烧了多少 Token | 顶部「已消耗 Token」计数器 |
| 出了几回事 | 顶部计数条（DANGEROUS / LOOP / ON_TRACK / 告警总数） |
| 每一件事的详情 | 中间「实时告警」区（带人话解释与干预按钮） |
| **它是不是一直在看** | 中间「实时告警」区**底部**的「实时审核流水」<br>（灰字一行一次动作：`[12:01:05] 正常读取: auth.py`） |
| 原始日志 | 右侧「被监控日志」区 |
| 各路 Agent 的状态 | 左侧「会话」列表 + 顶部「全局状态」条 |

> **v3.3.1**：中间那块以前空着的时候，
> 你只能从「计数条」猜它还在工作。
> 现在每次 L1 判定为正常都会在面板底部留一行灰字 ——
> **它一路在滚 = 它一直在看**；
> **它停了 = 真的出事了**（告警卡片会盖上来）。

### 4.1.1 顶部那个「未设置」是什么意思（v3.3.1）

挂载进来的会话常常**没有最初的 Prompt**，哨兵就找不到初始目标。
这时候顶部的「未设置」会变成**橘黄高亮**，旁边挂一个气泡：

> 雷达找不到初始目标，请在此手动输入任务目标，以启用漂移监控。

**点一下那个「未设置」**（或点气泡），
光标会直接跳到右上角的任务目标输入框；
填一句你这轮要干的事，点「**设定**」，
顶部就会变成「**手动锚定**」——
意图漂移监控（DRIFT）从这一刻开始盯。

### 4.1.2 「[未绑定进程]」要紧吗（v3.3.1）

**不要紧。**

| 能力 | 没有 PID 时 |
| --- | --- |
| L1 / L2 判定、告警落盘、通知推送 | ✅ **照常** |
| 红线告警时自动挂起 Agent | ❌ 做不到（没有 PID 就没法挂） |

想让它也能用，两条路：

- 用 `sentinel --agent <类型> <任务>` 启动
  （哨兵自己拉 Agent，进程一定认得）；
- 或者让 Agent 的命令行里**带上日志路径**
  （哨兵靠它反查 PID）。

### 4.1.3 看板左侧说「检测到活跃进程」是什么意思（v3.3.2）

看板左侧会亮起一条橘黄提示：

```
⚠️ 检测到本机有 1 个活跃的 MCode 进程，未发现可读日志。
若要监控，请点击此处手动填入其输出文件路径，
或者用 > log.jsonl 重定向重启。
```

**它的意思是**：本机有 Agent 在跑，但**看板没在看它**。

最常见的原因只有一个 —— 你在终端里跑 Agent 的时候
**没把输出重定向成文件**，雷达扫的是文件，自然扫不到。

**接上它，两条路**：

1. **点那条提示** —— 直接打开「发现/挂载进程」面板，
   光标落在「手动指定日志路径」的输入框上，
   路径已经**预填**好了（不是你那条也没关系，改一下就行）；
2. **重定向重启** —— 用设置页【④ 挂载管理】里的
   **「快捷重定向命令」**：

   ```text
   mcode exec --output-format stream-json --cwd "D:\项目\demo" "你的任务指令" > "D:\项目\demo\logs\capture.jsonl"
   ```

   照着跑，输出就落到哨兵认得的文件上，
   跑完回看板点【＋ 发现/挂载进程】把那个路径填进去即可。

⚠️ **重定向出来的文件必须是 JSONL**（每行一个 JSON 对象）——
纯文本流哨兵解析不了，不会有告警。
所以命令里那三个 `--output-format stream-json` / `--json` 开关
**一个都不能省**。

> **一切正常时不会有这条提示** —— 它只占「真有异常」的地方。
> psutil 没装的话也不会有（哨兵整体降级成「不感知进程」，其他功能照常）。

### 4.2 Token 统计怎么算的

- **有 usage 就用 usage**（codex 的 `turn.completed` 报真实账单）；
- **没有 usage 就按字符估**（中文 1 字 ≈ 1 Token，英文 4 字符 ≈ 1 Token），
  这种情况下计数器上会带一个 `~` 标记 —— **估算值不会冒充真值**。

「挽回 Token」的公式：

```
挽回 = 本次会话已消耗
     + 每步均摊 Token × 10 步
```

前一项是「这段工作正在走向危险动作，本就是无效消耗」，
后一项是「Agent 若不被拦住，本来还要继续烧的」。
它是**估算**，不是账单。

## 5. 排障

### 手机没收到通知

按这个顺序查：

1. **看日志里的中文提示**。哨兵会直接告诉你失败原因：
   ```
   webhook 投递最终失败（共尝试 3 次）：HTTP 404。请检查网络连通性、
   URL 是否正确、是否需要加签密钥。本次告警**未能**推送到手机。
   ```
2. **4xx 不会重试**（URL 错了、签名错了，重试也没用）；
   5xx / 网络错误 / 超时**会**按指数退避重试（1s、2s、4s）。
3. **确认触发类型对得上**：只推 `guardian_intercept` 与 `intent_drift`。
   普通告警（ON_TRACK）**不推** —— 这是设计，不是 bug。
4. **确认没被防骚扰挡掉**：同一条事件 60 秒内只推一次。
   首次投递失败会**撤销占位**，所以失败后是可以再推的。

### 端口被占用

```
[127.0.0.1:8000] 端口被占用，请修改端口或关闭已有进程。
[SENTINEL] 请改用别的端口，例如：--port 8001
```

多半是昨天 `--keep-alive` 的窗口还开着 —— 关掉它，或者换端口。

### 守护者没拦

看 `config/config.yaml` 里的 `intervention_mode` 是不是 `guardian`。
默认的 `advisory` **只告警不拦**。

### L2 解释一直是「模型解释生成中…」

L2 是**异步**的 —— 原告警会先出来，解释随后补上。
如果一直没出来，多半是 Ollama 没起或者模型不可用。
这种情况下哨兵会**降级**成规则层原始判定（卡片上会标出来），
**不会**把降级当成「有问题」（连续漂移计数会归零）。

### 引擎掉了怎么办（v3.3.0）

本机 NInfer 会掉线，而且掉得**不声不响**：
规则层照跑，但 **L2 判定与人话解释整个停用** ——
你只会看到一堆干巴巴的告警，**没有解释**。

v3.3.0 起哨兵会**每 30 秒**只读探活一次（不触发推理、不烧显存），
掉了立刻在**终端 + 看板 + 手机**上喊：

```
[CRITICAL] NInfer 引擎已掉线！L2 判定和解释已停用！
```

**排查三步**：

```bash
# 1) 引擎到底在不在
curl http://127.0.0.1:8888/v1/models
#    出不来 JSON = 引擎没起或卡死

# 2) 进程还在不在
tasklist /FO CSV /NH | findstr /I ninfer

# 3) 看哨兵自己的心跳状态
#    看板上「关于系统」页有引擎存活状态
```

### ⚠️ 哨兵**不会**替你拉起引擎（v3.3.0）

哨兵只**说**（「引擎掉了，你手动拉一下」），**不动手**。

```yaml
# config/config.yaml
llm:
  watchdog:
    enabled: true
    interval: 30
    timeout: 8
```

为什么不做自动重拉：

* 用户的要求是明确的：「**不要尝试自动拉起，保持只读监控的边界**」；
* 哨兵**替用户启动一个进程**就不再是只读监控了；
* 引擎启动要吃显存 —— 在你正被别的东西占满显存的时候自动拉它，
  只会把机器拖得更垮。

⚠️ 配置里那个 `llm.watchdog.restart` 段**保留但被忽略** ——
留着是为了不打断已有配置，但哨兵**不会**用它拉起引擎。
真写着 `restart.enabled: true`，哨兵会记一条日志提醒你。

### 「严重跑偏」告警太吵？调时间盒（v3.3.0）

「一个子任务吃掉整轮」现在会被**硬性拦截**（默认 15 分钟时间盒）。
嫌吵就调这三个参数：

```yaml
# config/config.yaml
rules:
  timebox:
    enabled: true
    window_minutes: 30        # 时间盒拉长 → 更少误报
    min_repeats: 5            # 要求重复更多次 → 更少误报
    categories: ["dependency"] # 只盯装依赖；跑测试不管
    guardian_suspend: null    # 留空 = 跟着守护者的武装状态走
```

**`guardian_suspend` 是三态**：

| 取值 | 行为 |
| --- | --- |
| `null`（**默认**） | **跟着守护者走** —— 守护者武装着（`enabled` 且 `intervention_mode: guardian`）才自动挂起死磕的进程 |
| `true` | 只要**有**守护者就挂起 |
| `false` | **永远不挂**，只告警 |

⚠️ 挂起是**可逆**的 —— 看板上点一下就能恢复。

**误报最多的两类**，以及对应处理：

| 误报场景 | 怎么处理 |
| --- | --- |
| 正常改代码被判跑偏 | `edit` **默认就不盯**，若你手工加过它，从 `categories` 里删掉 |
| 反复 `git status` | **本来就不算** —— 廉价查看命令不计入重复统计 |

⚠️ 「同一条命令反复出现」这条判定**不受** `categories` 限制 ——
同一条命令磨满一个时间盒，本来就值得看一眼。

### 手动双击 exe 被 Defender 拦了？

Defender 的机器学习启发式有时会**隔离**单文件 exe，
后果是**双击 exe 没反应**（文件已经被隔离走了，而且不报错）。

```powershell
# 看有没有中招
Get-MpThreatDetection | Select-Object -First 3 InitialDetectionTime, ThreatID

# 修（一键，需要管理员权限）—— 把 exe 所在目录加进排除项
powershell -NoProfile -ExecutionPolicy Bypass -File '_构建与发布\scripts\add_defender_exclusion.ps1'
```

⚠️ v3.3.0 起哨兵**不自启**了，所以不存在「开机自启静默失效」那种坑 ——
但**手动双击**一样会被拦，处置办法不变：**把 exe 所在目录加进白名单**。

详细说明见 README 的**【防误杀指南】**。

## 7. 安全边界（必读）

哨兵是**只读**的监控工具，它能做的干预只有一种：**可逆地挂起**。

| 它会做 | 它绝不会做 |
| --- | --- |
| 挂起 Agent 进程（可恢复） | **kill 进程** |
| 读 Agent 的日志 | 改 Agent 的任何文件 |
| 把告警推到你的手机 | 把内容发到**外部地址**（除非你自己配的 Webhook） |
| 在本机看板上展示 | 监听非回环地址（除非显式 `--allow-remote`） |
| 记录一切（`logs/` 留痕） | 替你做决定（放行与否永远由你点） |

> **权限永远小于用户。**
> 干预必须可逆、必须能被否决、必须留痕。
> 这是哨兵的设计底线，不是可选项。
