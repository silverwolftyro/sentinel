④ 挂载管理

这里列出的是当前正在监控的会话。 在看板左侧的【+ 发现/挂载进程】里可以接入新的 Agent。

怎么开一个带日志输出、而且雷达能准确定位的 Agent 任务？

雷达靠三样东西定位一个会话： ① 它落在默认扫描目录里； ② 日志正在被写入（不是早就跑完的历史文件）； ③ 日志里写清了工作目录（cwd）。

下面这条命令三样都满足：它让 Agent 在 --cwd 指定的目录里干活， 日志由 Agent 自己写到标准位置， 而工作目录会写进日志的首行 —— 雷达一眼就能认出「这是我刚才跑的那个任务」。 

sentinel --agent codex --cwd "{{ radar_workdir }}" "你的任务指令"

换成别的 Agent 只改 --agent： mcode / codex / claude。 Windows 上也可以直接用 启动哨兵.bat --agent codex --cwd "…" "任务指令"。

⚠️ 只想让雷达发现已经在跑的 Agent，什么都不用改 —— 在看板里点【＋ 发现/挂载进程】，雷达会列出 此刻正在写入的会话，点「接入」即可。 上面那条命令是给「你打算新开一个任务」用的。

快捷重定向命令：让你自己终端里的 Agent 被看板抓到

雷达扫的是日志文件。你在终端里跑的 Agent 如果没把输出重定向成文件，雷达就看不见它 —— 这正是「终端里明明跑着任务、看板却空空如也」的原因。
下面这条命令会把 Agent 的输出直接存成 JSONL 文件。 跑完以后回到看板点【＋ 发现/挂载进程】， 把那个文件路径填进去就能实时审查。

        如何让我的 Agent 被监控（各 Agent 推荐的启动命令）
        


          

            为什么要输出重定向？
            哨兵靠读日志文件来审查 Agent。
            Agent 自己写的会话日志有两种情况：

            ① 直接就是 JSONL（mcode / codex / claude）——
            雷达能直接扫到，接一下就行；

            ② 压缩格式（DeepSeek harness 的
            .zstd）——
            压缩流没法按字节增量跟读，暂时接不了。

            对付第二种，最直接的办法是
            在启动 Agent 时把它的输出重定向到一个普通文本文件：

            你的命令 > D:\logs\session.jsonl

            ⚠️ 重定向出来的文件必须是 JSONL
            （每行一个 JSON 对象）—— 纯文本流哨兵解析不了，不会有告警。
          


          

            重定向之后有两条路接入：

            ① 直接用上面的【手动指定日志路径】框
            填那个文件路径 —— 最省事，不用改任何配置；

            ② 让雷达自己找到它 ——
            把日志目录加进下面的「雷达扫描根目录」，
            雷达就会把它列出来（前提是那个文件正在被写入）。
          


          

            

              

                mcode（MiniMax Code）
                原生 JSONL · 可直接接入
              

              

                
mcode exec --output-format stream-json --cwd "<你的项目目录>" "<任务指令>" > "<日志路径>"

                
              

              

                --output-format stream-json 是关键 ——
                没有它 mcode 输出的是给人看的文本，哨兵解析不了。
              

            


            

              

                codex（OpenAI Codex CLI）
                原生 JSONL · 可直接接入
              

              

                
codex exec --json --cd "<你的项目目录>" "<任务指令>" > "<日志路径>"

                
              

              

                --json 让 codex 输出机器可读的事件流。
              

            


            

              

                claude（Claude Code）
                原生 JSONL · 可直接接入
              

              

                
claude --output-format stream-json --print "<任务指令>" > "<日志路径>"

                
              

              

                --print 是非交互模式；
                Claude Code 没有通用的 --cwd，
                工作目录靠先切到项目目录。
              

            


            

              

                deepseek（DeepSeek harness）
                压缩日志 · 暂不支持接入
              

              

                
<你的 deepseek 命令> > "<日志路径>"

                
              

              

                ⚠️ 说清楚现状：DeepSeek harness 自己的会话日志是
                .zstd 压缩的，
                哨兵能发现它、读出它的工作区和会话 ID，
                但没法实时跟读（跟读器按字节偏移走，压缩流读不了）。
                

                如果它支持 JSONL 输出，就用上面那条重定向命令把输出存成
                .jsonl，再通过
                【手动指定日志路径】接入；
                如果它只输出纯文本，那这条路暂时走不通 ——
                哨兵拿不到可解析的事件。
              

            

          

        

      


      
      

        雷达扫描根目录（radar.scan_roots）
        

          

            雷达去哪儿找 Agent 的会话日志 —— 一行一个路径。
            相对路径按家目录解析（``.codex`` 就是
            用户目录\.codex）；绝对路径原样使用，
            比如 D:\项目。
            

            留空 = 用内置默认清单。
            改完点【保存并应用】，下一次点【发现/挂载进程】就生效。
