③ 审查流水线控制

L1 / L2 / L3 独立开关 · L2→L3 桥接 · 命中后动作

正在读取当前通路…

开关改完点下面的保存并应用， 编排器会立刻重建 —— 不必重启哨兵。

怎么跑： L1 正则先筛一遍 → 需要复核的事件交给 L2 本地模型做三值判定 → L2 判「正常」就静默丢弃（省下一次云端调用）→ L2 判「有问题」 才打包上下文调用 L3 云端模型复审。

⚠️ 桥接的边界必须说清楚： 桥接时 L2 已经关着，只剩 L3 一票（单盲）—— 所以 L3 说有问题只会出标准级告警， 不会触发守护者挂起，也不会亮最高级红灯。 桥接只送工具调用类事件（思考过程与纯文本不上云）。 关掉 L2 又不开桥接 = 这些事件没有第二道模型复核， 只剩 L1 正则说了算。

L1 命中后的拦截策略

拦截策略只改 L1 命中之后做什么， 不改变任何判定规则、阈值与告警口径 —— 哪些命令算高危、哪些算红线，与 v3.6.x 一字未改。 逐条规则的开关与「仅记录」降级在 L1 规则页； 那一页也能改这一项，两页存的是同一个配置键。

③-1 L2 掉线热切与预算熔断

L2 临时掉线时自动转给 L3 · 热切预算上限

⚠️ 热切是单盲：L2 已经没了，只剩 L3 一票， 所以不会亮最高级红灯、不会挂起 Agent —— 「双盲一致才升级红线」这条原则一字未改。 热切只在 L2 临时性掉线（连不上 / 429 / 503 / 超时 / 熔断中）时发生； L2 只是输出解析失败（它还活着）时不会烧云端的钱。

预算熔断：窗口内的热切次数或预估费用超上限 ⇒ 放弃这次云端调用、回退 L1 纯规则， 并发一条严重系统告警（它说的是「预算用完了」， 不是「Agent 干了坏事」，所以不挂起）。 金额按「热切次数 × 单次预估费用」估算， 实际账单以服务商为准。L3 也挂时会安静回退 L1 —— 不报错、不卡死。

③-2 呈现与摘要

两个 0-100 极限压缩档位

这两个滑条是看板呈现的唯一入口 —— v3.7.0 起主看板上的日志档位滑条已移除， 档位在这里配，所有看板窗口共享同一份设置 （不再按浏览器分开记）。

右侧「被监控日志」的极限压缩（0-100）
–

0–30 纯代码（原始 JSON + 语法高亮）· 31–69 自然语言（提问 / 回答 / 思考 / 工具名）· 70–99 高度摘要（丢掉思考与工具结果）· 100 极限摘要（连续同类动作真的合并成一行， 例如连续 5 次读文件显示为 [读取] core/auth.py 等 5 个文件）。

中间「实时审核流水」的极限压缩（0-100）
–

0–39 完整（含「Agent 正在思考」）· 40–69 精简（省略思考过程）· 70–89 结论（只留核心结论与告警）· 90–100 极限（连续的普通流水合并成一条计数行）。

⚠️ 压缩只影响显示，不减少判定 —— 引擎该判的照判、该记的照记，告警一条不少。 真正丢信息的只有「思考过程」与「工具结果」这两类**原始噪音**。
